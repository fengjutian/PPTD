# V0.1 开发计划

## 1. 交付目标

V0.1 交付一个 Windows 优先的可运行桌面应用：用户可以新建项目，创建多页演示文稿，编辑文本、图片和基础形状，撤销重做，保存/恢复项目，并导出可由 PowerPoint 或 LibreOffice 打开的 PPTX。

AI、PPTX 导入、主题字体高级管理和 3D 编辑不进入 V0.1 主路径，但本阶段的端口和模型必须为后续能力留出稳定边界。

> **状态（2026-10-27）：** 本计划的 M0–M4 已交付，M5 主体完成。实际交付内容已超出本计划：AI 生成、内容审核、演示动画、原生表格/图表/图标、传统色主题预设、PPTX 模板导入、AI 设计生成与低代码布局编译器等后续里程碑能力被提前引入。已完成/部分完成/未开发能力的完整盘点见 [实现状态盘点](implementation-status.md)；如进入新范围，先按 TRS 更新需求基线。

## 2. 实施顺序

### M0：工程基线

- 初始化 Tauri 2、React、TypeScript、Vite。
- 配置严格 TypeScript、ESLint、格式化、Vitest 和前端组件测试。
- 建立 `src/core`、`src/features`、`src/components`、`src/services`、`src/store` 和 `src-tauri` 边界。
- 建立 CI：类型检查、Lint、单元测试、构建和许可证清单。

完成定义：开发与生产构建均能启动空工作台；CI 从干净检出可重复通过。

### M1：Document Core

- 定义强类型文档、页面、元素、主题、资源和版本结构。
- 建立运行时 Schema、默认文档工厂和版本迁移框架。
- 实现命令总线、事务、Immer patch、撤销重做和 revision 规则。
- 实现坐标、矩形、旋转和 EMU 转换工具。

完成定义：模型可独立于 UI 测试；设计命令无法改变内容快照；至少覆盖创建、变换、删除和撤销链路。

### M2：2D 编辑器闭环

- 工作台骨架：顶部工具栏、左侧缩略图、中央画布、右侧属性栏、底部状态栏。
- 页面新增、删除、复制和排序。
- 文本、矩形、椭圆、线条和图片对象。
- 单选/多选、移动、缩放、旋转、层级、锁定、复制粘贴、对齐和删除。
- 视口缩放、适应窗口、网格与参考线；辅助元素不进入导出模型。

完成定义：测试演示文稿可在 10 页间编辑；连续拖拽只生成一个撤销事务；常见操作无明显卡顿。

### M3：项目持久化

- Rust 端提供受控的新建、打开、保存、另存为命令。
- 项目 JSON、资源目录、内容哈希和 SQLite 项目索引。
- 手动保存、带防抖的自动保存、脏状态和可见错误。
- 临时文件原子替换、异常关闭标记和恢复入口。

完成定义：重启后模型等价；模拟保存中断不会破坏上一个有效版本；缺失资源返回具体诊断。

### M4：标准 PPTX 导出

- 将文本、图片、基础形状、页面背景和页面顺序映射到 PptxGenJS。
- 建立字体替代、坐标边界、溢出和不支持对象检查。
- 输出导出报告以及 ZIP/OOXML 基础结构校验。
- 建立固定样例，通过 LibreOffice 转换 PDF，并人工抽检 PowerPoint。

完成定义：代表性样例可打开，页数和顺序一致，文本/图片/形状仍可编辑；任何降级均写入报告。

### M5：稳定与发布候选

- 整合崩溃恢复、长任务取消、错误边界和诊断日志。
- 建立性能基线和视觉回归样例。
- 视觉回归样例已落地：固定夹具导出后由 PowerPoint（无则 LibreOffice）渲染成图片，与参考图逐像素比对，差异超过容忍度即判定回归。命令 `npm run test:visual`，详见 [0017 导出视觉回归比对](../architecture/decisions/0017-export-visual-regression.md)。
- 该比对需要本机的演示应用工具链，冷启动加渲染远超测试框架默认时限，因此显式放宽超时；没有工具链的构建机用 `PPTD_SKIP_VISUAL=1` 显式跳过，不以跳过冒充通过。
- 夹具覆盖四页：封面、指标页（文本、表格、图片）、柱状图页（原生图表、椭圆、旋转对象）、饼图页（原生图表、图例、数据标签、深色背景）。
- 完成依赖许可证审计、Tauri capability 收敛和打包验证。`npm run tauri build` 已产出 MSI 与 NSIS 安装包，安装后应用可启动。

完成定义：所有 V0.1 验收场景通过，并记录已知限制。

## 3. 建议 Backlog 切片

每个切片都必须形成纵向可验证结果，建议顺序为：

1. 创建空文档并显示单页。
2. 添加矩形，拖动后撤销/重做。
3. 编辑文本并保存到内存快照。
4. 增删/排序页面并生成缩略图。
5. 保存到磁盘并重新打开。
6. 导出一页文本和形状 PPTX。
7. 增加图片资源与跨页导出。
8. 自动保存、恢复与导出报告。

| ID  | 场景                                     | 预期结果                                  |
| --- | ---------------------------------------- | ----------------------------------------- |

| A06 | 使用缺失字体和越界对象导出               | 导出前给出明确警告，报告记录处理方式      |
| A07 | 导出过程中取消或失败                     | 项目不变，无半成品覆盖目标文件            |

## 5. 阶段外事项

以下内容分别进入 V0.2 以后：任意 PPTX 导入、母版/版式解析、模板保真导出、AI Provider、内容审核界面、字体库管理、Three.js 场景、动画和视频导出。V0.1 可定义接口和测试替身，但不实现伪兼容能力。

## 6. 风险与先行验证

开发第一周应完成三个技术探针：

- 验证 HTML 文本编辑与 SVG 变换在缩放画布中的坐标一致性。
- 验证 PptxGenJS 的中文字体、换行、透明度、旋转和图片裁剪输出。
- 验证 Tauri 在 Windows 上的原子保存、文件对话框授权和崩溃恢复路径。

探针代码不直接进入生产核心；结论写成 ADR，并据此冻结 V0.1 的实现选择。
