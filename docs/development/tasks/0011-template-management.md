## 1. 背景

模板库此前只能导入、列出和预览。误导入的文件无法删除，命名不合适的模板也无法修正；用户只能去应用数据目录手动操作。

分类、收藏需要独立的持久化元数据，本切片先解决最高频的删除与重命名，不伪造分类/收藏。

## 2. 范围

### 2.1 包含

- `delete_pptx_template`：只删除模板库中的文件，不影响已经应用该模板的当前文档。
- `rename_pptx_template`：保留导入时间戳，只替换文件名中的展示名；返回更新后的 `TemplateRecord`。
- 文件名清洗：路径分隔符、控制字符、Windows 非法字符替换为 `_`；自动补 `.pptx`；重名拒绝。
- 模板库卡片右键菜单：重命名/删除；删除前确认。
- 重命名后刷新模板列表；如果重命名的是当前选中模板，同步更新选中项。
- 删除当前选中模板时清空详情，但当前文档的设计不变。

### 2.2 不包含

- 分类、收藏、标签、排序偏好。
- 模板缩略图/版式缓存的手动刷新；缓存按内容哈希，删除文件后由现有上限清理。
- 批量删除、拖拽排序。
- 模板内容的编辑或重新导入覆盖。

## 3. 设计

### 3.1 文件名就是模板 id

模板 id 形如 `{importedAt}-{name}.pptx`。重命名保留 `importedAt`，只换 `name`，因此：

- 列表排序不受影响；
- 不需要额外的元数据文件或数据库迁移；
- 预览仍从 PPTX 自身读取，不依赖 id 之外的路径。

重命名到同名（包括已带 `.pptx`）直接返回现有记录，不重复 rename。

### 3.2 安全与错误

- `template_id` 不允许空、`/`、`\`、`..`、`.`、`\0`。
- 目标路径必须留在模板根目录内；源文件必须存在且是文件。
- 新名称去空格、限 100 字符；空名称拒绝；重名返回 `TEMPLATE_NAME_EXISTS`。
- 删除不存在的模板返回 `TEMPLATE_NOT_FOUND`。
- 删除只删模板文件，不触碰项目文档、图片资产或布局渲染缓存。

### 3.3 UI

模板库卡片增加 `onContextMenu`，弹出固定定位菜单：

- 重命名：`window.prompt` 预填去掉扩展名的名称，调用命令后刷新列表与选中项。
- 删除：`window.confirm` 后调用命令；若删除的是当前选中模板，清空预览/分析/版式渲染状态。
- 菜单不嵌套在卡片 `<button>` 内，避免无效 HTML 与点击冒泡。

## 4. 验收

- **AC-1** 右键模板卡片可以选择重命名或删除。
- **AC-2** 重命名保留导入时间，列表名称更新；重名被拒绝并显示错误。
- **AC-3** 删除后文件从模板库消失；已应用该模板的当前文档不变。
- **AC-4** 删除当前选中模板会清空模板详情，不残留旧预览。
- **AC-5** 路径穿越、非法 id、删除不存在文件被拒绝，不访问模板根目录之外。
- **AC-6** 取消重命名/删除不产生任何变更。

## 5. 测试

- Rust `commands/project_file.rs`：重命名、保留时间戳、同名幂等、重名拒绝、删除、删除不存在、路径穿越拒绝。
- 前端类型检查覆盖命令签名与 UI 状态；模板菜单为原生右键交互，未做 DOM 自动化。

## 6. 已知边界

- 没有分类/收藏/标签。
- 删除模板不可撤销；只删除模板库文件，不影响项目。
- 右键菜单对键盘用户不够友好；后续可补“管理”按钮或命令面板。
- 布局渲染缓存不立即删除，按现有 LRU/容量上限清理。
