# 设计能力手工验收与真实模型校准

这份清单覆盖自动化测试无法替代的两类验证：真实界面目视、真实模型输出。所有步骤在桌面应用里执行，结果记录在文末表格；不要用 `npm test` 通过代替。

## 1. 环境

| 项     | 要求                                                        |
| ------ | ----------------------------------------------------------- |
| 应用   | `npm run tauri dev`，窗口宽度分别试 1440、1100、900         |
| 字体   | 本机安装思源黑体/思源宋体（可选）；未安装时记录字体替代提示 |
| 渲染器 | Windows + 本机 PowerPoint；macOS/Linux 预期为画布近似       |
| 模型   | 已配置 API Key，且视觉探测通过（设置页显示已配置）          |

### 1.1 视觉基线命名与重建

- 常规导出基线：`tools/visual-regression/baseline/<renderer>/slide-<n>.png`。
- 四个概念方向的八页样张：`tools/visual-regression/baseline/specimens/<renderer>/<concept>.png`。
- contact sheet 固定为 4×2，按页序从左到右、从上到下排列；缺页或换序都会形成差异。
- 校验：`npm run test:visual`。
- 有意改变视觉后重建：`$env:PPTD_VISUAL_BASELINE='update'; npm run test:visual`。重建命令会以失败结束，提醒人工检查新增 PNG；目视确认后清除环境变量并再次运行。
- 没有 PowerPoint/LibreOffice 的构建机可设 `PPTD_SKIP_VISUAL=1`，但这只表示明确跳过，不算视觉验证通过。LibreOffice 当前只覆盖首页，八页 contact sheet 仅由支持整册渲染的 PowerPoint 建立。

## 2. 界面验收

### 2.1 设置

1. 打开设置 → 模型。
2. 确认四个开关存在且可保存：允许视觉评审、生成前选择设计方向、保存本机设计记忆、运行设计体检。
3. 设计记忆显示“已记录 N 个外观、M 条偏好”；点“清除设计记忆”后计数归零。
4. 关闭“运行设计体检”，回到编辑器：右侧不再出现“设计体检”；导出报告标题不再有体检计数。
5. 重新开启，体检面板恢复。

**预期**：刷新/重启后开关保持；关闭体检不影响生成与导出。

### 2.2 方向门

1. 不选模板，输入一个 8–12 页题材，生成。
2. 方向门出现四张卡片（2×2），每张卡有 2 页真实预览。
3. 预览应能看出骨架/图像策略/字阶差异，不是只换颜色；`paper` 的窄栏与 `instrument` 的左侧竖线应当可见。
4. 在“为什么选它”输入一句话，选择其中一个。
5. 生成完成后，右侧“设计方向”面板显示：所选名称、预设、你选的、时间、内容 revision、三个备选、你的原话。
6. 再生成一次，点“换一组”两次，确认按钮在 2/2 后禁用；点“跳过”仍能生成。
7. 生成过程中点取消，确认弹窗关闭、任务结束，不残留等待。

**预期**：四个方向两两至少在两项上不同；预览不修改真实文档；取消不卡死。

### 2.3 样张

1. 主题选择器 → “查看 8 页样张”。
2. 打开任一主题详情：字体样张、配色角色与对比度、推荐页型、适用受众都应出现；点击色块可复制色值；底部“查看 8 页样张”应能直接打开样张弹窗。
3. 17 套主题都能打开，每套 8 页；切换主题时标签页跟随。
4. 缩放窗口到 900 宽，网格换行不溢出；关闭后焦点回到选择器。

### 2.4 属性面板

1. 选中图片：来源 URL、许可说明、状态徽标、标记已核验、清除来源。
2. 只填 URL 不填许可 → “标记已核验”禁用；填全后点击，状态变“已核验”。
3. 清除 URL → 状态自动降为“待核验”，不会保留“已核验”。
4. 体检面板：徽标数量与列表一致；点击问题跳到对应页/元素；折叠后状态保留。
5. 生成一次并完成视觉评审，打开质量报告：顶部“评审依据”显示 PowerPoint 真实渲染或画布近似；有概念分与“总分已封顶”提示（若触发）。

### 2.5 导出报告

1. 导出 PPTX。
2. 报告包含：页数、原生对象、ZIP 条目、母版、主题色、体检计数（若开启）、回读通过/不一致、素材核验统计。
3. 故意把某张图片标为未标注，导出后“素材 未标注”计数 +1。
4. 在 PowerPoint 打开文件：文字可编辑、图表/表格为原生对象、图片未被压成整页图。

### 2.6 换一版（会话内）

1. 生成一册并让质量门通过，进入编辑器；在“设计”组点“换一版”。
2. 预期出现 3 张当前页的真实候选缩略图，卡片上标明配方名与版面问题数；内容区与页脚位置应与当前页不同。
3. 选一张：当前页换成该构图，正文、数字、引用、备注和页序不变；撤销一次回到原页。
4. 再点“换一版”，预期原候选仍可用，且当前配方不在候选里。
5. 手工移动任一对象后点“换一版”，预期提示“页面已被修改”，不打开候选；重新生成后才恢复。
6. 保存并重开项目后点“换一版”，预期提示“本次会话没有可换版的设计快照”，不提供过期候选。
7. 重复打开并取消 2 次，对话框底部应显示本机累计打开/采用次数；“设计质检 → 概览”应出现“换一版使用（本机）”卡片和累计数；关闭应用重开后计数仍在，且只含计数与配方 ID，不含标题或正文。

## 3. 真实模型校准

每个题材跑一次完整生成，保存方向输出、评分与耗时。

### 3.1 题材

| #   | 题材                                   | 重点                               |
| --- | -------------------------------------- | ---------------------------------- |
| 1   | 科技公司年度复盘（10 页，含 3 个指标） | 方向差异、数据关系、概念分         |
| 2   | 公益纪录片提案（8 页，图片为主）       | documentary 的 hero/band 是否成立  |
| 3   | 学术方法汇报（12 页，流程/对比）       | editorial 的编号栏、流程轨是否可读 |

### 3.2 记录

- 四个方向的 name / idea / typeContrast / imagery / rationale；
- 你选哪个、为什么（原话）；
- 概念分、总分、是否封顶；
- 数据页关系与最终图表类型；
- 总耗时、方向门额外耗时（提案 + 8 页预览）；
- 是否出现内容被改写、数字被改、页面顺序变化。

### 3.3 通过标准

1. 四个方向两两在**至少两项**（骨架、图像策略、字阶）不同；只换配色视为不通过。
2. 方向描述不复述标题、不虚构素材。
3. 概念分低于 60 时，你认同“这版没有观点”；高于 80 时不应明显空洞。
4. 时间趋势是折线、占比是饼图/条形、类别对比是柱状/条形；没有明显错配。
5. 内容零改动：标题、正文、数字、备注、页序与审核稿一致。
6. 方向门额外耗时不超过整册生成的 40%（记录实际值，不达标就调提示词或减少预览页）。

## 5. 不通过时怎么处理

- 方向同质：先看提示词是否把“两项不同”写死，再看模型温度；不要先加 UI。
- 概念分虚高：检查评分锚点与“换标题是否成立”的定义；不要直接调阈值掩盖。
- 图表错配：补 `data-relation.json` 样例，再改映射；不要只改测试预期。
- 内容被改：这是阻断级问题，停止发布并补命令层守卫测试。
- 证据等级错误：检查 `bestIteration` 对应轮次，而不是最后一次渲染。
