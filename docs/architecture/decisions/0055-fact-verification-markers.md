# 0055 事实核实标记

## 状态

已接受（V0.2）

## 背景

TRS 4.2 要求内容审核阶段能够"标记事实待核实""标记数字及引用来源"。此前审核页只有 `reviewed` 一个布尔值：要么整页已审核，要么没有。一个页面上"数据来自哪里我还没确认"这种状态没有地方记录，审核也就只能靠记忆。

AI 不能替人完成这件事：模型没有外部事实来源，让它判断"这条数据是否属实"只会产生看似专业的误判。所以核实必须是人的动作，系统只负责记录标记、跟随内容移动，并在确认前提醒。

## 决策

### 1. 标记挂在内容块上

`AiDraft` 的每页新增可选字段 `checks`：

```json
{ "blockIndex": 0, "kind": "number", "status": "unverified" }
```

- `blockIndex` 指这一页的内容块；缺省表示整页级（留给标题之类不属于某个块的判断）。
- `kind` 是 `fact` / `number` / `citation` 三选一，对应 TRS 里的三类核实。
- `status` 只有 `unverified` / `verified`。

字段可选：旧草稿没有它就是"这一页没有核实标记"，不需要迁移，也不需要固定样例。

### 2. 一个块最多一个标记

同一个块上同时挂"事实待核实"和"数字待核实"没有额外信息量，反而让页头的计数失真。重新标记会替换原有标记（包括类型）。想换类型就删掉重标。

### 3. 标记跟随块移动

标记按块下标保存，所以内容块重排或删除时必须一起重映射：

- 上移/下移：交换两个块的标记位置；
- 删除：被删块的标记消失，后面的块整体前移一位；
- 新增：没有标记。

重映射在 `remapChecks` 里完成，审核页把块的变更映射交给 App，App 在同一个撤销项里同时更新块和标记。

整页重写与拆页会重新分配正文，旧标记不再对应任何一段文字，因此这两类操作会清空该页的块级标记。

### 4. 标记不阻塞审核，但会回到待审核

- 待核实不是错误：页面仍然可以确认并进入模板选择。
- 新增一处待核实，或把已核实改回待核实，会让这一页回到"待审核"——它还没核完。
- 把最后一处改成已核实不会自动重新审核，仍要人点一次"已审核"。

这是刻意的：自动把页面变回已审核，等于替人签字。

### 5. 顶部提醒只报数量

`reviewIssues` 新增 `unverified-claims`（非阻塞）：`还有 N 处内容待核实`，并给出涉及的页面用于跳转。它和"标题是模板句"一样属于提醒，不属于缺陷。

## 后果

- 草稿 Schema 多一个可选字段；历史草稿、项目文件和 PPTX 导出都不受影响——核实标记只活在审核草稿里，不会进入演示文稿。
- 审核页每个内容块多一个"待核实"入口和一枚状态徽标；页头显示未核实数量。
- 保存时，如果某页有块因为内容被清空而在保存时被丢弃，这一页的块级标记一并丢弃：块下标会漂移，保留反而会指错内容。
- 标记进撤销栈：误点一次可以撤销，和其他编辑一样。

## 验证

- `aiDraftSchema`：旧草稿没有 `checks` 仍能解析；新标记解析出默认 `unverified`。
- `remapChecks`：重排交换位置；删除时丢弃对应标记。
- `reviewIssues`：待核实生成非阻塞的 `unverified-claims`。
- 审核页：块级"待核实"入口、状态徽标与页头计数。
- 重写与拆页清空块级标记（由 App 的替换逻辑保证）。

## 备选方案

- **把标记嵌进每个内容块**：类型上更直接，但内容块是判别联合，每个变体都要加字段，AI 输出合同和导出链路都会被牵动。
- **只做整页级标记**：实现最简单，但"第 2 条要点里的数字待核实"这种最常见的场景无法表达。
- **单独存一个核实状态文件**：不污染草稿，但会脱离撤销栈和历史版本，撤销一次编辑后标记就与现实脱节。
- **让 AI 自动标出需要核实的地方**：模型无法验证事实，只能猜；它给出的"可疑"标记会把人的注意力引向错误的地方。目前只支持人工标记。
