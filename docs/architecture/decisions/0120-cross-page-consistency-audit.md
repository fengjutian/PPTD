# 0120 跨页一致性由确定性审计报告

## 背景

ADR 0114 §14 要求版面在"页内正确"之外还要"跨页一致"：标题轴、页脚基线、内容左边界应当整册对齐。此前只有页内审计（ADR 0115）：每一页都能通过，整册仍可能看起来没排好——第 5 页的标题比其余七页右移了几个点，或某一页的页码下移了一行。而会移动整组元素的操作（对齐、留白、区域修复）恰恰最容易把一页推出队列。

## 决策

新增 `auditDeckLayout`（`core/layout/deck-audit.ts`），只看文档几何，报告两类跨页问题：

| 类型               | 判据                                                                 |
| ------------------ | -------------------------------------------------------------------- |
| `title-axis-drift` | 同一"标题带"内，某页标题左边界与该带中位数相差 > 0.8% 页宽（≈0.1in） |
| `footer-drift`     | 同一字号的页脚，某页顶边与该组中位数相差 > 0.4% 页高（≈0.03in）      |

三条限定决定了它不会误报：

- **只在同一"版式带"内比较。** 标题按框宽分组（相差 <0.5% 页宽算同一带），页脚按字号分组。封面、引文页、收尾页本来就换一个版式带，不与正文页比较——否则设计选择会被报成缺陷。
- **跳过模板页**（`layoutId`）。它们的几何属于上传的模板，与 ADR 0116 §3 同一条约定。
- **跳过居中与右对齐标题**、隐藏对象、空文本。左对齐标题才有一条共同的轴。

问题页数量计入变体的 `issueCount` 与 `issuePages`：卡片上的"N 处排版待调整 · 第 X 页"因此同时覆盖页内与跨页问题，不需要多一套 UI。

## 后果

- 整册的一致性第一次有了确定性判据：不再依赖人眼逐页比对缩略图。
- 内置十页 × 四个方向与词汇页在门里都要求"页内零问题 **且** 跨页零问题"（`tools/design-preview` 的测试），任何把某一页推出队列的改动都会在测试里失败。
- 审计只**报告**，不修复：把漂移的标题拉回轴上是设计变更，应由未来的对齐修复决定，而不是审计悄悄移动元素。
- 尚未覆盖：内容左边界（不同配方合法地不同）、页脚文字长度、页边距。它们需要各自的"版式带"定义，留待有真实案例时再加。

## 验证

- `deck-audit.test.ts`：同一轴的三页零问题；某页标题左移 0.5in 被点名（第 3 页）；某页页脚下移被点名；居中标题、不同宽度的封面带、模板页、不足三页都不报。
- `design-preview.test.ts`：四个方向与词汇页的跨页审计均为零——门同时守住页内与跨页。
