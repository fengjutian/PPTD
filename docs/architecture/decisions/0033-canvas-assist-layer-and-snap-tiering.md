# 0033：编辑辅助层不进文档模型，吸附按层级决胜

## 状态

已接受（2026-10-22）。

## 背景

V0.1 要求多页面 2D 编辑画布，TRS 4.4.1 明确列出网格、参考线、吸附、多选、对齐分布这些交互能力。之前的实现只有"选中一个对象 → 改属性 → 拖动"，缺少专业演示软件里最基础的那部分手感。

这里有一个容易走错的方向：把网格、参考线、选框也做成文档里的对象。看起来省事——反正都是画布上的东西——但代价很大：

- 网格线一多，文稿里就多出成百上千个元素，撤销栈、序列化、导出全部受牵连；
- 导出出来的 PPTX 会带上这些线，用户要自己删；
- 每次切换网格显示都要改文档，revision 疯涨。

另一个容易走错的方向是吸附的"决胜规则"。最直觉的实现是**按距离**：谁最近谁赢。实测下来这是错的。

## 决策

### 辅助层与文档模型完全隔离

1. 新增 `src/core/rendering/snap.ts`：纯几何层，只做计算，不碰文档也不碰 React。
   - `snapPosition` / `snapAnchors`：把一条边或一个锚点吸到目标线上。
   - `gridTargets` / `guideTargets` / `buildSnapTargets`：生成候选目标。
   - `snapMovingFrame` / `snapResizedFrame`：整块移动与单边缩放的吸附。
2. 新增 `src/store/canvas-guides-store.ts`：每页的参考线，以及 `gridEnabled` / `gridSnapEnabled` / `snapEnabled` 三个开关。**这个 store 里的东西不进文档、不改 revision、不进撤销栈、不导出。**
3. 新增 `src/features/editor/CanvasOverlay.tsx`：网格层与参考线层，纯视图组件（`CanvasGridView` / `CanvasGuideView`）与连接 store 的组件（`CanvasGridLayer` / `CanvasGuideLayer`）分开导出，前者可单独测试。
4. 参考线可拖拽、双击删除；拖动只在交互层发生，松开后没有留下任何文档痕迹。

### 吸附按层级决胜，不按距离

5. 吸附目标分三层，**层级优先于距离**：
   - `TARGET_TIER.grid = 1`：网格线；
   - `TARGET_TIER.center = 2`：页面中线；
   - `TARGET_TIER.guide = 3`：用户参考线。
6. 判胜顺序是"先比层级，层级相同再比距离"。这样页面中线永远不会被密集网格挤掉——0.1 英寸的密网格在任何位置都存在，按距离比的话中线根本抢不过。
7. 网格**显示**与网格**吸附**拆成两个独立开关。网格线参与比选会把对象切碎：对象边缘会粘到最近的那根网格线，而不是它真正该对齐的那条。

### 缩放只吸附被拖动的那条边

8. 缩放时只让被拖动的边贴到目标线上，固定边不动。否则每缩放一次，对象位置就悄悄挪动一点，用户会觉得"手滑了"。

## 结果

真实浏览器验证（headless Chrome + CDP）：

| 场景                      | 结果                       |
| ------------------------- | -------------------------- |
| 拖到离页面中线 3px        | 精确吸附，误差 **0.008px** |
| 拖到离中线 40px（超阈值） | 不吸附，保持 40px          |
| 开启网格吸附              | 吸到网格线，提示线同步显示 |
| 拖动参考线                | 480px → 540px，跟手精确    |
| 双击参考线 / 清除按钮     | 均能删净                   |
| 撤销                      | 网格与参考线保留，对象回退 |

## 未覆盖与风险

- 吸附阈值是固定的 8 屏幕像素，没有随缩放级别调整——高倍缩放时阈值偏大，低倍时偏小。
- 参考线只有水平/垂直两种，没有斜向参考线，也没有"角度吸附"。
- 网格只有固定间距，没有"对齐到对象"这一类目标（对象本身不算吸附目标）。
- 网格的绘制是 DOM 层叠在画布上，极高缩放下可能有轻微重绘压力。
