# ADR 0117：设计质量回路——先观测，再候选，后收敛

- 状态：提议（Phase 0 已实施）
- 日期：2026-10-26

## 背景

PPTD 的路线是“AI 做艺术指导，代码保证落地”：模型输出页面角色、构图意图、配方、焦点与配图意图，编译器负责几何、字号、安全区、内容消费和导出。这条路线在可编辑性、内容安全和跨页一致性上是对的，但当前质量提升主要靠增加配方、补提示词和事后视觉评审，缺少一个可度量的设计回路。

具体问题：

1. **表现力上限由配方库决定。** 四个方向、每方向 13–14 个配方，长尾内容形状（表格、引文+图片、对比+图片）没有配方，只能回退 legacy。每加一个配方都是设计、测量、测试和导出夹具的线性成本。
2. **合同存在双轨。** 设计提示词同时要求旧一代的 `layout/composition/emphasis/densityTarget/四色` 和可选的 `designPlan`；有 plan 时以 plan 为准。模型要在两代概念之间做选择，token 和歧义都是成本。ADR 0084 已经出现过“字段进了合同但没有消费点”的问题。
3. **“代码保证”在 PowerPoint 里会打折。** 画布、LibreOffice、PowerPoint 三处的断行、字体替换和 `normAutofit` 可能不同；重排保证文件装得下，不等于用户机器上打开一致。
4. **质量门能证明“不坏”，不能证明“好看”。** 确定性门查溢出、重叠、对比、越界与空洞；taste lint 是启发式且不阻断；视觉评审是模型打分，成本高、有方差。没有基准集和人工盲评，质量目标容易变成“过门即合格”。
5. **没有度量。** 一次生成里，多少页真的按计划编译、多少页被替换、哪些配方最常失败、哪类内容形状没有配方，目前只能靠翻报告和记忆。

## 决定

按以下顺序建设设计质量回路，不跳步：

```text
观测（Phase 0） → 候选（Phase 1） → 合同收敛（Phase 2）
      → 覆盖补齐（Phase 3） → 稳健性（Phase 4）
```

原则：

- 先让系统“看得见”自己的设计，再让它“量得准”质量，最后才让它“画得多”。
- 不通过增加 AI 字段来提升设计质量；新字段必须同时有类型、Schema、提示词、真实消费点和行为测试（ADR 0084）。
- 不开放任意坐标、CSS 或完整布局树；ADR 0114 的 DSL 必须有节点、属性和嵌套预算。
- 模型评分是证据之一，不是目标；最终质量以真实 PPTX、人工盲评和可编辑性为准。

## Phase 0：观测（本 ADR 已实施）

### 1. 设计提示词版本

新增 `DESIGN_PROMPT_VERSION`，与设计报告一起保存和显示。提示词或输出合同变化时必须递增；报告据此区分“哪一版提示词产出了这册设计”。

### 2. 设计度量摘要

新增 `summarizeDesignMetrics(report, totalSlides)`，从 `DesignDraftCompileReport` 派生：

- 计划覆盖率：`plannedSlides / totalSlides`；
- 采用、调整、拒绝页数；
- 换配方页数：请求配方与实际采用配方不同；
- 配方直方图：每个实际采用的配方覆盖多少页；
- 诊断直方图：稳定诊断码覆盖多少页，保留最高严重度；
- 每页决策：页码、结果、请求配方、采用配方、是否被替换。

度量只含计数、配方 ID 和稳定诊断码，不含标题、正文、数字、备注或图片。报告界面展示摘要和可展开的每页决策。

### 3. 合同守卫

`design-contract.test.ts` 增加：

- `DESIGN_PROMPT_VERSION` 必须符合 `design-pages-vN`；
- `pageDesignPlanSchema` 的配方枚举必须与 `RECIPE_CATALOG` 的键完全一致，避免 Schema 接受一个没有渲染实现的配方，或目录新增配方却忘了接线。

### 4. 验收

- 生成一册后，设计质检报告能看到计划覆盖率、采用/调整/拒绝、换配方页数、配方分布和提示词版本。
- 每页决策可展开，页码、请求配方、采用配方和结果与编译报告一致。
- 度量不改变文档、revision、撤销栈或项目状态；浏览器预览无 Tauri 依赖。
- `design-metrics.test.ts` 覆盖正常、全部拒绝、零页、同一诊断多页和替换计数。
- TypeScript 类型检查、ESLint 和相关 Vitest 通过。

## Phase 1：候选渲染与页级选择

当前模型在看不到画面的情况下写计划，编译器只能保证装得下，不能保证好看。下一步不是让模型写更多字段，而是让它看见候选。

- 复用 `buildDirectionPreviewPages` 的一页真实命令路径、`renderPresentationForVisualReview` 的缩略图、`inspectAiDesignedDraftCompilation` 的只读编译报告。
- 对当前页用同一份 plan + 2–3 个候选配方各编译一次，渲染缩略图，用户通过“换一版”选择；提交仍是单页设计事务，可撤销。
- 候选必须通过内容消费守卫；不允许改变正文、数字、引用、备注或页序。
- 先只覆盖 cover / section / claim 三类高方差页面，再扩展到全部页面。
- 记录“候选被选中/被放弃”的计数和用户选择，作为配方排序与后续模型选择的证据。

### Phase 1 实施记录：候选服务（2026-10-26）

本轮先落地不依赖界面的候选内核：

- 从方向预览抽出 `buildDesignPageCommand`，方向预览和候选共用同一份草稿、概念、页码、模板基座和配图；候选不再是第二条渲染路径。
- 新增 `buildDesignedPage`：在克隆文档上执行真实命令，同时返回一页文档和该次构建的编译报告，避免“构建一次、检查一次”得到两个答案。
- 新增 `buildDesignCandidates`：对同一份 `designPlan` 尝试 2–3 个替代配方，返回渲染所需的文档、编译报告、`auditSlideLayout`、taste lint 和确定性排序分；拒绝被编译器替代、被拒绝、改变内容或几何未变化的候选。
- 新增 `designWithRecipe`：选择候选时同时改写 `designPlan.recipe` 与 legacy `recipe`，避免两条路径对“请求了哪个配方”给出不同答案。
- 没有 `designPlan` 的页面不生成候选：legacy 路径没有编译报告，无法证明候选配方真的被采用，宁可报告 `DESIGN_CANDIDATE_PLAN_REQUIRED`，不把猜测包装成选择。
- 测试覆盖：候选内容不变、配方不被替代、源文档不被修改、无 plan、页码不存在、数量上限和 `designWithRecipe` 的同步。

会话内原型（2026-10-27）：编辑器“设计”组新增“换一版”，打开 3 张真实候选页；选中后以 `designWithRecipe` 改写该页设计，重建整册并作为**一个设计事务**替换文档，可撤销。上下文只保留在内存（生成命令、设计、概念、内容指纹和逐页签名）；重开项目或页面被编辑后，入口会明确提示没有可换版快照，而不是从已建页面反推假 plan。

本机使用计数（打开、采用、取消、无快照、页面已编辑、无 plan）写入 `localStorage`，只保存计数和配方 ID，不保存标题、正文或页面 ID；对话框底部和“设计质检 → 概览”显示累计打开/采用次数与最常采用的构图，用来判断是否值得做持久化。跨会话持久化 `AiSlideDesign` 仍需要 Schema 版本、迁移和固定样例；候选项的视觉排序仍由用户完成，模型选择尚未接入。

## Phase 2：合同收敛

- 新生成的页面只走 `PageDesignPlan` 一条合同；`palette`、`visualNarrative`、`visualAsset` 收进 plan 或一个 `PageDesignSpec` 包装。
- 旧字段由代码内部派生，只服务旧项目文件；保留 V1 parser 和迁移，不要求旧文件重写。
- 提示词与 Schema 共用同一份配方目录；新增提示词合同测试，防止 Rust 提示词与 TS Schema 漂移。
- 先 A/B，用 Phase 0 的度量证明解析失败率、调整率和视觉评分没有退化。

## Phase 3：覆盖补齐

- 补 `table-story`：目录目前没有 native-table 组件，提示词也明确表格页不选配方，导致表格页与配方页不是一套设计语言。
- 补一个通用 `anchor-split`：一个结构化/视觉锚点（chart/table/metric/quote/image）+ 一栏正文，覆盖“表格+正文、引文+图片、对比+图片”等组合。
- 用 `CompositionFacts` 建覆盖矩阵，统计每种内容形状有多少配方可承载；0 配方的形状进入路线图，而不是等用户撞上。

## Phase 4：稳健性

- 页级隔离：设计结果逐页校验，一页不合法不毁掉整册；失败页进入有界修复或回退，并报告稳定错误码。
- 统一几何审计：质量门与 `auditSlideLayout` 共用同一份文本测量，避免预览、生成门和导出三处口径不一致。

### Phase 4 实施记录：页级设计隔离（2026-10-27）

- 从 `aiPresentationDesignSchema` 拆出单页 `aiSlideDesignSchema`；新增 `parseAiPresentationDesign(raw, draft)` 逐页校验，返回设计结果和 `DesignSlideRepair[]`。
- 一页不合法或缺失时回退为安全版式（短封面、引用、摘要或正文页），不再让整册解析失败；模型多输出的页截断并报告 `DESIGN_SLIDE_EXTRA`。
- 回退页没有 `designPlan`，走既有 legacy 合成；它不如模型原设计，但保留已审核内容，且报告只记录页码、稳定错误码和 schema 级原因，不含正文。
- `generatePresentationDesign` 返回 `designRepairs`；生成质量报告的 notes 汇总回退页，用户能看到“第 N 页回退”。
- 设计度量新增 `repairedSlides`、`ignoredSlides` 和 `repairCodes`（字段不合法/缺页/多输出）；设计编译报告显示回退与忽略计数，便于观察真实模型的合同稳定性。
- 工作台 transport 用 `isDesignEnvelope` 判断最终设计，避免“一页字段不合法”被误判成无效轮次而丢掉整册。
- 测试覆盖：完整设计不动、单页非法、缺页、多页、短封面回退、非法 envelope，共 6 项。
- 统一几何审计仍在并行推进；本记录只覆盖页级设计隔离。

## 后果

### 批量候选的失败恢复（2026-10-27）

- 完整候选生成的并发上限由 3 降为 2，避免多条长结构化请求互相争抢同一超时预算。
- 图片仍是可选外部依赖：素材规划批准但没有返回真实像素时，对应页面在质量评估前切换到确定性的无图配方家族并重新编译；不得用缺图占位继续参加审美评分，也不得仅因图片服务失败淘汰整册。
- 候选级失败按主题、稳定错误码和用户可读原因保留在模板选择器中。批量汇总不得再把超时、Schema 错误和质量门拒绝折叠成没有上下文的“零产出”。
- 封面文字重叠、内容丢失、越界等硬错误仍然阻断；无图降级不放宽这些门槛，也不修改已审核内容。

正面：

- 设计质量第一次有可比较的基线：覆盖率、替换率、拒绝率、配方分布和提示词版本。
- 后续候选渲染、合同收敛和配方补齐可以用同一套度量证明收益，而不是靠感觉。
- 报告能解释“AI 要了什么、代码给了什么、为什么”，减少“这页为什么长这样”的排查成本。

代价与限制：

- Phase 0 只做单册报告，不做跨册持久化；跨册趋势要在后续把度量写入本地指标表。
- 度量描述的是编译结果，不是审美质量；它不能替代人工盲评。
- 提示词版本目前是人工纪律，Rust 提示词与 TS 常量还没有自动同步测试；Phase 2 补跨语言合同测试。

## 备选方案

- **继续加 AI 字段**：会让合同继续大于实现，重复 ADR 0084 的问题，不采用。
- **直接换更强模型**：能改善选择和修复，但不增加可画版面，也不产生度量，不采用。
- **先做完整布局树**：表达力上限更高，但验证、测量和权限成本也更高；在候选和度量跑通前不采用。
- **只靠视觉评分阈值**：模型评分有方差、可被阈值博弈，不能代替人工盲评和真实 PPTX 检查，不采用。
