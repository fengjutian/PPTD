# 0053 审核页的整页 AI 重写

## 状态

已接受（V0.2）

## 背景

内容审核页此前只有两个 AI 入口：顶部的“重新生成草稿”和每页的“恢复 AI 原稿”。前者重写整册，会把其他页面已经改好、审核过的文字一起丢掉；后者只能回到最初那一版。至于“这一页写得还行，但换一种写法更好”，用户只能一个字一个字地敲。

TRS 4.2 已经把“查看 AI 修改建议、对比修改前后、确认或拒绝 AI 提议”列为内容审核能力的一部分。审核页缺少的正是这条通道：AI 能写出草稿，却不能对已经写出来的草稿再给一次意见。

## 决策

### 1. 入口在页面卡片上，一次只重写一页

每个页面卡片新增“AI 重写本页”。它只处理当前这一页，其他页面的文字、顺序和审核状态都不受影响。整份重新生成仍然保留，用于“整册写法不对”的情况；两者按使用场景分开。

### 2. 重写不碰标题、页面计划和审核状态

- 标题由已定稿的大纲决定（ADR 0009），单页重写不改标题，提示词也不要求模型输出标题。
- `plan.purpose` / `plan.conclusion` 是这一页的沟通任务，重写后内容仍要服务它；模型做不到时只能在备注里说明，不能改结论。
- `reviewed` 不由 AI 决定。替换会走普通的内容编辑，页面因此回到“待审核”——这与手改一个字的语义一致。

### 3. 候选版本，而不是直接替换

对话框左右两栏并排显示“当前内容”和“AI 新版本”，各自带字数与演讲备注；用户点“替换本页”才写回草稿，关掉对话框就是拒绝。生成期间不花钱、不落盘：候选只活在对话框的状态里。

这也满足 TRS 对“对比修改前后”的要求：一次替换之前，用户看见的是完整的新旧两版，而不是模型的一串解释。

### 4. 替换是一次普通编辑

写入复用 `updateAiDraftWithHistory`，因此：一个撤销项、`reviewed` 置回 `false`、`aiOriginalDraft` 不变（“恢复 AI 原稿”仍能找回最初版本）。不新增内容版本、不改文档 revision——审核页的草稿仍是草稿。

### 5. 输出合同只含正文、备注和内容块

后端命令 `rewrite_presentation_slide` 接收整册主题、整册标题、整册页面标题、当前页内容和一段可选改写要求（≤300 字），返回：

```json
{ "slide": { "body": "...", "speakerNotes": "...", "blocks": [] } }
```

- 内容块才是渲染器真正画的东西，所以块优先；`body` 由块重新投影，避免审核页的字数和画面各说各话。
- 模型没给块时，用正文按行还原成 `bullet-list` 或 `paragraph`，不允许出现“有正文但没有块”的半成品。
- 正文和块都为空时直接失败（`AI_REWRITE_EMPTY`），不把空页面当成可替换的版本。
- 提示词明确禁止新增数字、来源、引语和案例，也禁止引入当前标题、页面计划和现有内容之外的事实。

### 6. 取消是真的取消

关闭对话框时递增请求号并调用 `cancel_ai_generation`，在途请求随之中断。请求号同时挡住迟到的响应，避免关掉窗口后候选又弹回来。

## 后果

- 审核页多一个低成本入口：不满意就重写一页，不用回到开始页重来。
- 草稿 Schema 不变，历史草稿和项目文件不受影响。
- 新增一个 Tauri 命令、一个前端 service、一个对话框组件和一条提示词；命令与提示词按现有 AI 端口接入，没有引入新的厂商绑定。
- 生成一页候选会产生一次模型调用。对话框在用户按“开始重写”之前不发请求，避免打开就看一次账单。
- 失败时保留上一版候选：一次重试失败不该把用户已经看过的版本清掉。

## 验证

- `rewritePresentationSlide` 的归一化：块优先、正文投影一致、无块时按行还原、空结果报错。
- 对话框：初始只展示当前内容、生成中禁用重复提交、候选可替换、失败原因可见、标题只读。
- 审核页：页面卡片出现“AI 重写本页”入口。

## 备选方案

- **直接替换，靠撤销兜底**：少一次点击，但用户看不到模型改了什么；审核页的核心动作是判断，不是接受。
- **一次给 2–3 个候选**：更接近写作工具，但单页重写的成本翻倍，而审核页需要的是“新旧对照”，不是“挑一个风格”。
- **重写整份草稿**：已有入口，代价是其他页面的人工修改被一起覆盖。
- **让 AI 顺手改标题**：标题是整册大纲的一部分，改一页标题会让相邻页的承接关系失去依据；标题仍然由人改。
