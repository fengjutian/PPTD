# 0076 确定性设计体检的边界与阈值

## 状态

已接受（2026-10-24）。实施见 [TASK-DESIGN-025](../development/tasks/0025-design-direction-and-taste-gates.md) 第 13 节。

## 背景

现有质量门 `validatePresentationVisualQuality` 只回答“有没有坏”：越界、重叠、溢出、对比度。它不回答“为什么这页像模板”：9pt 正文、四种字体、标题上方的小标签、非序列的 `01/02/03`、连续三页同骨架，都能全绿通过。

视觉评审能给出分数，但分数不可定位、不可复现，也不能作为 CI 门槛。需要一层纯确定性检查，把可判定的品味问题变成稳定 code、页码和元素引用。

## 决策

### 1. 独立模块，只读文档

新增 `src/core/design/taste-lint.ts`，输入 `PresentationDocument`，输出 `TasteReport`。禁止依赖 React、Tauri、PptxGenJS 和模型。检查不修改文档、不产生 revision、不进入撤销栈。

### 2. 两级结果

- **硬底线**：正文与标签字号、标题/正文字阶比。
- **软提示**：字体/色彩数量、模板装饰、跨页骨架重复、留白失衡。

两级都只报告。生成与导出不因体检失败而失败，[ADR 0015](0015-visual-qa-failure-must-not-block-generation.md) 继续有效。真正阻断导出的仍是几何/对比度硬门。

### 3. 阈值按页宽与 pt 双条件

页宽 pt = `pageSize.width / 12_700`。

| 规则        | 阈值                           |
| ----------- | ------------------------------ |
| 正文字号    | `< max(12pt, 1.25% 页宽 pt)`   |
| 标签字号    | `< max(9pt, 0.8% 页宽 pt)`     |
| 标题/正文比 | `< 2.5`，只对正文 ≥20 字的页面 |
| 字体族      | `> 2`（单字文本不计）          |
| 非中性色    | `> 4`（饱和度 <0.12 视为中性） |

固定 pt 保证小页面不失效，页宽比例保证大页面（例如 26.67in）不会把 12pt 当正文。两者取较大值。

### 4. 误报防护是规则的一部分

以下判定不是“调参”，而是规则定义：

- 单字文本是引号或图标，不计入字体族数量。
- 同页出现多个 `01/02/03` 视为版面索引，不报告“非序列编号”。
- 全页色块/底图是页面表面，不参与颜色与留白统计；留白只统计文字、图片、图表、表格的外接框。
- 连续骨架判断跳过封面与结论页；一个长串只报一条。

这些情况都在 `tools/design-preview` 的十页夹具上真实出现过，并由测试锁定。

### 5. 不持久化

体检是确定性函数：同一文档、同一版本、同一设置，输出必须可深度比较。报告不含时间戳，问题顺序固定为 `severity → slideIndex → code → elementIds`。

项目文件不新增字段。重新打开项目时重算；导出报告保存当次快照计数：

```ts
tasteLint?: { hard: number; soft: number; codes: Record<string, number> }
```

字段缺省表示“未执行”，界面与报告不得显示为通过。

### 6. 与视觉评审分工

体检只覆盖文本与对象级可判定项。模板底图内的装饰、图片内文字、抗锯齿与渲染器差异不在范围内，由视觉评审或人工确认。两者在报告里分开呈现，不合并成一个成功状态。

## 后果

正面：

- 品味问题第一次有稳定 code、页码和元素定位，可以点击跳转，也可以做回归计数。
- 不阻断生成，不影响既有导出与撤销语义。
- 阈值可被测试覆盖，模型或配方变化后能看出退化。

代价与限制：

- 阈值是经验值，可能与个别模板的排版规范冲突；规则允许按文档覆盖，但默认值需要持续校准。
- 留白是外接框代理，不理解真正的视觉重心；它只提示，不做结论。
- 装饰规则依赖文本结构与 `contentRef`，对完全无角色的导入文档覆盖有限。

## 验证

- `src/core/design/taste-lint.test.ts`：18 项，覆盖 11 条规则、阈值边界、确定性、四类误报防护。
- `tools/design-preview/design-preview.test.ts`：十页自有夹具零发现；导出报告为 `{hard:0,soft:0,codes:{}}`。
- `src/features/pptx-export/export-pptx.test.ts`：8pt 正文导出成功，报告 `hard=1` 且 code 正确。
- 全量测试、类型检查、ESLint、生产构建通过。

## 备选方案

- **并入质量门**：会让品味提示变成阻断，违反 ADR 0015；也会让“坏没坏”和“像不像模板”共用一个 `passed`。
- **只用视觉评审打分**：不可定位、不可复现、依赖模型与网络，不能作为回归基线。
- **持久化体检结果**：需要 Schema 迁移和上限裁剪，而确定性函数重算成本极低；只在导出报告保留快照计数。
- **把阈值写进主题预设**：不同主题可以有不同字阶，但可读性下限不应随主题变化；主题可以更严，不能更松。
