# 0039：自动保存写项目本体，演讲备注是内容

## 状态

已接受（2026-10-23）。

## 背景

两个缺口，一个关于数据安全，一个关于内容完整性。

### 自动保存只写恢复副本

原来的自动保存只写 `recovery/latest.pptd`——一份"崩溃恢复快照"。用户改完东西，关掉应用，下次打开看到的还是**上一次手动保存的版本**。

这在字面上叫"自动保存"，但用户的实际体验是"我明明改过了"。要保住改动，还得自己记得按保存。而自动保存存在的全部意义就是"不用记得"。

同时它还制造了一个假象：状态栏在改动后短暂显示"未保存"，用户以为没保存上，于是不敢关应用。

### 演讲备注在编辑器里改不了

导出器早就写了 `slide.addNotes(slide.content.speakerNotes)`，但编辑器里没有输入框——备注只能在 AI 审核页改，而审核页改的是草稿，套用模板之后草稿和文稿就分家了。

于是备注这条链路是断的：**能导出，但不能编辑**。

## 决策

### 自动保存：有路径就写项目本体

1. 新增 `src/services/project-files.ts` 的 `autoSave(document, projectPath, imagePath)`：
   - **有项目路径**：直接 `save_project` 写项目本体。
   - **没有项目路径**（新项目还没另存过）：仍然只写恢复副本。那时无处可写；弹保存对话框会把自动保存变成打断用户的东西。
2. 走**同一个队列**（`enqueueRecovery`）。恢复副本和项目本体可能引用同一批资源文件，并发写会互相踩。
3. 写成功才推进 `savedRevision`。写失败时状态仍是"未保存"——用户不该以为改动已经安全了。
4. `savedRevision` 的推进用 `Math.max` 语义：不能把标记往回拨，否则并发的两次自动保存会让状态倒退。

### 演讲备注是内容，不是设计

5. 新增命令 `set-speaker-notes`。它改的是 `slide.content.speakerNotes`——**内容域**，不是设计域。
6. 备注会进 PPTX 的备注页，也进内容哈希。用户改了备注，这一页就不该再报"已审核"：所以复用 `markContentChanged`，把 `approved` 变成 `changed`。
7. 属性面板加"演讲备注"区，用新的 `TextAreaField` 组件：多行、**失焦才提交**。边打字边提交会让一段长备注变成几十个撤销项。
8. `TextAreaField` 保留本地草稿，未提交时忽略外部的 value 更新——否则别处的重渲染会把光标挪到句子中间。
9. 备注区在页面属性里，选中对象与否都可见：备注属于整页，不属于某个对象。

## 结果

真实浏览器验证（headless Chrome + CDP）：

| 场景 | 结果 |
|---|---|
| 属性面板 | 有"演讲备注"区和 textarea，placeholder 正确 |
| 输入并失焦 | 提交成功，**内容 revision +1**，设计 +0 |
| 撤销一次 | 备注清空，revision 回到 0 |

导出的 PPTX 里备注真的在：

```xml
<!-- ppt/notesSlides/notesSlide1.xml -->
<a:t>这一页先讲背景</a:t>
```

自动保存的测试覆盖了三条路径：有路径写项目本体、无路径只写恢复副本、图片源路径正确传给后端。

## 未覆盖与风险

- 自动保存的防抖窗口是 1500ms，没有做"连续编辑时暂停、停止编辑后落盘"这种更细的策略。
- 自动保存不写 `.bak` 备份。项目本体的原子替换保证"中断后保留上一个有效版本"，但那是在同一文件上；如果写出的内容本身有问题（逻辑错误而不是写入失败），没有回退点。
- 演讲备注只在属性面板里编辑，没有大纲视图或演讲者视图。
- 备注的长度限制是 20000 字符，但没有按页给出"备注过长"的提醒——实际限制来自 PPTX 备注页的排版，超长的备注在 PowerPoint 里会被截断显示。
- 备注不参与导出前的警告检查（比如"备注与页面内容不符"这类提示）。
