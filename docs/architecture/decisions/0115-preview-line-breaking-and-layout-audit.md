# 0115 预览断行与排版审计：不再吞字，也不再假称通过

## 状态

已接受（2026-10-26）

## 背景

ADR 0114 把测量、编译和诊断写进了布局系统，但生成结果仍然出现三类"看起来只是偶然"的缺陷：

1. **预览吃掉一行。** 版面测量用 `measureTextWidthEm`（按 100px 参考字号量出的 em 宽度）判断行数，预览渲染器却用当前字号的 `measureText` 逐字累加。两者在临界宽度上会差出一个字；渲染器随后用 `Math.floor(height / lineHeight)` 把放不下的行整行丢掉。截图里的"…收入与利"少一个"润"、流程步骤"Duet AI 集成至"少了后半句，都是这么没的。丢掉的是**已审核正文**，而且没有任何提示。
2. **图标徽标是空的。** 卡片网格会用 `iconForText` 把能画成图标的编号换成图标，但 `presentation-renderer` 根本没有 `icon` 分支：导出的文件里有一枚图标，预览里只有一个空圆点。
3. **"排版检查通过"是硬编码的。** 变体卡片的 `issueCount` 一直写 0，预览弹窗于是对所有版本宣布通过——包括上面两页。用户看到的红框，正是系统自己没看见的缺陷。

布局系统要"保证布局"，靠的不是再多一条规则，而是让**测量、预览、导出、报告**对同一段文字给出同一个结论。

## 决定

### 1. 断行只有一个事实来源

新增 `fitTextToFrame`（`core/rendering/text-fit.ts`）：给定框宽、框高、字号与行高，返回该框能容纳的字号与断行结果。它和 `estimateTextLines` 共用同一个测量器（`measureTextWidthEm`），因此：

- 布局算出一行的文字，预览也画成一行；
- 预览按 em 宽度断行，不再使用当前字号的 canvas 度量（逐字 hinting 会在小字号上累积出 1–2% 的差，正好足以让临界行多断一行）。

测得准不等于放得下，所以规则 2 兜底。

### 2. 放不下就缩小，绝不丢行

`fitTextToFrame` 在整块文字装不进框时按固定步长缩小字号（乘 0.97，可复现），直到装下为止；下限是原字号的 55%，到此仍装不下才标记 `overflow`。

这与导出完全一致：导出对每个文本框写 `fit: "shrink"`（`normAutofit`），PowerPoint 本来就会缩字而不是裁字。以前预览不缩、直接丢行，等于让用户看到一份从未存在过的文件。

自动缩到不可读仍然禁止（ADR 0114 §6）：55% 的下限就是那条线，越过它时如实报 `overflow`，由审计与质量门说清楚。

### 3. 预览必须画出文档里的每一种对象

`presentation-renderer` 补上 `icon` 分支：按内置 24×24 网格把路径描边画进元素框，颜色与线宽取元素样式，和导出的 SVG 使用同一份 `BUILTIN_ICONS`。"预览里没有"不再等于"文件里没有"。

### 4. 排版问题由确定性审计给出，而不是写死

新增 `auditSlideLayout`（`core/layout/layout-audit.ts`），只看文档几何，不调模型、不读像素，报告五件事：

| 类型             | 判据                                                                         |
| ---------------- | ---------------------------------------------------------------------------- |
| `text-overflow`  | 按渲染器的断行与行高算出的文字高度 > 框高 × 1.02                             |
| `out-of-bounds`  | 文本框越出页面边界（图片与色块的出血是有意构图，不在此列）                   |
| `text-overlap`   | 两段文字的**墨迹框**交叠面积 > 较小者 12%                                    |
| `text-orphan`    | 多于一行且末行只剩 1–2 个字符（孤字，如「…贡献有 / 限」）                    |
| `table-overflow` | 表格按单元格断行算出的总高 > 框高 × 1.02（报告里点名最高的那一列与它的行数） |

`table-overflow` 补的是"整类对象没有度量"的洞。原生表格自己不存行高：导出把框、字号和一个均分的行高交给 PptxGenJS，**PowerPoint 在单元格放不下时会把那一行撑高**，表格于是长到框外、压住下面的元素；而审计此前只看 `type === "text"`，预览更是把每个单元格直接截断到 12 个字符，两处都不说真话。现在 `tableGeometry`（`core/rendering/table-geometry.ts`）按列宽、内边距、字号和同一个断行器算出每行所需高度与整表所需高度：预览按它绘制（单元格换行、行高随内容增长，与文件一致），审计按它报告，`table-overflow` 与 `text-overflow` 用的是同一套行距与容差。

`text-overlap` 比的是墨迹而不是文本框：同一页脚带上"第二部分 门店效率"（左对齐）和"03 / 10"（右对齐）共用一个大框是正确排版，按框判重叠会把整册都报成问题——内置的 paper 方向就是这么被误报的。墨迹框（`textInkBox`）按对齐方式与实测行宽算出文字真正占的区域；确定性质量门（`presentation-quality-gate`）的文本重叠检查也改用同一判据，否则这类页面会在生成阶段被直接淘汰。

`text-orphan` 补的是"框放得下但读起来像没排完"这一类：所有字形都在框内、高度也不超，最后一行却只有一两个字。重排会尽力避开它（ADR 0116），避不开的由审计如实报出，预览不再宣称通过。

表格在三个地方共用同一份几何（`tableGeometry`）：预览按它绘制、审计按它报告、导出按它写行高（`rowH` 取"均分值"与"内容所需高度"的较大者）。均分让一张短表仍然填满框，内容更长的那一行则按实测长高——文件、预览和报告从此都是同一张表。

变体卡片的 `issueCount` 改为该审计的问题数。审计只**报告**，不阻断生成（ADR 0015：视觉质检不能挡住生成）；挡住的是本来就在挡的确定性质量门。

`issueCount` 允许缺省，表示"这一版还没有排过、无从审计"（例如按需渲染的 AI 设计方向）。缺省时卡片与预览**不显示**任何通过/待调整字样——没有检查过就不该给出结论。这是本轮唯一改动的 UI 语义：三种状态（未检查 / 通过 / N 处）取代原来的两种。

只有一个数字时，用户还得自己翻缩略图去找问题页；所以变体同时带上 `issuePages`，预览把它排成"第 2–3、6 页"。编辑画布则用 `textOverflowsFrame` 给放不下的文字加一圈虚线的琥珀色边（`SlideElementFrame` 的 `text-overflow` 类，只作用于 `.slide-canvas`，缩略图保持干净）——画布仍按 CSS 裁字，但不再**默默**裁。

## 后果

正面：

- 已审核正文不会因为一个字的宽度差而在预览里消失。
- 预览与 PPTX 的行为一致：同样的断行、同样的缩字。
- 图标在画布、预览、文件里是同一个对象。
- "排版检查通过"变成一个可以追溯到具体元素的事实，而不是常量；没检查过的版本干脆不下结论。
- 问题数目能落到具体页，画布上也能一眼看到哪一段放不下。

代价与限制：

- 缩字会让"容量不足"看起来比"被裁切"温和。因此容量问题必须由 `text-overflow` 诊断与审计继续暴露，不能靠肉眼。
- 测量器现在带**字重与字距**（`widthEm(text, family, bold)` + `letterSpacingPt`）。预览、审计、重排、文件，以及配方与旧版构图的拟合都用同一组参数：`deriveDesignTokens` 暴露 `titleTrackingPt` / `bodyTrackingPt`，配方通过 `headingMetrics()` 传给 `fittedFontSize`；旧版 `text()` 直接从主题 token 取字距，并在创建元素时就写进样式，不再"先按无字距拟合、事后再补"。
- 剩下的近似是**行内粗体**：`runs` 里只要有加粗片段，整段就按粗体测量（上界）。这让一段混排最多小一号，但绝不会出现渲染器多出一行、拟合却没数到的情况；精确的逐字宽度需要断行器携带片段索引，留作后续。
- 编辑画布现在也按**测量出的行**绘制（`RichText` 用同一个断行器，每行是一个 `white-space: pre` 的盒子），所以画布、缩略图、预览和文件在同一处换行；浏览器不再有机会自行重排。超框的行仍被 `.slide-element.text > div` 的 `max-height` 裁掉，但外框会画警告边——把画布改成"溢出可见"牵扯相邻元素的交互，属于下一步。
- 缩字只发生在预览与导出（`normAutofit`），不会回写文档字号；文档里保留设计意图的字号，容量冲突靠诊断暴露。
- 审计只判断"框放不放得下"，不判断可读性（行长、字号带）——那属于味觉 lint。

## 验证

- `text-fit.test.ts`：整块放得下时保持字号；断行数与 `estimateTextLines` 一致；超框时缩字后逐字保留（含多段落）；下落 55% 仍放不下时报 `overflow`；15 个全角字在 300pt 框内会因 1pt 字距断成两行；注册测量器后粗体按粗体宽度断行。
- `measure.test.ts`：10 个全角字在 200pt 框内，主题加 1pt 字距后标题从 20pt 退到 19pt（规划阶段就算准）；`headingMetrics` 总是带粗体，0 字距时不写该字段。
- `layout-audit.test.ts`：超框、越界、文本重叠、孤字、表格超框各报一条；放得下的文字、表格与隐藏对象不误报；同带宽左右对齐的两段文字不互报。
- `table-geometry.test.ts`：等分列宽减去内边距得到文字宽度；长单元格换行且逐字保留；行高取最高单元格；空单元格保留最小行高；整表高度等于各行之和。
- `export-pptx.test.ts`：短表的行高之和等于框高；长单元格所在的行比别的行高，整表因此高过框——文件与测量一致。
- `VariantPreviewDialog.test.tsx`：问题页列表渲染成「第 2–3、6 页」；未审计的版本不显示结论。
- `SlideScene.test.tsx`：放不下的文字带 `text-overflow`，放得下的不带。
- `RichText.test.tsx`：画布渲染出的行数等于 `estimateTextLines`（同一段文案、同一框宽），每行都带 `white-space: pre`；片段样式、标记、垂直对齐不变。
- `text-refit.test.ts`：带 1pt 字距、正好卡在框宽上的标题会被缩字（无字距时不动）。
- `text-metrics-canvas.test.ts`：粗体走 700 字面，且缓存按字重区分。
- `presentation-renderer`：文字绘制改为调用 `fitTextToFrame` 并用同一 em 宽度断行；`icon` 元素进入渲染循环。
- 类型检查与 ESLint 覆盖新增模块。

## 备选方案

- **让渲染器继续用 canvas 度量，布局改成按字号测量**：能对齐，但会让断行依赖渲染分辨率，导出与画布再次分叉；不采用。
- **放不下就裁切并加水印提示**：仍然丢正文，只是丢得更显眼；不采用。
- **把审计结果接进质量门阻断生成**：会让一个字的宽度差淘汰整个版本，与 ADR 0015 冲突；不采用。
- **在预览里按裁切后的行数重排**：改了设计却不改文档，预览与文件必然不一致；不采用。
