# 0115 预览断行与排版审计：不再吞字，也不再假称通过

## 状态

已接受（2026-10-26）

## 背景

ADR 0114 把测量、编译和诊断写进了布局系统，但生成结果仍然出现三类"看起来只是偶然"的缺陷：

1. **预览吃掉一行。** 版面测量用 `measureTextWidthEm`（按 100px 参考字号量出的 em 宽度）判断行数，预览渲染器却用当前字号的 `measureText` 逐字累加。两者在临界宽度上会差出一个字；渲染器随后用 `Math.floor(height / lineHeight)` 把放不下的行整行丢掉。截图里的"…收入与利"少一个"润"、流程步骤"Duet AI 集成至"少了后半句，都是这么没的。丢掉的是**已审核正文**，而且没有任何提示。
2. **图标徽标是空的。** 卡片网格会用 `iconForText` 把能画成图标的编号换成图标，但 `presentation-renderer` 根本没有 `icon` 分支：导出的文件里有一枚图标，预览里只有一个空圆点。
3. **"排版检查通过"是硬编码的。** 变体卡片的 `issueCount` 一直写 0，预览弹窗于是对所有版本宣布通过——包括上面两页。用户看到的红框，正是系统自己没看见的缺陷。

布局系统要"保证布局"，靠的不是再多一条规则，而是让**测量、预览、导出、报告**对同一段文字给出同一个结论。

## 决定

### 1. 断行只有一个事实来源

新增 `fitTextToFrame`（`core/rendering/text-fit.ts`）：给定框宽、框高、字号与行高，返回该框能容纳的字号与断行结果。它和 `estimateTextLines` 共用同一个测量器（`measureTextWidthEm`），因此：

- 布局算出一行的文字，预览也画成一行；
- 预览按 em 宽度断行，不再使用当前字号的 canvas 度量（逐字 hinting 会在小字号上累积出 1–2% 的差，正好足以让临界行多断一行）。

测得准不等于放得下，所以规则 2 兜底。

### 2. 放不下就缩小，绝不丢行

`fitTextToFrame` 在整块文字装不进框时按固定步长缩小字号（乘 0.97，可复现），直到装下为止；下限是原字号的 55%，到此仍装不下才标记 `overflow`。

这与导出完全一致：导出对每个文本框写 `fit: "shrink"`（`normAutofit`），PowerPoint 本来就会缩字而不是裁字。以前预览不缩、直接丢行，等于让用户看到一份从未存在过的文件。

自动缩到不可读仍然禁止（ADR 0114 §6）：55% 的下限就是那条线，越过它时如实报 `overflow`，由审计与质量门说清楚。

### 3. 预览必须画出文档里的每一种对象

`presentation-renderer` 补上 `icon` 分支：按内置 24×24 网格把路径描边画进元素框，颜色与线宽取元素样式，和导出的 SVG 使用同一份 `BUILTIN_ICONS`。"预览里没有"不再等于"文件里没有"。

### 4. 排版问题由确定性审计给出，而不是写死

新增 `auditSlideLayout`（`core/layout/layout-audit.ts`），只看文档几何，不调模型、不读像素，报告三件事：

| 类型            | 判据                                                       |
| --------------- | ---------------------------------------------------------- |
| `text-overflow` | 按渲染器的断行与行高算出的文字高度 > 框高 × 1.02           |
| `out-of-bounds` | 文本框越出页面边界（图片与色块的出血是有意构图，不在此列） |
| `text-overlap`  | 两段文字的**墨迹框**交叠面积 > 较小者 12%                  |

`text-overlap` 比的是墨迹而不是文本框：同一页脚带上"第二部分 门店效率"（左对齐）和"03 / 10"（右对齐）共用一个大框是正确排版，按框判重叠会把整册都报成问题——内置的 paper 方向就是这么被误报的。墨迹框（`textInkBox`）按对齐方式与实测行宽算出文字真正占的区域；确定性质量门（`presentation-quality-gate`）的文本重叠检查也改用同一判据，否则这类页面会在生成阶段被直接淘汰。

变体卡片的 `issueCount` 改为该审计的问题数。审计只**报告**，不阻断生成（ADR 0015：视觉质检不能挡住生成）；挡住的是本来就在挡的确定性质量门。

`issueCount` 允许缺省，表示"这一版还没有排过、无从审计"（例如按需渲染的 AI 设计方向）。缺省时卡片与预览**不显示**任何通过/待调整字样——没有检查过就不该给出结论。这是本轮唯一改动的 UI 语义：三种状态（未检查 / 通过 / N 处）取代原来的两种。

## 后果

正面：

- 已审核正文不会因为一个字的宽度差而在预览里消失。
- 预览与 PPTX 的行为一致：同样的断行、同样的缩字。
- 图标在画布、预览、文件里是同一个对象。
- "排版检查通过"变成一个可以追溯到具体元素的事实，而不是常量；没检查过的版本干脆不下结论。

代价与限制：

- 缩字会让"容量不足"看起来比"被裁切"温和。因此容量问题必须由 `text-overflow` 诊断与审计继续暴露，不能靠肉眼。
- 测量器仍然**不带字重与字距**：`letterSpacingPt`（主题给标题加的 tracking）只作用于导出，粗体在实际字体里也更宽。预览与文件在这两处仍可能差 1–3%，需要后续给测量器补字重与字距参数。
- 编辑画布走 DOM/CSS 断行，且 `.slide-element.text > div` 有 `max-height: 100%; overflow: hidden`，所以画布上仍然会**裁掉**超框的行，只是不会被测量器发现。把画布也改成"缩小/溢出可见"是下一步，涉及 `.slide-element.text` 的交互（溢出文字会压到相邻元素上），本轮不动。
- 缩字只发生在预览与导出（`normAutofit`），不会回写文档字号；文档里保留设计意图的字号，容量冲突靠诊断暴露。
- 审计只判断"框放不放得下"，不判断可读性（行长、字号带）——那属于味觉 lint。

## 验证

- `text-fit.test.ts`：整块放得下时保持字号；断行数与 `estimateTextLines` 一致；超框时缩字后逐字保留（含多段落）；下落 55% 仍放不下时报 `overflow`。
- `layout-audit.test.ts`：超框、越界、文本重叠各报一条；放得下的文字与隐藏对象不误报。
- `presentation-renderer`：文字绘制改为调用 `fitTextToFrame` 并用同一 em 宽度断行；`icon` 元素进入渲染循环。
- 类型检查与 ESLint 覆盖新增模块。

## 备选方案

- **让渲染器继续用 canvas 度量，布局改成按字号测量**：能对齐，但会让断行依赖渲染分辨率，导出与画布再次分叉；不采用。
- **放不下就裁切并加水印提示**：仍然丢正文，只是丢得更显眼；不采用。
- **把审计结果接进质量门阻断生成**：会让一个字的宽度差淘汰整个版本，与 ADR 0015 冲突；不采用。
- **在预览里按裁切后的行数重排**：改了设计却不改文档，预览与文件必然不一致；不采用。
