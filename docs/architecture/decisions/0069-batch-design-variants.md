# 0069：批量设计版本——AI 选模板，用户只挑一版

## 状态

已接受（2026-10-25）。

## 背景

模板步骤把 17 套内置主题平铺给用户，先选模板、再看效果。真实反馈是"我不选，AI 帮我选，一次生成 8 个"：

- 推荐只有一条关键词规则：标题命中哪一族就选哪套，说不清理由，也不看内容结构（图表、表格、指标、配图位）。
- 一次只产出一种设计，用户只能靠想象在 17 套配色之间取舍，选完才发现不合适，再改就要重新生成。
- "换一套看看"的真实成本是一整轮设计生成，而不是一次点击。

## 决策

1. **推荐是确定性排名，不是模型抽样。** 新增 `src/core/design/theme-preset-ranking.ts`：按题材规则（与 `theme-preset-inference` 共用同一张规则表）、图表/表格/指标页数量、配图位数量、正文密度给 17 套主题打分排序，并生成一句可展示的理由。同一份内容每次得到同一排序，理由可以写进测试。模型负责设计，不负责这条排序。
2. **推荐与批量共用同一个第一名。** 选择器标记的"AI 推荐"和批量版本里带"AI 推荐"的那张卡来自同一次排名，避免界面推荐 A、批量却先排 B。
3. **批量不重复模板，并按强调色相做最远贪心。** 先取分数最高的一版，之后每次取"与已选色相距离最远"的剩余模板。色轮是聚集的（5 套蓝、3 套青），固定 22° 间隔在 8 版时无解，所以规则是"绝不放过更远的候选"，而不是一个做不到的最小间隔。
4. **批量只跑到设计为止。** 每个版本都执行真实的设计调用和本地渲染，但不生成配图、不跑视觉复评：这两步最贵，为 8 个版本各付一次、然后丢掉 7 个，是把钱花在不会被看到的地方。画廊里的每一版都是真实排版，不是主题色卡。
5. **选中的版本续跑原管线。** `generateFromDraft` 增加可选 `prepared: { presetId, concept, design }`：跳过方向门、概念调用和设计调用，配图、确定性质量门、视觉复评、写项目全部照旧。用户挑的那一版不会因为"再生成一次"而变样。
6. **版本数默认 8，可 4/6。** 每个版本一次设计请求（整册一次返回），8 版约 9 次模型调用、分钟级；面板上写明耗时与"选定后其余丢弃"，并可以随时停止。
7. **失败与取消按版本隔离。** 单个版本失败只丢自己并记诊断日志；全部失败才报错；取消中断在途请求，不写任何项目内容。

## 结果

- 模板步骤从"先选再看"变成"看完再选"：8 张卡各带封面与首页真实渲染、AI 理由和确定性排版问题数。
- 选择器里的"AI 推荐"第一次有了解释：推荐理由写在主题详情里。
- 内容隔离不变：批量与单版都走 `apply-ai-designed-draft`，已审核内容不参与改写。
- 新增测试：排名排序与理由、8 版模板唯一且色相分散、数量夹取、概念兜底映射、画廊卡片与问题数渲染。

## 未覆盖

- 批量不生成配图，画廊预览比成品素；面板与画廊都写明了这一点。选中后才会补图。
- 设计调用仍是分钟级：8 版串行执行，没有并行化（共用 taskId 的流式进度会互相覆盖）。
- 其余 7 版只存在于内存，选定或返回即释放；没有"把 8 版都保存成文件"的入口。当前产品语义是挑一版，不是批量交付。
- 排名是规则而不是模型判断：题材词表之外的内容（例如纯代号项目）会退到页面类型与密度匹配，理由会比较泛。
