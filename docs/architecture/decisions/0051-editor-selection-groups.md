# 0051 编辑期选择组与导出展平

## 状态

已接受（V0.2）。导出展平部分由 [0109 原生分组导出](0109-native-group-export.md) 取代；编辑期选择组模型不变。

## 背景

TRS 4.4.1 把“分组对象”列为支持的对象，4.4.4 要求“排列”功能区提供组合/取消组合。

真正的分组有两种实现：

1. 嵌套 `group` 元素，子元素有自己的坐标和递归 Schema。
2. 页面级元数据，成员仍是平铺元素。

嵌套元素会波及渲染、命中测试、Z 序、动画、内容同步、复制粘贴、导出和所有按 `slide.elements` 遍历的代码；PptxGenJS 也没有分组 API，导出仍要自己后处理 OOXML。V0.2 的时间更适合先补“选择组”，把原生分组导出留给独立任务。

## 决策

### 组是页面元数据

```ts
interface SlideGroup {
  id: string;
  elementIds: ElementId[];
}
```

元素继续平铺在 `slide.elements` 中，保持原有 Z 序。组只声明“这些对象一起选”。

### 选择展开，而不是新增一套组命令

store 的 `selectElement`、`toggleElement`、`selectElements` 把任一成员展开成整组。移动、对齐、分布、锁定、删除沿用既有多选命令，不需要为组再写一遍几何逻辑，也不会出现“组移动”和“对象移动”两套撤销语义。

### 不变量与清理

- 组合至少两个、全部存在、全部未锁定、均不属于现有组。
- 一个元素只能属于一个组；组 id 全局唯一。
- 删除成员后丢弃整组，避免半组；重排版式清空分组；复制页不继承分组。
- 复制/粘贴不携带分组。

### 导出展平并如实报告

> 后续：[0109](0109-native-group-export.md) 已实现原生 `<p:grpSp>` 导出。本节保留当时的选择记录。

PptxGenJS 没有分组 API，本版不写 `<p:grpSp>`。成员仍导出为原生可编辑对象，只是 PowerPoint 中不再成组。

导出 preflight 新增 `group-not-exported`，逐页说明；不把“编辑期分组”说成“原生分组”。

## 后果

- 用户获得组合、取消组合、整组点选、整组移动/对齐/删除的能力，且可撤销、可保存。
- 组整体缩放/旋转、嵌套组、组内进入编辑不存在；控制柄仍按单个成员工作。
- 复制页和复制粘贴得到散开的副本，这一点在任务书中明确。
- 原生分组导出是独立任务 TASK-GROUP-002，需要 OOXML 后处理与真实 PowerPoint 验证。

## 备选方案

- **嵌套 group 元素**：模型更“正确”，但要改所有元素遍历和 PptxGenJS 导出，V0.2 风险过高。
- **只做 UI 暂时选中、不持久化**：关闭项目就丢失，无法撤销，等于假功能。
- **直接把成员 XML 包进 `<p:grpSp>`**：PptxGenJS 输出没有稳定的元素边界与组变换数据，未经 PowerPoint 验证就写会生成需要修复的文件；留给独立任务。
