# 0063：统一页面骨架与测量式构图

## 状态

已接受（2026-10-24）。实施见 [TASK-DESIGN-002](../development/tasks/0012-page-chrome-and-measured-composition.md)。

## 背景

2026-10-24 对当前生成链路做的 7 页样张复核暴露出一组同源问题：

- 同一册的“标题 + 短线 + 内容”表头不在一条线上：标题 y 在 0.09 与 0.12 之间跳，短线 y 在 0.245、0.265、0.38 三个高度，`comparison` 页没有短线，内容顶边在 0.29–0.44 之间。
- 空页不是“留白”，而是“余数”：收束页正文框从 0.29 到 0.87，17pt 文字只写到 0.38；指标页数值 56pt 顶在一个 0.27 页高的框里，标签固定在 0.73；流程卡高度上限 0.28 页高并整体居中。
- 编号页把 3–4 行均分到 0.55 页高，17pt 单行的行距变成 1.35in；卡片左右内边距用页宽的 0.045（约 0.6in），在一张 2.77in 的流程卡上把文字挤成“建/库”这类孤行。
- `DesignTokens.space / grid / radius` 定义了但没有被任何配方消费；`fittedFontSize` 只会从 preferred 往下缩，页面再空也不会把字放大。
- 结果是“每一页都没有越界、没有重叠、对比度合格”，但整册没有共同轴线、没有尺度对比、没有焦点，读者看到的是“排版正确但不好看”。

根因不是某一条规则写错，而是**没有一个页面骨架的所有者**：配方、旧分支、卡片、流程、对比各自硬编码标题/短线/内容顶边，垂直位置由“等分”或“居中”临时决定，而不是由内容和共同轴线决定。

## 决策

### 1. `PageChrome` 是页面表头的唯一来源

新增 `src/core/layout/page-chrome.ts`，由命令层在构建页面前计算一次，随 `RecipeContext` 传给配方，并由旧分支直接读取：

```ts
export interface PageChrome {
  /** 标题框，归一化。模板页来自模板占位，预设页来自安全区。 */
  title: NormalizedFrame;
  /** 标题下的强调短线。 */
  rule: NormalizedFrame;
  /** 内容区。 */
  content: NormalizedFrame;
  /** 内容区的上下边界，归一化。 */
  contentTop: number;
  contentBottom: number;
}
```

计算规则：

- `title` / `content` 来自命令层已经解析好的 `frame.title` / `frame.content`；模板页用模板占位，预设页用安全区，二者不各自再写一套坐标。
- 短线放在标题框下方一个固定呼吸位（`0.03` 页高，最大不超过内容顶边前 `0.02`），宽度取标题宽度的 20%，上限 0.12；标题框过矮时（模板页常见），短线跟随标题框，不压到内容。
- 内容顶边、底边来自内容区；所有页型共用。
- 配方不再定义 `TITLE / RULE / CONTENT` 常量；旧分支不再各自计算 `alignmentGrid.ruleY`。

### 2. 垂直构图改为“测量后成组”，不再等分或固定 Y

- `editorial-index`：条目用 `layoutFlow` 统一字号测量行高，行距有上下限；整组在内容区内垂直居中，竖向强调线只覆盖这一组，不再从内容顶边拉到内容底边。行数少时字号允许长大，不把 17pt 单行拉成 1.35in 行距。
- `data-story`：数值按测量高度定字号，标签紧贴数值下方（约 0.03 页高），数值 + 标签作为一个组在内容区内垂直居中；删除 `VALUES_Y = 0.42`、`LABELS_Y = 0.73` 这类固定坐标。
- `asymmetric-split`：右栏条目用 `layoutFlow` 从内容顶边向下成组，行距有上限；不再把内容区等分到条目数。
- 旧分支的卡片网格、指标卡、流程、对比：卡片高度由“内容测量高度 + 上下物理内边距”决定；接近填满内容区时顶对齐，明显短于内容区时在内容区内居中，但高度不再固定为 0.24/0.28 页高。

### 3. 字号允许在空页上长大

`fittedFontSize` 保持“只缩”的语义不变，新增一个带最大值的拟合入口：在 `[minimumPt, maximumPt]` 内先尝试 preferred，再向上/向下找最大可容纳字号。使用范围：

- 3–4 条短要点的编号页正文：preferred 可到 `bodyPt + 6`，上限 26；
- 稀疏卡片正文：preferred 18–20，上限 22；
- 指标数值：3 列 56–72pt，1–2 列 72–96pt；
- 单段正文收束页：preferred 20–24，短文本可居中。

标题与正文的目标比例不小于 2.0（display/title 对 body），避免 30/17 这种“两级只差一档”的层级。

### 4. 内边距使用物理单位，不使用页宽比例

卡片、面板、流程步骤的左右内边距改为英寸换算（默认 0.22–0.28in），不再使用 `0.03–0.045 × 页宽`。同一张卡片在 2 列和 3 列网格里得到相同的呼吸位，不会因为页面布局改变而被挤窄。

### 5. 确定性质量门增加“下半页空洞”

`validatePresentationVisualQuality` 增加 `underfilled-page`：

- 只检查正文不少于 20 字的页面（极短正文更像刻意留白的声明页，不按“没排满”处理）；
- 忽略整页背景图、页脚（y ≥ 0.9）和 cover/section 页；
- 取所有其余元素（文本、形状、卡片、图片）的绘制底边；
- 若底边 < 0.58，报告“正文只占页面上半部，下方连续空白超过三分之一”。

这条门是确定性的，不依赖视觉模型是否开启；它只报告，不阻断生成（沿用 ADR 0015），但会进入质量报告和修复授权范围。

## 边界

- 内容不可变：所有几何只读 `SlideContent`，不新增、不改写、不重排文字；`consumed` 继续作为丢字守卫。
- 模型仍然不输出坐标、字号和颜色值；`PageChrome` 由确定性引擎计算。
- 模板背景、Logo、装饰仍由现有前置逻辑绘制；本决策不改模板的母版/导出链路。
- 模板页接入配方仍不在本决策范围（见“未覆盖”）；本次只让旧分支的几何使用同一套测量规则。
- 不新增依赖；只使用现有 `estimateTextLines`、`layoutFlow`、`stripListPrefix` 和文档模型。

## 结果

- 同一册的标题轴、短线、内容顶边由同一对象决定；配方页与旧分支页不再各画一套表头。
- 稀疏页的字号和成组高度由内容测量决定，不再出现“页面很空、字很小、行距很大”。
- 卡片内边距与列数解耦，中文孤行和“大卡小字”减少。
- 空页从“只有视觉模型可能发现”变成“确定性门也能报告”，质量报告可以指向具体页。
- 旧文档、无 `designConcept` 的设计、模板路径的背景/装饰/导出行为保持不变。

## 未覆盖

- 模板路径接入配方已由 [ADR 0064](0064-template-recipes.md) 接续；本决策只负责统一骨架和测量式构图。
- 章节页、引文页、`process-rail`、`comparison` 配方仍走旧分支；它们的表头会走 `PageChrome`，但构图没有重写。
- 跨页“标题轴偏差”尚未做成确定性检查；本次先保证同一渲染路径内一致。
- 视觉评审的 `distinctivenessScore` / `changeRecipe` 仍是 ADR 0046 的 P2。

## 实施结果（2026-10-24）

- `PageChrome` 已接入命令层、五个配方和 `grid / metric / process / comparison / 单段正文` 旧分支。
- 7 页预设样张的标题轴、短线、内容顶边已统一；编号行由等分改为测量成组，指标标签紧贴数值，收束页居中放大。
- `underfilled-page` 已进入确定性质量门，模板页的下半页空洞可以被报告，但模板页仍不自动重排。
- 全量前端测试 1044 项通过；类型检查、Lint、生产构建通过。视觉回归因本机图表渲染与旧基线有 0.476% 差异而显式跳过，未更新基线。
