# 0075 设计方向提案、真实预览与选择记录

## 状态

已接受（2026-10-24）。实施见 [TASK-DESIGN-025](../development/tasks/0025-design-direction-and-taste-gates.md) 第 13 节。

## 背景

设计阶段只有一个可渲染的概念预设 `editorial`，`resolveDeckConcept` 会把其他意图降级。用户在生成前只能选主题色板，看不到两种不同骨架的封面与正文，方向错了只能整册重来。

“方向”不能只是一段提示词描述：模型说“纪实全幅”，渲染器仍画编辑式，用户选中的就是一个无法落地的承诺。

## 决策

### 1. 方向是设计态事实，不是内容

`DesignDirectionRecord` 记录最终展示的提案集合、用户所选、选择方式、内容 revision、内容指纹、模型与提示词版本、重新生成次数。它随 `apply-ai-designed-draft` 与设计一起写入，一个事务、一个撤销项，不进入内容哈希。

### 2. 两个方向，两个真实预览页

当前渲染器只有 `editorial` 与 `documentary` 两个概念预设，因此固定提出两个方向；第三个方向等第三个可渲染 preset，而不是让模型发明。

每个方向只设计 2 页（封面 + 一页代表性正文），预览页由**同一条命令路径**生成：

- 用已审核草稿建一个中性的基线文档，只为拿到页码与页序；
- 每个预览页建一个单页临时文档，`apply-ai-designed-draft` 传真实 `pageContext`（index / total / sectionLabel）；
- 主题、模板、字体从 `commandBase` 带入，和最终整册应用保持同一份参数；
- 真实文档不被修改，预览文档渲染后丢弃。

不新写渲染器，也不整册克隆：后者需要一次设计 20 页，成本与方向阶段上限冲突。

### 3. 内容指纹来自草稿，不来自文档哈希

应用草稿会生成新的内容块 ID，`documentContentFingerprint` 每次都会变。方向记录改用 `directionContentFingerprint(AiSlideDraft[])`：标题、正文、备注与块的语义内容，不含 ID。这样“同一份已审核内容”在多次应用之间保持稳定，过期判断才有意义。

### 4. 只有 preset 生成走方向门

上传模板已经决定版式与视觉语言，两个方向会预览同一套模板两次。方向门只在“无模板、按主题预设生成”时触发；模板模式沿用现有的单方向路径。未来若要给模板做方向，需要先定义“模板内的方向”而不是复用 preset。

### 5. 失败、跳过与重新生成

- 方向提案或任一预览失败：回退现有单方向路径，不写记录。
- 用户跳过：记录 `selectedBy: "fallback"`，选中推荐方向，下次同一内容 revision 不再强制询问。
- “换一组”最多 2 次；每次重新提案并重渲染预览。
- 取消任务会释放等待中的选择，不会把后台任务卡在已关闭的对话框后面。

### 6. 成本上限

一次方向门最多：1 次提案调用 + 2 个方向 × 2 页设计 + 4 页本地渲染。没有整册重跑预算。方向门关闭或失败时，行为退化为改造前的单方向生成。

## 后果

正面：

- 用户第一次能在花费整册设计成本之前，看到两种骨架的真实页面并做选择。
- 方向、预览页与最终稿共享同一条命令路径，不会出现“预览能画、最终画不出”。
- 选择记录可追溯，重新打开项目后仍能回答“这版是谁选的、基于哪版内容”。

代价与限制：

- 方向门增加一次模型调用与 2 页设计成本；模板模式暂无方向选择。
- 单页预览的模板版式轮换可能与最终整册不同；预设主题的标题轴已由测试锁定在 1% 页宽内。
- “换一组”可能得到同样的两个方向；当前没有跨项目外观去重（属于 P1 设计记忆）。
- 未做端到端 UI 截图验证；组件已通过类型检查与生产构建，交互需在 `npm run tauri dev` 中目视确认。

## 备选方案

- **生成两套完整 20 页再让用户选**：成本翻倍，且用户要在两个长文档里找差异，不采用。
- **只让模型描述两个方向，不渲染**：用户看不到骨架差异，选择无效，不采用。
- **让用户先选主题色板，再生成单方向**：保留现状，正是本决策要解决的问题。
- **把方向写进内容版本**：方向是设计态，进入内容版本会污染内容哈希与审核语义，不采用。
