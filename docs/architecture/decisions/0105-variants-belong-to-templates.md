# 0105 版式变体属于模板，不属于主题

## 状态

已接受（2026-10-26）。修订 [WP4 计划](../development/tasks/0026-visual-vocabulary.md) 中"主题包 = 令牌 + 命名版式变体"的表述。

## 背景

[视觉词汇 TRS](../../requirements/PPTD-Visual-Quality-TRS-v0.1.md) 的 FR-V2 把"版式变体"挂在主题包上，来源是 presenton 的模型——在那里"模板"同时是配色和版面。把这个结构照搬进 PPTD 会产生一个与本产品既有架构冲突的设计：

- **ADR 0087**：整册的骨架由**方向**（concept preset）决定，四个方向各自拥有自己的构图；
- **ADR 0094**：`paper` / `instrument` 方向拥有自己的页面配方，模型点名别的方向的配方会被拒绝；
- **主题**（`theme-presets.ts`）只有调色板、字体与字阶，从来不参与版面选择。

如果让主题再决定"这一页用哪个配方"，就会出现两个权威：用户因为喜欢青色而选了"青编"，页面结构却跟着变了。用户以为自己换的是皮肤，拿到的却是另一套版式——这正是 ADR 0087 明确反对的"让人以为在选版面，其实只是换色"的镜像错误。

另一个事实：**FR-V3 想要的能力已经部分存在**。`checkTemplateFit` 已经在测"有多少页真的落到了模板的版式"（`layoutCoverage` / `checkedSlides`），`planTemplateLayouts` 也在按意图挑版式。缺的不是新模型，而是把结果说出来。

## 决策

### 1. 主题不拥有版式

`ThemePreset` 保持现状：颜色、字体、字阶。不新增 `variants`，不让主题参与配方选择。

### 2. 版式变体是模板的属性

"这套设计能排哪几种页"由**导入的模板**回答，因为它真的有版式占位。派生方式：按模板版式的区域签名（有无标题/正文/图片/双栏）判断它能承接的页面类型；派生结果是信息，不是新的选择器。

### 3. 先补诊断，再谈选择

本轮只做一件确定的事：导出报告把"没落到模板版式的页"说出来。

- `ExportReport.templateFit` 增 `checkedSlides` / `layoutCoverage`（两者 `checkTemplateFit` 早已算出，只是没进报告）。
- `layoutCoverage < checkedSlides` 时写一条 warning：`N 页没有匹配的模板版式，已按自由排版导出`。
- 不新增错误码，不阻断导出（ADR 0015）。

选择层面的"模型只能在变体清单内选"仍留给 FR-V3 的下一步，且必须建立在**模板**上，而不是主题上。

## 后果

正面：

- 避免了一次会破坏"方向管结构、主题管皮肤"这条既有架构的实现。
- "这套模板排不出这一页"从静默行为变成报告里的一句话。
- 主题包的数据模型保持简单：四个概念预设已经承担了结构差异。

代价与限制：

- FR-V2 的"命名版式"没有实现，TRS 需要按本 ADR 修订（下一轮同步）。
- 警告只覆盖"没有落到版式"的页，不区分具体是哪种页面类型排不出来。
- 模板能承接哪些页面类型仍是隐式的（由区域签名推断），没有面向用户的清单。

## 验证

- `export-pptx.test.ts`：模板版式全覆盖时 `checkedSlides === layoutCoverage === 1` 且无警告；把版式绑定去掉、目标里放两个版式（没有单版式兜底）后，`layoutCoverage === 0` 且报告出现"没有匹配的模板版式"。
- 全量测试与构建通过。

## 备选方案

- **照搬 presenton：主题包声明版式**：结构冲突，且会让"换主题"变成"换版面"；不采用。
- **在主题包里只声明、不参与选择**：等于加一份没人读的数据，违反"没有消费点就不加字段"；不采用。
- **把模板变体也存进文档**：`layouts` 已经存了版式名与网格，再加一层变体清单是重复真源；不采用。
