# 0024：内容词表是共享资产，视觉素材由 AI 说意图、由引擎定位置

## 状态

已接受（2026-10-23）。

## 背景

第四波把评审、修复、整册节奏都做出来了，但"AI PPT 一眼假"这个原始问题还剩两个硬缺口。

**第一个缺口是标题。** 生成出来的标题大多是"现状分析""市场概述""未来展望"这类东西——它们是表格的列头，不是结论。逐页看还行，整册看下来三十页全是同一个模具。更麻烦的是，提示词里已经写了"不要用背景/概述/介绍/总结这些词"，检测端却没有对应的判定：提示词里明明禁止了，评审环节却查不出来。

于是出现了一个典型的两套规则漂移：**检测说某个标题没问题，提示却还在要求模型避免它**。词表、提示、检测各写各的，改了一处另外两处不知道，用户看到的评审结论和模型收到的指令对不上。

**第二个缺口是整册没有素材。** 翻遍仓库，没有任何图片来源。每一页都是"文字 + 矩形 + 文字 + 矩形"。这是"一眼假"最大的单一原因——真实演示里会有照片、示意图、图标、图表，它一页都没有。模板自带的 30 张媒体也救不了：排查下来全是背景纹理（3082×1731 全幅底图）和 logo（872×280），没有一张是内容配图。

## 决策

### 词表是共享资产，两端同源

1. 新增 `assets/content-lexicon.json`（version 1），是标题词表的**唯一事实来源**：栏目名 40 个、栏目后缀 9 个、疑问式开头 6 个、空泛结尾 10 个、连接词 11 个。
2. 前端 `src/core/content/title-quality.ts` 用 `import` 读它做检测；后端 `src-tauri/src/commands/ai/content_lexicon.rs` 用 `include_str!` 在编译期内嵌同一份文件写生成提示。运行时后端不依赖仓库路径。
3. 检测出的四类问题——栏目名、栏目名+后缀、疑问式开头、空泛结尾——全部来自词表，不在代码里硬编码。
4. Rust 侧提示里的每一个词都从词表取。`title_rules_prompt()` 的反面例子（栏目名拼标题、栏目名+后缀）由词表里的词现场拼出来，不另写一份示例。

### 标题问题只提示，不改写

5. 内容已经审核过，模型把标题写成模板化或句式雷同，属于**非阻塞警告**，进入审核界面（与 `duplicate-title` 同级），由人决定改不改。代码不静默重写已审核内容。
6. 句式指纹只记录**段数 + 连接词**，不记录内容。所以"现状与挑战"和"机遇与风险"被认成同一种句法骨架。单段标题不给指纹——没有可比结构。
7. 同一句式在整册出现 3 次以上才提示（`repeatedPatternThreshold: 3`）。

### 视觉素材：AI 说意图，引擎定位置

8. 设计合同新增语义字段 `visualAsset`：`enabled`（要不要配图）、`prompt`（配什么图，描述画面，不含文案）、`role`（`hero` / `side` / `band`）。**仍然不让 AI 输出坐标**——ADR 0003 的原则不变。
9. 新增 `src/core/commands/visual-asset.ts`：
   - `resolveVisualAsset()` 拒绝不合适的页面：有结构化内容块、要点超过 4 条、不是封面的页不给配 `hero` 图。AI 指定的 `role` 被采纳。
   - `planVisualAssetLayout()` 计算图和文字区的几何，**两者不重叠、共享一条边**。文字区随之收窄。
10. 图片按**填充裁剪**（`coverCrop`）而不是拉伸——等量切边，比例不变形。拉伸过的图一眼就假。
11. 封面页和章节页原本有硬编码的占位框，用 `clipToTextArea()` 收进新的文字区，纯 EMU 运算，不引入像素。
12. 新增 `src/core/rendering/image-fit.ts`（`coverCrop` / `visibleSourceRect`）和 `src/core/commands/visual-asset.ts` 两个模块，职责分开：前者只管几何，后者只管意图与契约。

### 外部依赖失败不影响主流程

13. 新增 `src-tauri/src/ai/minimax_image.rs`：`ImageProvider` 端口 + `ImageRequest` / `ImageResult` / `ImagePayload` / `ImageLimits`。120 秒超时，支持取消，只有 429 / 5xx / 529 / 传输抖动才重试。
14. 下载走受控通道：只允许 https、只允许官方域名、上限 20 MB、**不带 API Key**。外部返回的图片按不可信输入处理，PNG/JPEG 头嗅探尺寸与 MIME（不写死 png——真实返回很可能是 JPEG）。
15. 前端 `src/services/ai-visual-asset.ts`：`generateVisualAsset()` 失败**一律不抛**，返回 `undefined`。没有凭据、超时、限流、余额不足，都只是少一张图，文稿照常成立，导出照常进行。
16. **整册配图上限 4 张**，生成并发限制 2。避免变成相册，也避免一次演示烧掉大量额度。

## 结果

- 提示与检测同源：词表改一处，两端同时变。检测报"栏目名+后缀"，提示里也恰好禁止这个组合。
- 标题模板化、句式雷同进审核界面，不再靠用户自己看出来。
- 有素材的演示和没素材的演示一眼能分辨。
- 图片生成挂了不影响出稿。

## 未验证声明与风险

- **MiniMax 图像生成接口规格仅来自官方文档，未经真实 API 调用验证。** 规格（端点 `POST https://api.minimaxi.com/v1/image_generation`、`model` 为 `image-01` / `image-01-live`、`prompt` ≤1500 字符、`aspect_ratio` `16:9` = 1280×720、`width`/`height` ∈[512,2048] 且为 8 的倍数、`response_format` 默认 `url` 可选 `base64`、`n` ∈[1,9]、错误码 1002 限流 / 1004 鉴权 / 1008 余额 / 1026 敏感 / 2013 参数 / 2049 无效 Key）来自 `platform.minimaxi.com` 的文档页。
  - 本机没有 `MINIMAX_API_KEY` 环境变量，keyring 槽位（`ai-api-key/minimax`、旧槽 `minimax-api-key.com.pptd.desktop`）也未读取。**整条链路没有跑过一次真实请求。**
  - 厂商换 CDN 需要扩下载白名单（当前基于文档示例 `cdn.hailuoai.com`）。
  - 首次接入时应加一个手动冒烟脚本，用真实 key 验证请求体字段名和响应结构，再把该脚本固化成测试。
- 视觉素材层目前只服务于 AI 设计流程，手工新建页面的编辑路径没有配图入口。
- 配图内容不受审核关卡约束：图是 AI 生成的视觉素材，不进内容模型，也就不进内容审核。生成图的合规性目前靠提示词与人工复核，缺自动检查。
- 模板自带的 30 张媒体（背景纹理与 logo）没有被复用为内容配图，素材层完全依赖生图。
