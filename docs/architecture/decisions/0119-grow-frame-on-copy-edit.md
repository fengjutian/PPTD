# 0119 编辑文案后按需增高文本框（只增高，不动字号）

## 背景

生成阶段有重排（ADR 0116）：一页从设计里出来时，文字已经按渲染器的断行放好。但**编辑**是另一条路：`edit-text` / `replace-text-edits` 只写正文，页面的几何停在生成时的那一刻。

后果：用户把一段正文改长、或把标题替换成更长的句子之后，

- 画布把超出的行裁掉，只画一圈虚线警告边；
- 预览与文件按 `normAutofit` 缩字——用户看到自己的字被缩小了；
- 审计会把这一页报成"文本超出文本框容量"。

三个表面都在说"放不下"，却没有一个把框加高。用户要么手动点检查器里的「适配文本」（那会缩小字号，不是他要的），要么自己拖框。

## 决策

文案编辑命令在写完正文后，对**被编辑的那一个文本框**调用 `growFrameForText`（`core/layout/text-refit.ts`）：

- **只增高**：框高增到实测所需高度（+1% 余量），字号一个点都不改——生成阶段可以缩字，因为那页还没人读过；编辑阶段缩掉的是作者自己选的字号。
- **只动这一个元素**：不重排同页其它对象，不改任何其它几何。
- **只在有空间时**：沿用重排的 `growthLimitPt`——下方有对象或页面下边距挡住时就放弃增高，把溢出留给审计与画布警告边，而不是让文字叠到别的元素上。
- **只在能原地长高时**：垂直居中/置底的文本框增高会让内容跳动，因此不处理，交给审计。
- **模板页不处理**：`layoutId` 页面沿用上传模板的占位契约（与 ADR 0116 §3 同一条）。
- **命令域变成 `both`**：新文案装不下时，`commandDomain("edit-text")` 返回 `both`，于是设计版本一并递增（几何确实动了），内容版本仍只在正文真的变化时递增。装得下的编辑仍是纯内容编辑。

## 后果

- 编辑后的页面立刻是"能装下自己文案"的页面；不需要手动适配，也不会在下次导出时才发现。
- 一条内容命令因此可以改变几何。这是有意的边界放宽：改动只限于**被编辑的那个框**、只往一个方向、且不改变字号。ADR 0116 的重排仍是生成阶段的唯一入口，两者共用同一份测量与同一个"下方能长多高"的判断。
- 拥挤页面里改长文案仍然会溢出——现在这是**明确的**结果（审计 + 警告边），而不是被裁掉的一行。
- 增高后的框会成为撤销栈里同一条记录：正文与几何在同一个 patch 里，撤销一次两者一起还原。

## 验证

- `text-edit-frame.test.ts`：改长正文后框变高、字号不变、审计归零；改成更短的文案不动几何；下方有对象时框不长高，审计仍报 `text-overflow`。
- `text-refit.test.ts`：`growFrameForText` 在下方有阻挡、垂直居中、模板页三种情况下都不动几何。
- 全量测试与构建通过（含真实 PowerPoint 导出回归）。
