# 0077 本地设计记忆与设计指纹

## 状态

已接受（2026-10-24）。

## 背景

方向选择、主题预设与用户口味都只存在于当前会话。连续做三个科技类主题，可能三套都是深底加等权卡片；用户在方向选择时写下的“太素了”“想要更像杂志”，下一次生成不会再被参考。

把这些信息上传到云端可以跨设备，但正文、备注与图片不应该离开本机；设计记忆只需要“外观”和用户自己写下的判断，不需要内容。

## 决策

### 1. 只存两类数据

SQLite 表 `design_memory`：

```text
id, kind ('deck' | 'preference'), scope, payload_json, created_at
```

- `deck`：外观指纹——主题预设 ID、调色板（最多 8 个色值）、主/次字体、概念预设、页数。
- `preference`：用户原话（最多 200 字）与适用范围（最多 64 字）。

不保存标题、正文、备注、图片、模型响应或整份文档。payload 上限 8 KB，`kind`、`scope` 与对象形状在 Rust 端校验。

### 2. 写入时机

生成成功、文档已提交之后记录外观；方向记录里有 `userWords` 时同时记一条偏好。数据库失败只忽略，不影响已经完成的生成。关闭“保存本机设计记忆”后不再写入。

### 3. 读取用途只有两个

1. 方向提案时带最近 3 个外观指纹，提示模型避免与最近项目使用完全相同的“配色 + 字体 + 方向”组合。
2. 设置页显示数量，供用户判断是否需要清除。

设计记忆**不得**自动改变主题、自动应用方向或替代用户选择；它只影响提案的去重提示。

### 4. 本地、可关闭、可清除

- 默认开启；旧库缺字段时保持开启。
- 设置页提供开关、当前数量与“清除设计记忆”。
- 单条删除接口保留在服务层，供后续“记忆列表”使用。
- 表结构随 SQLite `user_version` 2 → 3 迁移；`CREATE TABLE IF NOT EXISTS` 保证旧库原地升级。

### 5. 上限与裁剪

`deck` 最多 50 条、`preference` 最多 100 条；写入后按 `created_at` 删除最旧记录。上限在 Rust 端执行，前端不能绕过。

## 后果

正面：

- “越用越懂你”有了最小实现：只记外观与用户原话，不碰内容。
- 方向提案可以主动避开最近的外观，减少连续项目同质化。
- 隐私边界清晰：仅本机 SQLite，无上传路径，可一键清除。

代价与限制：

- 冷启动没有记忆；前几个项目不会受益。
- 目前只把外观用于“避免重复”，还没有做“偏好 → 预设推断”的偏置。
- 偏好按原话保存，没有结构化标签；后续若要做检索，需要另加分类而不是改写原话。
- 浏览器预览模式没有数据库，记忆不生效，也不回退到 localStorage。

## 验证

- `src/services/design-memory.test.ts`：外观不含正文、最近外观可读、偏好去空白、汇总与清除。
- Rust `storage` 测试：保存、读取、清除；迁移测试覆盖 v1 → 当前版本。
- 全量测试、类型检查、ESLint、生产构建、`cargo fmt --check`、`cargo check` 通过。

## 备选方案

- **写进项目文件**：记忆是跨项目的，进项目会让每个 `.pptd` 携带无关历史；不采用。
- **上传云端**：隐私边界扩大，且当前没有账号体系；不采用。
- **用向量/语义检索偏好**：需要嵌入模型与额外依赖，当前原话数量很小，直接取最近 N 条即可。
- **自动套用最近主题**：会让用户失去选择权，也违反“设计记忆只影响提案”的边界。
