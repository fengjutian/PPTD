# 0086 模板符合度是测量结果，不是模型评分

## 状态

已接受（2026-10-25）。

## 背景

上传模板后，模板本身会出现在每一页渲染图里，但“看得见”不等于“可验收”。视觉模型看到的是像素，无法稳定回答：

- 标题左轴是否与模板占位一致；
- 正文是否越过模板内容区；
- 字号是否回到模板占位的大小；
- 封面/章节页是否本来就允许自由构图。

只靠模型评分，会把“页内好看但偏离模板”的页面放过去；只靠规则，又无法判断视觉平衡。两者必须分工。

## 决策

### 1. 先把模板编译成可测目标

`buildTemplateReviewTarget` 把 `analyze_pptx_template` 的分析结果编译为：

- 页面归一化 0–1 坐标的 `TemplateGrid`（标题区、内容区、左右/上下边距）；
- 每个版式的标题/正文字号；
- 主题色板与主题字体（既进入评审提示词，也做 warning 级确定性检查）；
- 轴语言（`left-grid` / `centered-grid`）；
- 置信度与最低符合度阈值；
- 容差：轴 0.01、纵向轴 0.005、边距 0.01、字号 1.5pt、颜色逐通道 12。

优先使用版式占位，而不是模板样例页：样例页常被手工调整，不代表模板网格。

### 2. 自由构图的页面不按内容轴扣分

名称匹配 `封面|标题幻灯片|扉页|章节|篇章|过渡|分隔|结束|谢谢|引用|引言|金句|cover|section|quote|closing|end` 的版式标记为 `freeComposition`。这些页面允许打破内容轴；检查直接跳过。

### 3. 检查能从文档观察的六类偏差

| 代码                      | 严重度  | 判断                           |
| ------------------------- | ------- | ------------------------------ |
| `template-title-axis`     | error   | 标题框 x/y 超出轴容差          |
| `template-content-bounds` | error   | 正文并集超出内容区超过边距容差 |
| `template-title-size`     | warning | 标题字号与模板占位差超过 1.5pt |
| `template-body-size`      | warning | 正文字号与模板占位差超过 1.5pt |
| `template-palette`        | warning | 标题/正文墨色不在模板色板内    |
| `template-font`           | warning | 标题/正文字体不属于模板字体    |
| `template-align`          | warning | 标题/正文段落对齐偏离模板      |

带结构化内容块（指标、表格、图表等）的页面跳过字号检查：这些元素的字号由组件决定，不是普通正文。

### 4. 分数与阈值是确定性的

```text
score = max(0, 100 - errors × 10 - warnings × 3)
passed = checked && errors === 0 && score >= minimumFit
```

没有可检查页面时 `checked=false`、`score=0`、`passed=false`，不能把“没检查”当成通过。

置信度：

- 至少 2 个可测版式，且至少 1 个同时有标题/正文占位 → `high`，阈值 90；
- 否则 `low`，阈值 85。

只有标题的封面也算“可测版式”，但它不能单独把置信度抬到 high。

### 5. 模型评分与确定性检查合并，但后者是权威

- 评审提示词携带同一份模板目标，要求偏离轴线的页面 alignmentScore 不高于 79，并报告 `misalignment`；
- 确定性检查的 issues 以 `template-mismatch` 进入同一份 `VisualReview`，并带原始 `code`；
- 确定性 `templateFitScore` 覆盖模型可能给出的值：模型不能用一个宽松的模板分绕过实测偏差；
- 修复计划可以把标题移回模板标题区，移动是设计命令，不改内容；
- `restyle` 增加 `fontFamily`：模板字体 warning 可以由确定性修复恢复模板主/次字体，命令层会按角色依次应用同一元素的多个修复动作。

### 6. 色板与字体是提示级检查

模板色板（主题色、占位符墨色、默认底色）和主题字体进入目标。`checkTemplateFit` 还会检查：

- 标题和正文墨色是否属于模板色板，中性色始终允许，逐通道容差 12；
- 标题/正文字体族是否属于模板主字体或次字体，名称做去引号、去空白、小写归一化，并识别常见中英文别名（微软雅黑/Microsoft YaHei、宋体/SimSun、思源黑体/Source Han Sans 等）；
- 标题/正文段落对齐是否与模板占位符的 `pPr@algn` 一致（模板未声明时跳过）。

这些检查只产生 `warning`（`template-palette` / `template-font` / `template-align`），不是硬错误：模板色板经常被设计系统扩展，字体别名和对齐继承也很常见。它们会降低 `templateFitScore`，但不会单独把页面判为不可交付。模板目标同时保存占位符墨色和对齐；确定性修复会用 `restyle` 把标题/正文的颜色、主/次字体和段落对齐恢复到模板值。

### 7. 评审输入、达标判断与报告共用同一份目标

1. 逐页评审、整册评审和修复计划都携带同一份 `TemplateReviewTarget`；模型只给评分、问题和修复意图，不写最终坐标。
2. 发给模型的目标只保留当前文档实际引用的版式（最多 12 个），确定性检查仍使用完整目标，提示词体积不会随模板版式数量失控。
3. `runDesignQualityStage` 在渲染评审的同一份文档快照上运行 `checkTemplateFit`，把确定性 issues 并入 `VisualReview`，并用实测 `templateFitScore` 覆盖模型可能给出的分。
4. `visualPassed` 要求模板检查已执行且通过；模板不可检查时记为 `false`，不能把“没检查”当成通过。
5. 确定性检查不依赖模型，因此视觉评审关闭或失败时仍然运行并进入报告；没有模型结论时报告只展示模板符合度。
6. 报告单独列出模板名、得分/阈值、偏差数量、版式覆盖和逐条偏差，不与“视觉评审建议”合并成一个成功状态；导出报告也会带上模板符合度的摘要。
7. 模板分析抽屉展示编译后的验收目标（标题轴、内容区、字号、字体、版式数量、置信度/阈值），用户在选择模板时就能看到系统将以什么为基准验收。

### 8. 模板目标随项目保存

`TemplateReviewTarget` 进入文档设计态（`PresentationDocument.templateStyle`，Schema 22），不进入内容哈希，也不改变内容 revision。生成时写入，重新打开项目后手动复检直接复用；预设模式会清掉旧目标。目标保存模板文件的 SHA-256，来源可追溯；手动复检拿到新的模板分析时，通过 `set-template-style` 设计命令把新目标写回项目。内容版本的设计快照也保存它，选择“同时恢复版式”时会一起恢复。`ReviewTrace` 同时记录 `templateFitScore`、模板名、模板哈希和分项偏差数量，历史记录里能看到当次模板符合度与来源。质检报告提供“重新编译目标”和“清除目标”两个操作：前者用当前模板分析重建并写回契约，后者通过 `set-template-style` 删除契约。手动复检、视觉评审阶段和导出报告都会核对页面尺寸、主题名和版式名：目标与当前文档不一致时视为过期，不用旧轴评审新稿。

## 后果

正面：

- 模板符合度可测、可复现，不依赖模型当天的心情。
- 封面/章节页不会被内容轴误伤。
- 报告能指出具体页、具体偏差和修复建议。
- 与评审循环共用同一份目标，不会出现“提示词说 90、代码说 85”。

代价与限制：

- 只覆盖标题轴、内容区、字号、标题墨色和字体的提示级匹配；装饰几何、图片内文字、视觉平衡仍归视觉评审。
- 需要模板分析结果里有标题/正文占位；没有占位时无法建立目标，报告为未检查。
- 版式是否自由构图由名称和几何共同判断；改名或特殊构图仍可能误判。
- 色板和字体是 warning，不是硬门槛；阈值 90/85 是当前经验值，需要真实模板校准。

## 备选方案

- **只让模型打分**：不可复现，也无法给出精确修复坐标。
- **只做规则检查**：无法判断视觉平衡与模板气质。
- **把模板截图直接当背景**：会丢掉可编辑对象，不符合导出目标。
- **色板强制匹配**：模板色板常被设计系统扩展，强制会大量误报；当前只做 warning 级检查，不单独判失败。
