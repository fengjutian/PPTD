# 0097：封面标题拆成眉题与主标题，编辑回写只改自己那一段

## 状态

已接受（2026-10-25）。

## 背景

[ADR 0096](0096-title-length-budget.md) 把标题预算写进了内容提示，但已审核的长标题仍会出现在封面上。真实稿件里最常见的形态是"主题：结论"：

> Alphabet 2023 年报：广告基本盘与 AI 第二曲线同时加速

整句当标题排，只有两种结果：字号压到一行塞下（标题变成一条横幅），或者折成三行（最后一行只剩一个"速"）。两种都不像封面，而真正的问题是**这一句其实说了两件事**——前半句是这套稿子叫什么，后半句才是封面要喊出来的判断。

## 决策

1. **按全角冒号拆成眉题与主标题。** `cover-statement` 在"：`"`的两侧各取一段：前段 ≤16 字时作为眉题（眉题行高固定、字号取 caption+4），后段作为主标题（沿用 display 字号）；没有冒号、前段太短或后段为空时保持原来的整句标题。
2. **一个标题，两个视图。** 主标题仍是 `contentRef: "title"` 的文本元素，但带 `contentRange: { start, end }`（UTF-16，和 `String.slice` 同单位）。眉题是 `decorative`：它是排版的产物，不参与内容编辑。
3. **编辑回写只改自己那一段。** `applyTextEdit` 遇到 `contentRange` 时把新文本拼回原字段的那个区间（`before + text + after`），并顺延自己的区间；不带区间的标题仍整体覆写。这样"在封面上改主标题"不会把前半句一起删掉——这是拆分最容易造成的静默内容丢失。
4. **绑定判定尊重区间。** 页面收尾的"文本回连内容"流程按整串比对标题，拆分后的主标题永远比不中，会被降级成 `decorative` 并从内容上脱落。该流程现在跳过带 `contentRange` 的元素。
5. **主标题加"孤儿保护"。** 拟合只保证塞得下，不保证断得好看：两行标题的最后一行只剩一个字，是真实出现过的观感事故。`fittedFontSizeWithoutOrphan` 在拟合后再逐磅收缩，直到末行至少 3 个字（封面与图文页封面生效，内容页不收缩）。
6. **持久化与复制。** `contentRange` 进入文档 schema；元素复制深拷贝该字段，避免两个视图共享同一个区间对象。

## 结果

- 同一句标题，封面从"一堵字"变成"眉题 + 一句主标题 + 细线 + 副标题"，主标题可以用回 display 字号。
- 内容不被改写：拆分只发生在渲染层，标题文本仍是审核过的那一句；编辑主标题时回写的是它的区间。
- 无冒号的标题、以及旧的文档（元素上没有 `contentRange`）走原路径，行为不变。

## 未覆盖

- 眉题固定取冒号前那段，不判断语义（它不是"报告/第 N 章"这类真正的栏目名）。要更准，需要内容阶段产出显式的 kicker 字段。
- 拆分只做一次（第一个全角冒号）；"A：B：C" 的 C 会整体成为主标题。
- 主标题被编辑成极短文本时，`contentRange` 会变成零长度区间；下一次整册重排会按新的标题重新拆分。
- 图文页（`image-led`）封面只加了孤儿保护，没有拆分眉题：那一版的文字栏更窄，拆分收益小、挤压风险高。
