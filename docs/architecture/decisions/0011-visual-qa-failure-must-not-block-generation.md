# 0011：视觉质检失败不得阻断 PPT 生成

## 状态

已采纳（2026-10-22）。

## 背景

“选择 PPT 模板 → 生成 PPT”这一步的最后一公里曾经把整份成果一起吞掉：视觉评审、像素对比度检查和确定性质量门任一环节抛出异常，`generateFromDraft` 就会跳到外层 `catch`，文档不会被应用，用户等了几分钟的 20 页文稿最后只得到一条错误提示。

现场表现尤其有欺骗性：视觉评审那一步的进度条停在 96%「视觉模型正在检查第 1 轮」不动（降级分支没有更新进度），随后整段生成以“生成失败，请重试”收场。用户看到的是一个卡住的进度条和一句报错，而不是“评审这一步没跑通，但 PPT 其实已经生成好了”。

代价还不止于此。视觉评审失败的原因（超时、鉴权、厂商返回不合法 JSON）被 `AI_VISION_REVIEW_RETRY_EXHAUSTED` 这类常量吞掉，用户无法判断是网络问题还是模型不支持带图请求；前端端口对超时也照常重试一次，于是“一次评审”变成两轮等待，进度条却毫无变化。

## 决策

1. **质检阶段只做判断和修复，不决定要不要交付。** 视觉评审、像素对比度检查、质量门统一收进 `runDesignQualityStage`，它们只返回问题清单，不抛异常。
2. **视觉评审不可用时降级，不阻断。** 模型报错、超时、返回不合法 JSON、厂商不支持带图请求，一律记为降级并继续用确定性布局校验完成生成。降级原因必须写进阶段说明并展示给用户，不得用常量掩盖真实原因。
3. **超时和 4xx 不重试。** 重试一次不会让超时更快、也不会让不合法的请求变合法，只会多等一轮。前端视觉评审端口与 Rust 文本请求遵循同一条规则。
4. **底图渲染失败只影响那一页。** 单页底图解码失败时，评审图缺这张底图继续评，对比度检查跳过该页并记录，不允许它中断整段质检。
5. **质量门未过时文档照常产出。** 问题按页和类型完整列出（越界、重叠、对比度、溢出、双栏过空），文档仍然进入项目并可继续编辑；界面不自动跳进编辑器，而是提示问题所在，让用户决定是调整还是直接导出。质量门仍然是门：它拦住的是“无声地把坏稿当成成品”，不是“把稿子扔掉”。
6. **取消必须一路向上传播。** 取消不是失败，不能被降级逻辑吞掉，否则用户点了“取消生成”应用还会继续跑完并覆盖文档。
7. **失败原因可诊断。** 厂商在 4xx/5xx 时通常会说明原因（MiniMax 返回 `base_resp.status_code` / `status_msg`），后端只取这部分错误码和提示回传，不回传响应正文，避免把用户正文带进界面和日志。

## 影响

- 视觉评审或质检任一环节失败，用户仍然拿得到 PPT，并能知道缺了什么检查。
- 进度条不再停在 96%：降级会立刻把阶段说明改成“视觉评审不可用，继续用确定性校验”。
- 质量门的语义从“拦截交付”调整为“拦截自动进编辑器并列出问题”。这改变了 0003 的降级行为，0003 的降级条款以本 ADR 为准。
- 视觉评审仍然可能因为厂商能力、时间预算而不可用；此时系统报告的是“结构与确定性布局校验”，不会宣称执行了视觉评审。
- 厂商错误原因会出现在界面提示里。提示只包含厂商自己的错误码和一句话说明，不包含请求内容。
