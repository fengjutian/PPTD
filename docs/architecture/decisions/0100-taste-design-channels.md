# 0100 体检区分庸俗装饰与设计装置

## 状态

已接受（2026-10-25）。

## 背景

`taste-lint` 的定位是“这一页像不像模板随手塞了字”。它此前用两条硬规则实现这个判断：

- 每页字体族不超过 2，包括标题；
- 标题里只要有一个词被单独换色就报 `DECORATION_ACCENT_WORD`。

这两条在拦模板味时是有效的，但它们同时拦掉了两种真实设计手段：

- **display 字体**：标题用衬线、正文用无衬线是最常见的编辑式搭配，但它天然是第三种字体族；
- **一处强调**：标题里把一个关键词换成强调色，是一页唯一的重点，而不是逐词上色。

结果配方即使有了更丰富的视觉词汇，也会被自己的体检拦住，或者被迫退化成“全篇一个色号”。

## 决策

### 1. 字体按“是否只出现在 display 尺寸”分类

- `displayFamilies`：只用于标题尺寸（≥ 标题字号 × 0.9）的字族；
- `textFamilies`：其余字族（正文、图注、标签）。

判定改为：`textFamilies ≤ maxFontFamilies`（默认 2）且 `displayFamilies ≤ 1`。一个也用于正文的字族不会因为标题也用它而被算作 display 字族。

于是“标题衬线 + 正文黑体”通过，“正文两种 + 标题一种”通过（旧规则会判 3 种），而“三种正文字体”仍然报错。

### 2. 强调词改为计数，不再是布尔

`DECORATION_ACCENT_WORD` 从“有没有”改为“有几处”，`maxAccentRuns` 默认 1。相邻同色的 run 合并为一处（加粗加色会拆成两个 run，不应算两次）。

一处强调是设计，两处以上是逐词装饰——后者才是这条规则要拦的东西。

### 3. 保留其余装饰规则

kicker、装饰性编号、emoji 仍然一律拦截。它们没有承载信息，也不构成层级。

## 后果

正面：

- 体检不再否决“标题用 display 字体 + 正文一种”的正常搭配。
- 强调从“绝对禁止”变成“有额度”，配方和模板都能表达一页的重点。
- 两条规则都变成可配置阈值，评审口径可校准。

代价与限制：

- display 字族通道目前没有内置预设使用：`DocumentTheme.displayFont` 是可选的，未设置时回退到 `majorFont`，既有主题行为不变。要真正启用需要模板或新预设在主题里声明；
- 强调额度的判定只看标题内的彩色 run，正文里的强调词不计数（正文本来就不该有强调色）；
- 体检结论仍是建议性质，不阻断生成或导出（ADR 0015）。

## 验证

- `taste-lint.test.ts`：标题 display 字体 + 两种正文字体不报错；三种正文字体仍报错；一处强调不报错；两处强调报错且 `metrics.runs = 2`。
- `design-preview.test.ts`：内置十页样例仍然零发现，说明放宽没有引入新的误报。
- `design-tokens.test.ts`：`displayFont` 未设置时等于 `majorFont`，设置后只影响 display 层。

## 备选方案

- **取消字体数量上限**：模板味的典型症状就是三种字体混排；不采用。
- **继续禁止单处强调**：与“一页一个重点”的编辑原则冲突；不采用。
- **按强调面积设阈值**（例如不超过标题的 40%）：更细，但面积规则会把“短标题整句强调”判错，且难解释；当前用“处数”更稳。
