# 0102 元素效果的 OOXML 落点：探针结论

## 状态

已接受（2026-10-25）。WP2 的准入结论，决定 FR-V4 的实现范围与边界。

## 背景

[FR-V4](../../requirements/PPTD-Visual-Quality-TRS-v0.1.md) 要求阴影、圆角、图片形状裁剪、色调、亮度/饱和度全部以原生 OOXML 表达，并且真实可编辑。其中"图片形状裁剪"要把 `p:pic` 改写成用图片填充的 `p:sp`，是本次唯一有结构风险的操作；如果它不成立，整条 WP2 的排期与降级策略都要改。

探针见 [`tools/design-preview/effects-probe.test.ts`](../../../tools/design-preview/effects-probe.test.ts)：四页，各答一个问题，产物写 `.tmp/probe-effects.pptx`。

## 探针结果

| 效果         | OOXML 落点                                              | PowerPoint                                   | LibreOffice                 | 结论                               |
| ------------ | ------------------------------------------------------- | -------------------------------------------- | --------------------------- | ---------------------------------- |
| 阴影         | `a:effectLst/a:outerShdw`（由 PptxGenJS `shadow` 生成） | 三档可辨（card / raised / emphasis）         | 解析成功                    | 直接实现，无需后处理               |
| 圆角         | `a:prstGeom prst="roundRect"` + `adj`（`rectRadius`）   | 0.04 / 0.12 / 0.28 三档可辨                  | 解析成功                    | 直接实现                           |
| 图片色调     | `a:blip` 子元素 `a:duotone`                             | 双色映射生效，图片仍是图片                   | 解析成功，像素未比对        | 后处理实现                         |
| 亮度         | `a:blip` 子元素 `a:lum bright="…"`                      | +30% 明显变亮                                | 同上                        | 后处理实现                         |
| 图片形状裁剪 | `p:pic` → `p:sp`（`a:prstGeom` + `a:blipFill`）         | 椭圆与圆角矩形裁剪干净，仍是可换图的图片填充 | 解析成功（4 页转 PDF 正常） | 后处理实现，**必须带 `a:srcRect`** |

证据等级：PowerPoint 逐页导出 PNG 目视（`.tmp/probe-effects/`）；LibreOffice 只验证了"能解析并转出 4 页 PDF"，像素级一致性未验证，按需求 C-7 记为"未验证"，不写成"支持"。

### 落地后补记（同一 ADR）

阴影已进生产（`ShapeShadowToken` + Schema 23，见 §"落地"）。实现时发现一处探针没暴露的细节：**PptxGenJS 的 `ShadowProps` 字段是 `offset`，不是 `distance`**。探针里写的 `distance` 被库静默忽略，所以当时三档之间的差异实际只来自 blur 与 opacity，偏移量并没有被验证。生产实现改用 `offset`，并用导出夹具断言 `<a:outerShdw` 真实存在（`export-pptx.test.ts`），不再依赖目视。

## 探针发现的三个坑

### 1. `a:stretch` 不等于裁剪

只写 `blipFill → a:stretch` 时，图片被拉伸到形状边界：320×180 的源图放进 1:1 框，条纹被纵向拉长。椭圆（带 `a:srcRect`）与圆角矩形（不带）在同一页上的条纹角度明显不同。

**结论**：形状裁剪必须把现有的 cover 裁剪结果写成 `a:srcRect`（`l/t/r/b`，单位 1/1000%）：

```xml
<a:blipFill>
  <a:blip r:embed="rId2"/>
  <a:srcRect l="21875" t="0" r="21875" b="0"/>
  <a:stretch><a:fillRect/></a:stretch>
</a:blipFill>
```

已有 `coverCrop()` 与 `image-crop-xml.ts` 的取整逻辑可以直接复用，不新增裁剪实现。

### 2. PptxGenJS 的 `a:blip` 不是自闭合标签

它写出 `<a:blip r:embed="rId1"></a:blip>`。用 `/<a:blip([^>]*)\/>/` 匹配会一个都命中不了，探针第一版就是这样静默失败的（断言写成检查文件名，才发现没打上补丁）。后处理必须同时接受自闭合与成对两种形态，并断言"改了多少处"，不能只断言"没报错"。

### 3. `p:pic` 改写会丢三样东西

探针里只搬了 `r:embed`、`a:off/x`、`a:ext`、`id`、`name`。生产实现必须额外保留：

| 丢失项                             | 后果                              | 处理                           |
| ---------------------------------- | --------------------------------- | ------------------------------ |
| `p:cNvPr@descr`（替代文本）        | 可访问性丢失，且需求 C-9 要求保留 | 写到新 `p:cNvPr` 的 `descr`    |
| `a:xfrm@rot` / `@flipH` / `@flipV` | 旋转或翻转的图片会回正            | 原样搬进新 `a:xfrm`            |
| 图片的裁剪 `a:srcRect`             | 已裁剪图片在改形状后回到全图      | 与形状裁剪合并为一次 `srcRect` |

另外：替换是原地进行的，所以 z 顺序天然保留；组合内的图片只替换子元素，组合变换不受影响。

## 决策

1. **阴影与圆角直接用 PptxGenJS 的参数**，不写后处理：少一条 XML 路径，就少一处和库版本赛跑的地方。
2. **色调、亮度、形状裁剪走既有 OOXML 后处理管线**（与 `shape-gradient-xml.ts`、`image-crop-xml.ts` 同层），每次改写都返回"改写处数"，为 0 视为未生效并进导出报告。
3. **形状裁剪必须带 `srcRect`**；算不出来（源图尺寸未知）时拒绝该效果并记 `EFFECT_UNSUPPORTED`，不退化成拉伸。
4. **不栅格化**：探针已证明五类效果都能留在原生对象上，没有降级为整页图的理由。
5. 效果参数用令牌档位（阴影三档、圆角三档、色调两组色 + 强度、亮度 ±40% 夹取），配方不写任意数值。

## 后果

正面：

- WP2 的五项能力全部可做，无需缩减范围，也无需在"好看"和"可编辑"之间取舍。
- 形状裁剪的失败模式（拉伸、丢替代文本、丢旋转）在探针阶段就被发现，而不是在用户文件里。

代价与限制：

- 后处理要维护两处正则：`a:blip` 的两种形态、`p:pic` 的改写；每次升级 PptxGenJS 都要重跑探针。
- LibreOffice 只验证到"能解析"，像素一致性要靠后续视觉回归补齐。
- 组合内的图片形状裁剪没有单独验证（只验证了顶层图片），实现时要补一页组合夹具。

## 验证

- `effects-probe.test.ts`：断言产物里 `prst="ellipse"`、`prst="roundRect"`、`<a:duotone>` 真实存在（断言包内 XML，不断言内存）。
- PowerPoint：四页导出 PNG 目视，阴影/圆角/色调/裁剪均符合预期，对象仍为图片或形状。
- LibreOffice：`soffice --convert-to pdf` 成功，4 页。

## 备选方案

- **整页栅格化换效果**：视觉上最快，但破坏"原生可编辑"这一产品前提；不采用。
- **只支持圆角与阴影，放弃形状裁剪**：省掉唯一的风险点，但图片页仍只有矩形，FR-V4 的一半能力没了；探针成立后没有必要降级。
- **用 `a:srcRect` 模拟圆形**：只能裁矩形区域，做不出椭圆；不成立。
