# 0034：多选是选择数组，批量操作是单条领域命令

## 状态

已接受（2026-10-22）。

## 背景

此前编辑器一次只能选一个对象。对齐、分布、批量删除这些操作要么没法做，要么只能靠"逐个循环调用单条命令"硬凑出来。

后者会直接违反一条核心约束：**一次用户意图 = 一个领域事务 = 一个撤销项**。用户框选了三个对象点了删除，如果实现成循环调用 `delete-element` 三次，撤销栈里就有三个条目——用户得按三次撤销才回到原样，而且中途再点别的操作，三个条目就被打散了。这是能感知的坏体验，不是实现细节。

多选还牵涉一个更细的问题：选中状态算不算文档的一部分？如果算，每次点选都改文档，revision 疯涨，撤销栈被选择操作污染，导出时还得想办法把选中框剔出去。

## 决策

### 选中状态是数组，不进文档

1. `src/store/editor-store.ts`：`selectedElementId: ElementId | null` 改为 `selectedElementIds: ElementId[]`。只选一个时数组里只有一个元素，不额外保留一条"单选"路径。
2. 选中状态**不进文档模型**：不改变 revision，不进撤销栈，不导出。
3. 新增 `toggleElement`（增减一个）与 `selectElements`（直接设定一组，框选用），`selectElement` 保留为"只选这一个"。
4. 新增 `pruneSelection()`：删除、重排、换页会让旧选择失效，选择必须跟着文档走，否则属性面板会显示一个已经不存在的对象。

### 批量操作是单条领域命令

5. `src/core/commands/commands.ts` 新增四条命令：
   - `align-elements`：把一组对象按同一方向对齐；
   - `distribute-elements`：把一组对象均匀分布；
   - `move-elements`：整组一起移动；
   - `delete-elements`：整组一起删除。
6. 这四条在 `applyCommand` 里**插在单元素解析之前**处理：它们一次动一组对象，没有单一的 `elementId`。
7. `delete-elements` 的域分类要看内容：如果删掉的里面有标题或正文占位符，它连带清空了已审核内容，属于 `content` 变更；否则是 `design`。不能一律当成 design。

### 几何单独成层

8. 新增 `src/core/commands/arrange.ts`：`unionFrame` / `alignFrames` / `distributeFrames` / `framesIntersect` / `framesInSelection`。这些函数只算位置、不改文档，命令层拿到结果再写回元素。这样对齐与分布的规则可以脱离界面单独测，画布、属性面板和导出用的是同一套几何。

### 对齐的基准是这一组，不是页面

9. 多选时"左对齐"对齐的是**这一组的外接框左边**，不是页面左边。把三个对象的左边推齐，和把它们推齐到页面，是两件事。前者才是"对齐"的含义。
10. 分布是**两端固定、中间等距**，不是"平均间隔"。平均间隔会让整组散开，两端固定才是分布的意思。少于三个对象时不分布——两个对象没有"中间"可以填。

### 框选用相交，不用完全包含

11. `framesIntersect` 判定只要有一块重叠就算被框住。比"完全包含"宽松，也更符合拖框选对象的直觉：擦过边角的对象通常也算选中。
12. 框选与点击用 `CLICK_THRESHOLD_PX = 3` 区分：拖动距离小于 3px 视为"点了一下空白"，清空选择。

### 多选拖动按整组外接框吸附

13. 拖动多选中的任意一个成员，整组一起走。吸附算的是**整组外接框**的位置：整组一起贴到网格线上，而不是某一个成员贴上去而其他留在原地。
14. 拖拽过程状态放在 `src/store/group-drag-store.ts`：握着鼠标的那个对象自己画预览，其余成员用整组位移跟随。拖完就清空，不进文档。

### 多选面板不硬凑公共属性

15. `src/features/editor/MultiSelectionPanel.tsx`：多选时只显示这一组**确定成立**的信息——已选几个、整组外接框的 X/Y/宽/高、对齐、分布、批量删除。各对象的属性大多各不相同，硬凑一个公共值反而误导人。
16. 单选时仍显示该对象的全部属性，"当前对象"取选中数组的最后一个。

## 结果

真实浏览器验证（headless Chrome + CDP）：

| 场景 | 结果 |
|---|---|
| 框选覆盖多个对象 | 选中 3 个，属性面板显示"已选 3 个"与整组范围 |
| 整组拖动 | 三个对象同时平移同一位移 |
| 整组拖动后撤销一次 | 全部回位（**一次**撤销，不是三次） |
| 左对齐 | 三个对象左边推齐到外接框左边 |
| 对齐的 revision | 设计 +1，内容 +0 |
| 撤销后 revision | 回到原值，对象精确回位 |

## 未覆盖与风险

- 框选只处理**当前页**，没有跨页多选。
- 对齐只支持左/中/右、上/中/下六种，没有"两端对齐中间"（需要三对象以上才成立的排列）。
- 分布只做等距，不做"按间距数值"或"按百分比"。
- 还没有分组 / 取消分组——那需要跨页结构支持，属于另一层模型改动。
- 多选状态下属性面板不显示字体、颜色等公共值：两个对象的字号不同时没有正确的公共语义，目前是整体隐藏而不是显示"混合值"。
