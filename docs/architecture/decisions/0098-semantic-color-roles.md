# 0098 语义色阶：从四个墨色扩到十一个角色

## 状态

已接受（2026-10-25）。

## 背景

主题一直只有七个颜色槽：`primary`、`accent`、`accent2`、`accent3`、`muted`、`surface`、`surfaceAlt`。页面能用的墨只有标题、正文、强调和底，除此之外只有细线。结果是每一页都只能用 0.75pt 的横线分隔内容：

- 卡片没有“浮起来”的填充，只能画一个和背景同色的框再加描边；
- 分区没有底色，只能靠留白；
- 次要信息（图注、来源行、副标题）只能继续用正文色，层级靠字号硬撑。

十七套预设共享同一套槽位与同一个字阶，因此“换主题”实际上只换了色相。这是“生成结果不够美观”的结构性原因之一，而不是调色板不够多。

## 决策

### 1. 新增四个语义角色，不是十二级色阶

`SemanticColors`：

| 角色            | 用途                                     |
| --------------- | ---------------------------------------- |
| `surfaceRaised` | 浮在页面之上的面：卡片、压字题板、图注条 |
| `border`        | 细线、卡片描边、分栏线                   |
| `textMuted`     | 次要文字：图注、来源、副标题             |
| `accentSubtle`  | 强调色的低强度填充，正文墨仍可读         |

角色按用途命名，不按亮度编号。Radix 的 1–12 阶适合 UI 状态（hover、active、disabled），演示文稿没有这些状态；把十二级搬进来只会得到一堆没人知道该用哪一级的槽位。

### 2. 派生一次，写进主题

`deriveSemanticColors({ surface, ink, accent })` 负责计算：

- 深色页面的 `surfaceRaised` 向白走 10%，浅色页面向墨走 5%——固定单向混合会让其中一种页面的卡片消失；
- `border` 比 `surfaceRaised` 更强，保证描边卡片落在浮动面上仍然可见；
- `textMuted` 的混合比例由对比度决定而非固定百分比：从中间调墨向白页混 38% 只有 3.9:1，图注就读不清了，所以按 4.5:1 逐档回退；
- `accentSubtle` 在浅页面混 12%、深页面混 22%。

内置预设调用一次并把结果写进 `DocumentTheme.colors`，因此页面构建、主题选择器和将来的导出读的是同一组值。模板页没有预设可问，就按该页真实的底色与墨色现场派生。

### 3. 页面构建优先用预设值

`design-page-builder` 取 `paletteOf(slot) ?? derived[slot]`：有预设时用设计系统写死的值，没有预设（导入模板）时用现场派生。两者是同一个函数的输出，不会漂移。

### 4. 不新增 schema 迁移

`DocumentTheme.colors` 是 `{ name, value }[]` 的开放数组（上限 64），新增槽位是纯增量；旧文档缺少这四个槽位时按派生值补，不需要迁移和固定样例。

## 后果

正面：

- 配方可以画“浮起的卡片/题板/底色分区”，而不只是画线。
- 次要文字有了独立墨色，字号不用再被压到 9pt 来制造层级。
- 派生逻辑只有一处，深色与浅色页面用同一套规则。

代价与限制：

- 只有四个角色，没有 hover/pressed/disabled 这类交互状态（演示文稿不需要）。
- `accentSubtle` 始终是低强度填充，不能当作第二强调色使用；需要第二强调色仍用 `accent2`。
- 导入模板若只提供 `dk1/lt1/accent1` 这类 OOXML 槽名，派生使用页面解析出的墨色，不一定等于模板作者的意图。

## 验证

- `theme-presets.test.ts`：每套预设都写入四个角色，且 `surfaceRaised` 不等于 `surface`，槽名不重复。
- `design-tokens.test.ts`：深色页面 `surfaceRaised` 更亮、浅色页面更暗；`border` 比 `surfaceRaised` 更远离底色；`textMuted` 对白底 ≥ 4.5:1；`accentSubtle` 对白底 < 1.3:1（确实是低强度）。
- `recipes.test.ts`：`full-bleed-image` 的题板填充等于派生的 `surfaceRaised`；`side-image-text` 的标题色带等于派生的 `accentSubtle`。

## 备选方案

- **照搬 Radix 12 阶**：演示页面没有交互状态，多数台阶没有消费点；不采用。
- **让 AI 选色阶数字**：等于让模型写颜色值，破坏“代码保证对比度”的边界；不采用。
- **只在配方里硬编码浅灰/深灰**：深色主题和深色模板页会得到看不见的卡片；不采用。
