# 0032 · 配图意图进内容审核

## 背景

配图是"AI 生成 PPT 效果不好"里最直观的一块短板：一份全是文字和矩形的演示，
看上去就像一份排版过的 Word。但配图这条链路有一个时序问题。

原来的流程是：

```
内容生成 → 用户审核内容 → 设计阶段（此时才决定配什么图、生成图片）→ 编辑器
```

配图意图在设计阶段才产生，也就是说**用户审核文字的时候，看不到这一页会配什么图**。
等图生成完、钱花完，用户才发现第 5 页的图不合适——那时候能改的只有编辑器里的
几何位置，画面描述已经定死了。

审核阶段恰恰是最该看图的地方：那是唯一还没花钱、也最容易改的时机。

## 决策

### 1. 配图意图前移到内容阶段

内容生成（一次性草稿与分批正文）就产出每页的配图意图，写进 `plan.visualAsset`：

- `enabled`：这一页配不配图。
- `prompt`：画面描述。
- `role`：图在页面上的角色（主视觉 / 侧栏图 / 通栏图）。

后端提示词新增【配图意图】一段，规则来自共享词表（ADR 0024 的同一份
`assets/content-lexicon.json`）：整册配图上限、提示词里不该出现的词、哪些页面
不该配图。

### 2. 审核页看得见、改得动

审核页每一页新增"页面配图"折叠区：开关、角色下拉、画面描述输入框。
用户改完这一页就不再是"已审核"状态，因为它变了。

### 3. 合规检查在审核阶段就报

新增 `src/features/ai/visual-asset-review.ts`，四类确定性检查：

| 问题                       | 判据                                 |
| -------------------------- | ------------------------------------ |
| `image-text-request`       | 画面描述里出现"文字/标题/写着…"等词  |
| `image-empty-prompt`       | 配了图但没有画面描述                 |
| `image-on-structured-page` | 页面已有时间线/对比/流程/表格/指标块 |
| `image-over-limit`         | 整册配图超过上限                     |

规则表在共享词表里，前端据此检测，后端据此写提示，两边不会各说各话。

这些问题**不阻塞**审核：内容本身没有问题，图的事可以之后再定。这与既有原则
一致——标题问题只提示、不改写。

### 4. 用户的决定压得住模型，模型的保守压不住

设计阶段仍然会给出 `visualAsset`（它是设计合同的一部分），但两边的意见要分开看：

- **用户**在审核页关掉配图 → 这一页不配，谁的意见都不算数。
- **模型**在内容阶段说"这一页不用配图" → 不算数。它只是保守。

这条区分是实测逼出来的。用线上跑的那份提示词问真实模型（一册四页），
结果是：**只有封面页带了配图意图，其余三页都写 `enabled=false`**，
而设计阶段本会给其中两页配图（侧栏图、通栏图）。

最初的实现是"审核阶段的意图一律优先"，结果整册的图从 3 张掉到 1 张——
模型在内容阶段的保守，恰好压掉了设计阶段更合理的判断。

所以 `plan.visualAsset` 带一个 `source` 字段：

| source | 含义 | 效力 |
| --- | --- | --- |
| `model` | 生成时模型给的 | 只能加票，不能减票 |
| `user` | 审核页里人改的 | 能加票，也能减票 |

规则因此是：

- 配图：任一模型意图说"要配"，就配；两边都说不要，才不配。
- 不配图：只有人说了"不配"，才不配。
- 画面描述：优先用内容阶段那一份（它贴着正文），空了就退回设计阶段那一份。
- 角色：内容阶段指定了就用它，否则用设计阶段的。

用户改过任何一处（开关、角色、描述），`source` 就变成 `user`。

### 5. 图照旧由引擎决定位置

配图意图只回答"配什么图"和"图是什么角色"，不回答坐标。落点仍由
`planVisualAssetLayout` 计算（ADR 0021、0026）。

## 影响

- `slidePlanSchema` 新增可选字段 `visualAsset`。旧草稿和历史记录不受影响。
- 审核页多一个可折叠区；不改内容字段的既有交互。
- 内容阶段的输出契约变了：模型要多给一段配图意图。提示词里写明了什么时候
  不要给（每页都配、已有结构化块的页面）。
- 后端的两个内容提示词抽成了独立函数（`draft_prompt` / `slides_batch_prompt`）。
  抽出来是为了**可测**：真实调用测试必须用线上跑的同一份提示词去问模型，
  测试里另写一份，测到的就不是用户会遇到的。

## 真实调用验证

`cargo test --lib content -- --ignored --nocapture` 用**命令层线上跑的同一份
提示词**问真实模型（一次调用，四页），检查 `plan.visualAsset` 是否真的出现。

实测结果：4 页里 1 页带配图意图（封面，主视觉，画面描述是
"明亮午后的区域商业街鸟瞰画面……色调温暖。"——纯画面，没有要求出现文字），
其余 3 页 `enabled=false`。这个结果直接催生了上面第 4 节里 `source` 字段的区分。

## 备选方案

**在设计之后再让用户审核配图。** 那时图已经生成，钱已经花完，改一次要重新生成，
用户会倾向于接受现状——审核就失去了意义。

**让审核页直接显示生成好的图片。** 需要把配图提到审核之前，也就是设计阶段之前，
整条流水线的顺序要重排，代价远大于收益。

**只提示不修改。** 用户看得见问题却改不了，只能等进了编辑器再回头改描述，
那时已经没有图可以再生成了。
