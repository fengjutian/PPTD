# 0107 安全文本超链接往返

## 决策

文本片段 `TextRun` 增加可选的 `hyperlinkUrl`，它属于设计模型，不复制或改变正文。持久化 Schema 升到 v30；`29 → 30` 只提升版本号，不根据可见文字推断链接。

PPTX 导入只保留外部 `http`、`https` 和 `mailto` 关系。内部跳页、文件链接、缺失关系及其他协议不进入文档，并逐项写入兼容报告。Rust OOXML 适配层先过滤，TypeScript 命令边界再次校验；编辑画布不执行链接。

导出把合法地址写入 PptxGenJS 文本 run 的原生 hyperlink 选项，使文字与链接在 PowerPoint 中保持可编辑。编辑器“插入 → 超链接”按整个文本框设置或移除链接；属性面板可在文本框内选中文字后只给该范围设置、编辑或清除链接。两者都写 `set-text-hyperlink`（局部链接附带 `range`），属于设计事务：正文、内容哈希和片段强调都不变。局部范围只允许一个文本元素，并拒绝越界、空范围和从代理对中间切开的选区；清除局部强调只移除粗体、颜色和下划线，不会顺带删除同一 run 上的链接；“清除格式”和格式刷也会保留链接，因为链接是动作而不是字体。当前仍不支持形状级链接和内部幻灯片跳转。

## 原因

导入文件是不可信输入，不能把任意 `file:` 或脚本协议带入桌面应用。把链接附着在字符区间上，同时维持正文唯一来源和内容/设计隔离，也不会为了保留链接而把文本栅格化。

## 验证

- Rust 测试覆盖安全 https 关系的导入及 `file:` 关系的报告与丢弃。
- Schema 固定 v29 样例验证迁移不会凭空生成链接。
- 文本分片测试验证不同目标不会被错误合并。
- 命令测试验证整框和局部链接保留既有加粗/颜色、只清除所选范围的链接、移除链接不改正文，并拒绝 `file:` 等不安全协议和多元素范围。
- 片段测试验证局部链接不清除范围外的链接，清除强调不会删除同一 run 上的链接；命令测试验证“清除格式”和格式刷只保留链接、不保留字体强调。属性面板测试验证局部链接入口和链接不再被误列为“强调”。
