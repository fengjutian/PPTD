# ADR 0114：声明式低代码布局系统

- 状态：提议
- 日期：2026-10-26

## 背景

PPTD 已有配方、语义区域、`normalized-1000` 坐标、确定性几何函数和 AI PPT Workbench，但还缺少一层可同时供用户、模板作者和 AI 操作的布局表达。当前两种极端都不适合作为统一方案：

- 只保存绝对坐标，适合最终渲染和自由编辑，但无法稳定表达“等宽四列”“左图右文”“内容增加后自动换行”等布局意图。
- 让 AI 或 UI 直接构造任意页面对象，容易绕过内容与设计隔离、测量、Schema、revision 和撤销重做边界。

低代码产品常用“容器、属性、约束、组件树”表达界面。PPT 页面可以借鉴这种声明式能力，但不能照搬浏览器 DOM、CSS 或响应式网页布局：PPT 有固定页面尺寸、确定性导出、文本测量差异以及原生对象可编辑性要求。

## 决定

建立一套声明式布局树，作为“布局意图”的事实来源；布局编译器将其确定性编译成槽位和整数 EMU 几何。用户低代码编辑器、内置配方和 AI Workbench 都操作同一种布局能力，但权限和入口不同。

```text
已审核 Content Model ───────────────┐
                                    v
用户布局编辑器 / 配方 / AI ──> LayoutTree
                                    |
                                    v
                         Layout compiler + measure
                                    |
                                    v
                    normalized-1000 slots + diagnostics
                                    |
                                    v
                       Design commands / integer EMU
                                    |
                       ┌────────────┴────────────┐
                       v                         v
                    2D 画布                  PPTX 导出
```

### 1. 布局树只表达设计，不保存内容副本

首版节点集合保持有限：

- `canvas`：页面根节点，一页恰好一个。
- `section`：标题、正文、页脚或自定义语义区域。
- `row`：沿水平方向分配子节点。
- `column`：沿垂直方向分配子节点。
- `grid`：固定列数的规则网格。
- `slot`：标题、正文、图片、图表、表格、指标或装饰对象的放置槽。

`slot` 只持有稳定 `contentRef` 或语义查询，不复制标题、正文、数字、引用和备注。设计命令不得通过布局树改写 Content Model。

### 2. 尺寸使用受限策略，不引入 CSS

节点尺寸只允许以下策略：

- `fixed`：逻辑坐标中的确定尺寸；仅编译器和高级精确编辑使用。
- `fraction`：在父容器剩余空间中按整数权重分配。
- `fill`：占据剩余空间。
- `content`：按测量结果申请空间，并受最小、最大值约束。

间距、内边距和圆角优先引用设计令牌。布局树不接受 CSS 字符串、像素、英寸、浮点百分比、任意表达式或脚本。内部中间坐标使用 `normalized-1000` 整数，持久化的最终对象继续使用整数 EMU。

### 3. 自动布局与自由编辑显式共存

页面对象具有以下布局状态之一：

- `managed`：几何由布局树负责，重新编译时可以移动或调整尺寸。
- `detached`：用户显式脱离自动布局；布局编译不得覆盖其几何。
- `overlay`：独立于普通流的受控叠加对象，必须指定锚点和层级策略。

从 `managed` 切换为 `detached` 是一个设计事务和一个撤销项。系统不得因为一次拖动而静默破坏布局关系；拖动自动布局对象时，交互层先预览插入位置、比例调整或脱离操作，鼠标释放后只提交一个命令。

### 4. LayoutTree 与 LayoutProgram 分工

- `LayoutTree` 是可持久化、可视化编辑、可复用的声明式意图。
- `AiLayoutProgram` 是 Workbench 会话内的受控增量操作记录。
- 编译器把布局树降低为现有 `inset/columns/rows/stack` 等几何操作，并产生槽位表。
- AI 不直接提交完整布局树 JSON；它通过工具对草稿树执行有界操作，服务端返回结构化结果。
- 同一页面在任一 revision 上只能有一个有效布局树，不能让树和手写操作程序分别成为事实来源。

### 5. AI 交互采用“检查—计划—预演—提交”协议

AI 通过 ADR 0113 定义的 PPT Workbench 交互，不持有可写 `PresentationDocument`，也不直接输出 EMU、CSS 或任意坐标。

#### 5.1 会话上下文

应用创建 AI 布局会话时提供只读、裁剪后的上下文：

- 页面 ID、页面尺寸和 revision 基线。
- 可用语义区域、主题令牌和模板能力。
- 内容块的稳定 ID、类型、字符/项目数量、测量摘要和审核状态。
- 当前布局树摘要、槽位占用和布局诊断。
- 允许调用的工具清单及 JSON Schema。

默认不重复发送完整正文。只有确实需要判断语义映射时，才发送最小必要的内容摘要；日志和工具轨迹不得记录完整敏感正文。

#### 5.2 工具域

首版 AI 工具建议分为四类：

| 工具 | 作用 | 是否改变草稿 |
| --- | --- | --- |
| `layout.inspect` | 读取区域、节点、槽位或诊断 | 否 |
| `layout.suggest` | 根据内容事实返回兼容的布局骨架候选 | 否 |
| `layout.node.add` | 向容器添加受支持节点 | 是 |
| `layout.node.update` | 修改方向、尺寸策略、间距、对齐等白名单属性 | 是 |
| `layout.node.move` | 在同页布局树中移动节点 | 是 |
| `layout.node.remove` | 删除未绑定内容或可安全替代的布局节点 | 是 |
| `layout.slot.bind` | 将已有 `contentRef` 绑定到兼容槽位 | 是 |
| `layout.compile` | 编译草稿并返回槽位、测量和诊断 | 否 |
| `layout.preview` | 返回预演摘要或受控预览资源引用 | 否 |
| `layout.plan.inspect` | 查看待提交设计命令 | 否 |
| `layout.plan.clear` | 清空当前草稿计划 | 是 |

工具命名是目标协议；实施时可以把现有 `layout.columns/rows/stack` 保留为底层或兼容工具，但模型不应同时面对两套重叠的高层写接口。

#### 5.3 多轮流程

```text
AI inspect
  → suggest 或创建/修改节点
  → compile
  → 根据 diagnostics 有界修正
  → preview
  → 返回 proposal
  → 用户确认
  → revision check
  → 单事务提交
```

AI 每轮只能调用一个工具。工具失败返回稳定错误并保持调用前草稿，不得让模型假设操作成功。循环受最大轮数、工具白名单、输入体积、节点数量和嵌套深度限制。

#### 5.4 提案而非静默生效

AI 最终结果是 `LayoutProposal`，至少包含：

- 基线 document/content/design revision。
- 目标页面 ID。
- 布局树 patch 或强类型设计命令计划。
- 编译报告摘要。
- 内容绑定变化列表；只允许引用变化，不允许内容值变化。
- 视觉变化说明和仍未解决的问题。

默认先展示预览及差异，由用户确认后提交。明确的“一键自动排版”可以自动确认设计变更，但仍必须经过同一 Schema、编译、质量门和 revision 检查，且形成单个可撤销事务。

### 6. AI 权限矩阵

| 能力 | AI | 用户 | 确定性代码 |
| --- | --- | --- | --- |
| 选择布局骨架 | 可提议 | 可选择 | 校验兼容性 |
| 新增/移动布局节点 | 仅草稿 | 可以 | 校验并编译 |
| 绑定已有内容 | 可提议 | 可以 | 检查类型与完整性 |
| 修改正文、数字、引用、备注 | 禁止 | 进入内容流程 | 不允许由设计命令完成 |
| 写任意坐标、CSS、脚本 | 禁止 | 高级模式也受 Schema 限制 | 生成最终几何 |
| 自动缩小至不可读 | 禁止 | 不提供绕过 | 返回容量冲突 |
| 删除已审核内容 | 禁止 | 需内容变更流程 | 返回未消费内容 |
| 提交事务 | 禁止直接提交 | 确认或显式自动排版 | revision 检查后执行 |

### 7. 测量、冲突和降级

布局编译至少执行：

1. Schema、节点 ID、引用和树无环校验。
2. 父子包含、边界、最小尺寸、间距和兄弟重叠校验。
3. 文本、图片、表格、图表的类型兼容和容量测量。
4. 未绑定槽位与未消费内容检查。
5. 可读字号、行长、对比度和模板约束检查。
6. 生成 normalized-1000 槽位和整数 EMU。

硬错误阻止提交；软问题进入 `DesignCompileReport`。首版稳定错误至少包括：

- `INVALID_LAYOUT_TREE`
- `INVALID_NODE_REFERENCE`
- `UNSUPPORTED_NODE_TYPE`
- `SLOT_CONTENT_MISMATCH`
- `UNCONSUMED_CONTENT`
- `INSUFFICIENT_CAPACITY`
- `TEXT_OVERFLOW`
- `OUT_OF_BOUNDS`
- `OVERLAP`
- `MEASURE_UNAVAILABLE`
- `REVISION_CONFLICT`

遇到容量不足时，AI 可以在剩余轮数内换骨架、调整比例、增加行列或提出拆页建议，但不能删除、改写内容或把字号缩到质量门以下。拆页属于内容结构变化，必须转入内容审核流程，不由布局工具直接执行。

### 8. 持久化和版本

布局树进入持久化模型前必须具有独立 `layoutSchemaVersion`、运行时 Schema、迁移和固定样例。首个 UI/Workbench 原型可以先使用会话草稿，不立刻修改 `PresentationDocument` Schema；持久化设计必须在实现前另开迁移任务。

模板可以携带布局树骨架，但实例页面只保存稳定引用和必要覆盖，不复制整套模板定义。模板更新不能静默改变已有页面；必须生成可预览的迁移提案。

### 9. 布局能力注册表

布局节点和属性由一个强类型注册表管理，UI、AI 工具 Schema、编译器和文档校验器都从同一注册事实生成能力视图。注册项至少声明：

- 稳定类型 ID 和协议版本。
- 可接受的父节点、子节点类型及数量限制。
- 可配置属性及其默认值、范围和设计令牌来源。
- 允许绑定的内容类型。
- 测量策略、编译器和导出能力。
- AI 是否可读取、创建、修改或删除。
- 不支持时的错误或显式降级行为。

注册不等于运行任意插件代码。V0.1 只注册仓库内置、经过测试的纯函数能力；外部布局组件、动态脚本和远程代码不在范围内。未注册字段按 Schema 拒绝，不得静默忽略。

### 10. 约束分级与确定性求解

约束分成三个等级：

1. `required`：边界、正尺寸、无环、内容完整性、最小可读字号等硬约束；违反即编译失败。
2. `preferred`：期望比例、对齐、行长、视觉平衡等软约束；产生评分和诊断，但不自行改变内容。
3. `suggested`：AI 或模板给出的审美倾向；只在不影响前两级时参与候选排序。

首版不引入通用约束求解器。容器按稳定节点顺序、整数权重和明确余数规则计算；相同布局树、内容测量、主题令牌与页面尺寸必须产生字节级相同的槽位结果。若以后引入求解器，必须固定版本、目标函数、决胜规则和数值精度，并通过 ADR 更新此决定。

### 11. 测量反馈是有版本的编译输入

布局编译输入除布局树外，还包括 `MeasurementSnapshot`：字体解析结果、文本度量器版本、图片宽高比、表格最小尺寸、图表图例需求和测量环境标识。编译报告记录其摘要，避免同一布局在未知字体替代后无声漂移。

- 字体不可用时先按明确替代策略重新测量，并记录 `FONT_SUBSTITUTED`。
- 画布与 PPTX 导出共享同一测量快照或报告可解释差异。
- 测量不可用不得伪装为成功；可以使用标记过的保守估算生成预览，但不能无警告通过最终质量门。
- AI 只能读取容量摘要和诊断，不能伪造测量结果。

### 12. 模板、实例和覆盖层

布局复用采用三层合成，而不是复制后失去来源：

```text
LayoutDefinition（可复用骨架）
  + LayoutBinding（页面内容绑定）
  + LayoutOverride（页面局部设计覆盖）
  = EffectiveLayoutTree
```

- Definition 更新必须产生迁移预览和受影响页面列表。
- Binding 只保存稳定内容引用和槽位引用。
- Override 只允许注册表声明为可覆盖的属性；不能改变内容值。
- 编译报告必须能指出最终属性来自定义、绑定、页面覆盖还是 AI 草稿。
- 用户可将实例“断开为独立布局”，该操作必须显式、可撤销并生成新的稳定布局 ID。

### 13. AI 可解释性、幂等与恢复

每个 AI 写工具调用带 `callId` 和调用方看到的 `draftRevision`。Workbench 对同一会话中的重复 `callId` 返回原结果，不重复应用；revision 不匹配返回 `DRAFT_REVISION_CONFLICT`。工具轨迹记录类型化操作和诊断，不依赖模型自然语言作为审计事实。

`LayoutProposal` 还应包含：

- `goal`：本次排版目标。
- `changedNodeIds` 和 `affectedElementIds`。
- `decisionReasons`：引用内容事实或诊断 code 的短理由。
- `qualityDelta`：硬错误、软问题和布局评分的前后变化。
- `replayDigest`：基线、工具轨迹、注册表版本和测量快照的摘要。

AI 会话异常中断时可以丢弃，默认不进入项目自动保存。若产品以后支持恢复草稿，只保存经过大小限制和脱敏的 Workbench 状态，并在恢复时重新执行 Schema、revision 和注册表版本检查。

### 14. 批量排版与跨页一致性

批量排版先形成 deck 级计划，再为每页建立独立草稿。deck 级计划只能选择布局族、重复节奏和共享设计令牌，不能跨页移动、合并或改写内容。每页单独编译和报告；最终可以整体提交，也可以让用户排除失败页后提交其余页面，但两种行为必须在确认界面明确区分。

跨页一致性检查至少覆盖标题轴、页边距、重复槽位位置、同类页面比例和视觉节奏。它只产生设计诊断或页面级修正提案，不直接改变页面语义顺序。

## 后果

正面：

- 用户低代码编辑、内置配方和 AI 使用同一个布局语义。
- 页面仍能编译为原生可编辑 PPT 对象，不依赖整页截图。
- AI 的每一步可校验、可回放、可诊断，失败不会污染文档。
- 自动布局和 PowerPoint 式自由编辑有明确边界。

代价与限制：

- 需要布局树编辑器、测量反馈和编译报告，初期复杂度高于只存绝对坐标。
- `content` 尺寸受字体度量影响，画布与导出必须共享或校准测量事实。
- 第一版不支持任意嵌套响应式规则、条件表达式、脚本或 CSS。
- AI 只能组合已注册能力；新增节点或属性必须同时具备 Schema、编译消费点和行为测试。
- 布局注册表、测量快照和模板继承增加了协议版本治理成本。

## 备选方案

- **只保留绝对定位**：实现简单，但无法表达布局意图和安全重排，不采用。
- **完整照搬 CSS Flex/Grid**：能力过宽、跨渲染器难以一致，也会把浏览器细节带入领域模型，不采用。
- **让 AI 一次性输出完整页面 JSON**：难以渐进校验、冲突恢复和权限审计，不采用。
- **为 AI 和用户分别维护布局模型**：会形成两个事实来源并造成画布、导出和自动排版漂移，不采用。
