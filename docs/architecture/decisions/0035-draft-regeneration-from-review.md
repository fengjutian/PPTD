# 0035 · 审核页重新生成整份草稿

## 背景

内容审核页是第一处能判断"整册写得不对"的地方：标题句式重复、栏目式标题、
满页密集文字，这些问题往往不是某一页的错，而是模型的整体写法问题。

以前的唯一出路是返回开始页重新生成，代价是把已经改好、审核过的页面全部丢掉。
审核页本身没有重新生成的入口，用户只能在两件都不理想的事情里选一件：

- 逐页手动改二十页文字，改完已经不是 AI 那一版了。
- 返回开始页重来一版，接受前面所有编辑作废。

审核阶段的草稿还没有生成图片、也没有进入设计阶段，重新生成的成本只是文字，
这是整条流水线里最适合"再要一版"的时机。

## 决策

### 1. 重新生成是审核页的整册动作

审核页头部新增"重新生成草稿"，与"确认内容，选择 PPT 模板"并列。它只做一件事：
用同一个主题、同样的页数再生成一份结构化草稿。

- 主题取当前的生成主题（制作历史里保存的 `topic`）；老数据没有主题时退回草稿标题。
- 页数取**当前草稿的页数**：用户在审核页加过的页，不会因为重新生成被悄悄减掉。

### 2. 生成期间旧草稿保持可见、可读

重新生成不是先清空再看结果：旧草稿在生成期间继续显示，正文依旧可读。
生成成功后整体替换草稿；失败或取消不改动草稿，只报告原因。

生成中显示进度条与"已写 N 页"，并可以取消。取消会推进请求号并中断后端任务，
与开始页的取消语义一致，避免模型继续生成一份没人要的草稿。

### 3. 旧版本进撤销栈

重新生成成功后，旧草稿作为快照压入内容编辑的撤销栈，所以按一次撤销就能回到
上一版。这是"再要一版"的必要条件：用户会对比两版，必须能来回切。

同时，新的生成结果成为这一版草稿的 **AI 原稿**（`aiOriginalDraft`），单页的
"恢复 AI 原稿"随之指向最新一次生成的文字，而不是上一版。

### 4. 重新生成期间不进入模板选择

"确认内容"在重新生成期间禁用。否则可能用旧草稿开始设计、生成到一半草稿被替换，
设计与内容就来自两个版本。

## 影响

- 制作历史仍是一条记录：重新生成后的草稿按原有防抖逻辑写回同一条历史。
- 每页的"已审核"状态由新草稿决定，旧版的审核标记留在撤销快照里，撤销可恢复。
- 重新生成按当前草稿页数调用 `generatePresentationDraft`，走既有的分批生成与
  进度事件，不新增后端命令。

## 备选方案

**返回开始页重新生成。** 会丢掉全部审核结果，用户会倾向于勉强接受现状。

**单页重新生成。** 粒度更细，但整册写法不对时要点二十次；留给后续迭代按需增加，
两者的撤销与 AI 原稿语义可以复用本决策。

**生成期间清空旧草稿。** 屏幕会长时间空白，用户既看不到自己改了什么，也无法在
生成失败时继续审核。
