# 0016 真实字体度量与文字适配

## 状态

已采纳（2026-10-23）。

## 背景

文本框会不会溢出，此前靠一个固定启发式判断：CJK 字符算 1 em，拉丁字符算 0.55 em。实测（Chromium canvas，100px 字号）：

| 字体 | 文本 | 真实 (em) | 启发式 (em) | 偏差 |
| --- | --- | --- | --- | --- |
| Microsoft YaHei | 开始创造你的演示文稿 | 10.000 | 10.000 | 0.0% |
| Microsoft YaHei | 覆盖机构：12万 | 7.173 | 7.100 | +1.0% |
| Microsoft YaHei | 年度检测样本量 38万，覆盖 12家机构 | 16.938 | 17.300 | −2.1% |
| Arial | Quarterly revenue grew 38% | 12.729 | 14.300 | **−11.0%** |

中文场景误差在 2% 以内，可以接受；但纯拉丁与数字密集的文本（如英文标题、含百分比的数据句）被系统性地**高估约 11%**。后果是：质量门误报溢出，用户点"适配文字"时被无谓地缩小字号。

## 决策

1. **度量是一个端口，不是依赖**。核心层定义
   ```ts
   interface TextMeasurer { widthEm(text: string, fontFamily: string): number }
   ```
   应用层注入基于 canvas 的适配器（`createCanvasTextMeasurer`）。核心层不碰 DOM、不碰 Tauri，因此无头工具与单元测试仍可运行。端口是进程级单例，应用启动时注册、卸载时注销。
2. **宽度以 em 为单位**。字号与宽度解耦，同一段文字只需测量一次，就能用于所有候选字号。适配器在 100px 下测量后除以 100，并按 `字体 + 文本` 缓存（上限 500 条，超出即整体清空——缓存只是加速，允许丢弃）。
3. **没有 measurer 时回退到原启发式**。因此导出校验、命令行工具、既有测试在没有浏览器的环境下行为不变；注册 measurer 只是让结果更准。
4. **新增 `fit-text` 命令**（设计域）：从当前字号逐档下调到 8pt，取第一个不溢出的字号。它只改 `style.fontSizePt`，不动文字、数字、来源和备注，内容哈希与审核状态不变，可撤销。
5. **阈值与质量门完全一致**（行高 ×1.2 对框高 ×1.08）。修复后质量门的溢出报告真的消失，而不是换个数字继续报。
6. **属性面板给出入口**：文字超出文本框时显示警告和"适配文字"按钮。画布渲染与质量门都把 `style.fontFamily` 传进度量。

## 影响与边界

- **度量解决宽度，不解决断行**。浏览器与 PowerPoint 的换行算法不同，断点位置仍可能不同。
- **字体缺失无法被检出**。canvas 量的是浏览器**实际渲染**的字体：字体没装时浏览器静默回退，本机实测"一个不存在的字体名"与真字体的测量结果完全一致，`document.fonts.check` 也返回 `true`。因此本决定不声称能发现字体替代问题——那仍由导出报告的字体替代警告负责。
- **8pt 是下限**。装不下时保留 8pt 并继续报溢出，不静默截断文字。
- **只做等比缩小**。不重新断行、不压缩字距、不自动拆分成多段。
- 适配器是 Chromium canvas 实现，与 PowerPoint 的字距、字偶距处理仍有细微差别；导出侧仍以导出报告的检查结果为准。
