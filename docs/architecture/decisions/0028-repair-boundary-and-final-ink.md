# 0028：修复不能把文字从卡片里搬走

## 状态

已接受（2026-10-22）。

## 背景

一份 20 页课件在视觉评审和修复之后，文字系统性地离开了它所在的容器：

- 卡片里的要点落到卡片下沿以外，压到下一行卡片上；
- 对比页的栏头标签跑到色条上方 0.6 in，正文钻到色条下面；
- 计数面板的"04"跑到面板左侧外面；
- 封面白字压在浅灰底色上；
- 标题被放大到 44pt，两行文字高 110pt，而标题框只有 90pt。

这些不是四个独立 bug，而是同一个结构问题的四种表现：

1. 区域修复（ADR 0023）只遍历文本对象，形状不参与移动。模型说"把这块往下挪"，代码把文字挪了、卡片没动，文字就离开了卡片。
2. 模板亮度探针描述的是底图。底图没有绘制时（`keepsArtwork` 为假），探针仍然被采用，于是深色底图上的白字被放到了浅色平页上。
3. 修复的 `restyle` 和强调逻辑会改字号/颜色，但改完不再检查文本框是否还装得下、颜色是否还读得清。

## 决策

1. **几何修复止步于容器边界。** 一个文本被面积小于页面 40% 的生成形状包住时，`move`/`resize`/`align` 不再作用于它；`restyle` 仍然允许。文字属于卡片，卡片的位置由版式引擎决定，模型不能只搬文字。
2. **修复之后统一再适配。** 所有修复和强调执行完，逐条检查文本是否溢出，溢出就逐级缩小到装得下（下限 8pt）。放大标题不再能撑破标题框。
3. **最后一遍墨色解析。** 每条文本按实际承载面重新解析颜色：承载形状的填充 → 模板亮度区间（底图真的存在时）→ 页面底色。模型重上色不能留下看不见的字。
4. **模板探针只在底图绘制时生效。** `keepsArtwork` 为假时用页面底色计算明暗，避免"按不存在的深色底图配白字"。

## 结果

- 卡片文字、栏头标签、计数面板的数字不再被修复搬出容器。
- 封面在浅色平页上自动改用深色墨，不再出现白字压浅灰。
- 被放大的标题自动缩回框内，不再压住正文。
- 新增 3 条回归测试：区域移动后卡片内所有文本仍被容器包住、封面标题对比度 ≥ 3:1、修复放大后的标题不再溢出。

## 未覆盖

- 没有承载形状的正文（整段文字直接放在页面上）仍然可以被区域移动；这类页面没有"离开卡片"的判定依据。
- 不支持"整卡移动"：形状和文字的同步移动还没有实现，模型想搬一整张卡时会被忽略。
- 8pt 只是兜底。内容长到 8pt 仍装不下时，问题在内容量与版式的匹配，不在字号。
- 已经被搬走的位置没有原始坐标可还原；已有文档需要重新生成，修复只对新的生成生效。
