# 0116 设计完成后重排文字：让文档本身装得下

## 状态

已接受（2026-10-26）

## 背景

ADR 0115 让预览不再吞字：测量与渲染共用一个断行事实来源，放不下时按 `normAutofit` 的方式缩字。这解决了"预览里少一个字"，但把问题往后推了一层：

- 文档里的文本框仍然可能比它的文字矮几个百分点；
- 编辑画布（`.slide-element.text > div` 有 `max-height: 100%; overflow: hidden`）照样把行裁掉；
- PowerPoint 打开文件时再按 `normAutofit` 缩一次字，同一个文本框在三个地方有三种字号；
- 用户改完内容、模板收窄了栏宽、风格约束加了行距之后，问题会不断重新出现。

一页的组成来自很多独立决定：配方按内容算一次，模板占位给一次几何，风格约束再改一次行距，修复流程还可能把标题放大一号。每个环节都"差不多对"，合起来就会差一行。只在末端补救，等于永远在追。

## 决定

在设计合成结束时，对每一页做一次**确定性的文字重排**（`core/layout/text-refit.ts`），让文档本身就是装得下的那一版。

### 1. 只改设计，不改内容

重排只动两个设计属性：文本框高度和字号。正文、数字、引用、备注、元素顺序、`contentRef` 一律不动；因此不触发内容版本，也不需要重新审核。

### 2. 优先争取空间，其次缩字

对每个放不下的文字：

1. 若它顶对齐，且下方还有空高度（到最近一个"障碍物"为止），先把框长高到刚好放下——保住了设计字号，也是排版师会做的第一反应。
2. 否则在可读下限（原字号 70%，且不低于 8pt）之上缩字，并逐步回退到"严格装得下"，不依赖 2% 容差。
3. 到下限仍放不下，写回下限字号并记一条冲突；文案一字不改。

"障碍物"取两类：下方最近的对象，以及**衬在文字后面的面板/卡片**（其底边是上限）。后者防止文字为了放下面长出卡片，跑到页面底纹上。增长上限另加两行：重排吸收的是设计漏掉的一两行，不是把单行标签拉成一列。

### 3. 模板页不重排

带 `layoutId` 的页面使用上传模板的占位几何，那是用户选定的契约。重排不碰这些页面：既不增高、也不缩字，超出的部分交给审计报告和文件的 `normAutofit`。否则一次"修复"就会把模板的标题轴和占位高度改掉，模板贴合检查还会因此报出偏差。

### 4. 重排是设计合成的一部分

`buildDesignedSlide` 在返回页面前调用重排，所以配方页、旧版构图、方向预览、重排（`slide-relayout`）走的是同一条路径。它不进撤销栈、不产生额外事务：页面从设计阶段出来时就已经是最终几何。

重排的结果不改写内容，也不进入 UI 文案；仍然装不下的页面由 ADR 0115 的 `auditSlideLayout` 与 `TEXT_OVERFLOW` 诊断继续暴露，预览按 `normAutofit` 缩小显示，文件同样缩小显示——三者不再各说各话。

## 后果

正面：

- 画布、缩略图、预览和 PPTX 里的文字是同一个字号、同一个断行，不再"预览一份、文件一份"。
- 缺一两行的版面自动补上，不需要为每个配方再写一遍边界处理。
- 模板页的几何保持原样，模板贴合检查不会因为一次修复而漂移。

代价与限制：

- 重排会改变字号（最多 70%）。它保证"放得下"，不保证"好看"；容量严重不足的页面仍需要拆页，那属于内容流程（ADR 0114 §7）。
- 增长依赖"障碍物"判定：绝对定位的装饰、大面积出血图可能让可用空间算得保守，于是回退到缩字。保守的失败方向是可读，不是重叠。
- 重排只在设计合成时执行一次。用户在编辑器里手工放大字号、或改内容导致文字变长时，要等下一次重排/校验才会被修；编辑器仍会裁字（ADR 0115 的限制）。
- 模板页完全不重排，所以模板占位比内容矮时，画布上仍可能裁掉一行——这是有意的取舍，需要模板作者或内容流程解决。

## 验证

- `text-refit.test.ts`：
  - 装得下的文字不动（几何与字号都不变）；
  - 框短、下方有空时增高而不是缩字，文案不变，增高后严格装得下；
  - 文字被卡片衬底时缩字，不越过卡片；
  - 垂直居中的文字只缩字、不移动；
  - 到下限仍放不下时报冲突，字号停在下限，文案不变；
  - 模板页（`layoutId`）不做任何修改；
  - 结果是确定性的（同输入同几何）。
- `commands-layout.test.ts`：模板占位几何在生成后保持逐 EMU 一致。
- `apply-ai-designed-draft` 生成的两页在 `auditSlideLayout` 下没有 `text-overflow`。
- 全量测试与真实 PowerPoint 导出视觉回归通过。

## 备选方案

- **只在预览里缩字（ADR 0115 的状态）**：文件、画布、预览仍是三种表现；不采用。
- **让重排增高一切、永不缩字**：单行标签会变成整列，也会压到页面底部与页脚；不采用。
- **改模板页几何让它装下**：破坏用户上传的版式契约，模板检查随即报偏差；不采用。
- **把重排做成用户可见的"一键修复"**：多一次交互，且失败时页面仍是坏的；设计阶段静默完成、只报冲突更符合"排版是编译器的事"。
