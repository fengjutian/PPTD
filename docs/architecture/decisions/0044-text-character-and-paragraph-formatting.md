# 0044 字符与段落格式

## 状态

已接受（V0.2）

## 背景

TRS 4.4.4 要求“开始”功能区提供字体与段落命令：字体、字号、粗体、斜体、下划线、删除线、文字颜色、清除格式、项目符号、编号、缩进、行距和对齐。

在此之前，`TextElementStyle` 只有字体、字号、颜色、粗体和水平对齐。`lineHeight` 与 `letterSpacingPt` 虽然已经存在于模型和导出路径，却没有编辑入口；文字片段（ADR 0013）只覆盖局部的粗体、颜色和下划线。用户要改整段格式只能逐项输入，多选时也无法一次套用。

## 决策

### 格式是设计状态

在 `TextElementStyle` 上增加可选字段：

```ts
italic?: boolean;
underline?: boolean;
strikethrough?: boolean;
verticalAlign?: "top" | "middle" | "bottom";
bullet?: "none" | "dot" | "number";
indentLevel?: number; // 0–8
```

这些都是设计字段，不进入内容哈希，也不改变审核状态。字段全部可选，旧文档不需要补默认值；读取端按“缺省即未设置”解释，画布回退到原有的顶端对齐、无标记、无缩进行为。

选择扩展元素样式而不是新建并行格式模型，是因为渲染、导出和属性面板已经共享 `TextElementStyle`；再引入一层映射只会让三处状态漂移。

### 项目符号属于整个文本框

正文仍然是一个字符串，没有逐段结构。V0.2 的项目符号和编号因此作用于文本框的每一行：点状标记统一为“•”，编号按行递增；缩进 0–8 级作用于整个框。标记由渲染器画在文字旁边，不写进 `element.text`，所以复制文本、内容哈希和审核状态都不受格式影响。

逐段格式（同一框内部分段落有标记、部分没有）需要先给内容模型增加段落结构，属于内容格式变更；不在本次范围内，避免用隐藏分隔符模拟段落。

### 批量命令是一个事务

新增两个设计域命令：

- `set-text-style-elements`：把同一份样式应用到所有选中的、未锁定的文本对象。
- `clear-text-format`：把格式恢复为当前主题的标题或正文令牌；没有主题时回退到工厂默认值。

两者都只产生一个撤销项。多选时逐个调用 `set-text-style` 会留下多个撤销步骤，用户按一次 Ctrl+Z 只回退一个对象，这与“一次用户意图”冲突。锁定对象被跳过；过滤后没有可编辑对象时命令抛 `ELEMENT_NOT_TEXT`，不写空事务。

字号增减在核心层使用 Office 的字号阶梯（8、9、10、10.5、11、12、14 … 120），避免产生 13.7pt 这类无法在 PowerPoint 字号框中稳定复现的值。

### 画布与导出共享同一份语义

- 画布按元素样式渲染斜体、下划线、删除线、行距、垂直对齐、项目符号和缩进。
- 导出把它们写成 PowerPoint 原生文本属性：`i`、`u`、`strike`、`anchor`、`lnSpc`、`buChar`/`buAutoNum`、`lvl`，不栅格化文本。
- 带 runs 的文本仍写成原生 run；元素级下划线作为 runs 未声明时的兜底，保证局部强调和整段格式可以共存。

### Schema 15

新增字段使持久化格式升到第 15 版。`14 → 15` 迁移只校验并改版本号，不写入默认格式；固定样例见 `src/core/document-model/__fixtures__/v14-document.json`。

## 后果

- “开始”功能区、属性面板和快捷键共用同一套批量命令，三条入口的行为一致。
- 垂直对齐会改变文字在框内的落点；溢出质检仍按顶端对齐的旧假设计算，需要后续用真实样例校准。
- 项目符号的编号从文本框第一行开始计数，续页或跨框续编号暂不支持。
- 逐段格式、制表位、段落间距和字体嵌入仍未实现。

## 备选方案

- **只扩展文字 runs**：runs 能表达局部字符格式，但无法承载段落级标记和缩进；整段加粗还要为全文写一个 run，反而更重。
- **独立的段落格式模型**：需要修改 `TextElement` 的内容结构和导出映射，收益与成本不匹配；等真正需要逐段格式时再引入。
- **把项目符号写成文本前缀**：会污染内容、内容哈希和审核状态，撤销和导出都无法区分“用户写的•”与“格式生成的•”，明确拒绝。
