# 0104：图层可见性是编辑器状态，导出用去隐藏快照

## 状态

已接受（2026-10-26）

## 背景

图层面板需要“眼睛”开关和图层重命名。两者都不是页面内容：它们不改变文字、数字、引用或版式坐标，只影响编辑器里的可见性和组织方式。问题出在导出：

1. 隐藏对象应该写进 PPTX 吗？
2. 如果写，怎么表达“隐藏”？
3. 自定义图层名要不要写进 PPTX 的对象名？

PowerPoint 原生支持把形状标记为隐藏（`<p:cNvPr hidden="1"/>`），但 PptxGenJS 没有这个 API，只能在生成后改写 slide XML。我们当前的导出链已经按对象名（`objectName = element.id`）做渐变、图片框形和动画的 XML 补丁；再加一个隐藏补丁并非不可能，但会引入新的兼容性面：

- 图表没有 `objectName`，无法按 id 找到它的 `cNvPr`；隐藏图表要么跳过，要么按顺序猜。
- 隐藏对象仍参与“导出后与文档一致”的校验、动画目标和模板贴合度，语义会变得含糊。
- 隐藏对象如果留在包里，PowerPoint 的普通视图仍会显示它们（只有放映视图隐藏），用户看到的文件与编辑器画布不一致。

## 决策

1. `ElementBase` 增加两个可选字段（Schema v25）：
   - `name?: string`：图层名，最长 80 个字符，单行；缺省表示沿用从文字/替代文本/类型推导的名字。
   - `hidden?: boolean`：缺省表示可见；`false` 不写入文档，保持旧文档干净。
2. 可见性只在编辑器生效：
   - 画布、幻灯片缩略图、评审渲染图和框选都不绘制隐藏对象；
   - 图层列表仍显示隐藏行（降低不透明度、眼睛图标切换），否则无法把它恢复；
   - 隐藏对象仍可被图层列表选中、改名、重排和删除。
3. 导出使用 `withoutHiddenElements(document)` 快照：
   - 隐藏对象不写入 PPTX；
   - 依赖隐藏对象的分组、动画一并从快照中移除；
   - 图片框形、渐变、动画、导出校验、素材来源统计和一致性校验都基于同一份快照，避免各走一套对象集合；
   - 导出前置检查按页报告“有 N 个隐藏对象，导出时不会写入 PPTX”。
4. 自定义图层名暂不写入 PPTX。`objectName` 继续使用稳定的 element id，因为原生动画时间线要靠它定位形状；改名会破坏这条链路。图层名先作为项目内的组织信息，PowerPoint 的选择窗格仍显示 id 名。

## 后果

- 隐藏对象在项目里完整保留，撤销/重做、内容审核和再次导出都不丢失；但打开导出的 PPTX 时不会再看到它们。这是有意的降级，报告里明确写出。
- 不再需要处理“隐藏图表没有 objectName”的特殊路径；图表和普通形状行为一致。
- 以后要做原生隐藏形状（放映时隐藏、编辑时保留），需要单独的 OOXML 补丁和 PowerPoint 实测，不在本次范围。
- 图层名不进入 PPTX 的对象名；如果产品需要“PowerPoint 选择窗格显示中文图层名”，要重新设计动画目标映射（例如另存一个内部名），不能在当前 `objectName` 上直接改。

## 备选方案

- **导出时保留隐藏对象并写 `hidden="1"`**：PowerPoint 普通视图仍显示，和编辑器画布不一致；图表没有对象名，需要按顺序猜；补丁面扩大。暂不采用。
- **导出时按可见状态导出**：文件里会出现用户明确隐藏的对象，最不可接受。
- **只做 UI 隐藏、不写模型**：刷新/保存后丢失，无法撤销，也做不到导出过滤。
- **自定义名直接替换 `objectName`**：原生动画补丁按 id 查找形状，改名后动画会丢失目标；需要额外的映射层，超出本次范围。
