# 0019 属性面板的显示偏好与九宫格对齐

## 状态

已采纳（2026-10-22）。

## 背景

属性面板原本把"文档里存的东西"和"这个用户此刻的界面状态"混在一起：

- 长度单位（英寸/厘米）和宽高比锁是组件内的 `useState`，写在属性区里，却和"位置与尺寸"这类真正的文档属性排在一起，看不出哪些会进文档、哪些不会。
- 面板宽度写死在 CSS 里，252px 放四列属性网格很挤，用户却没法调。
- 对齐是"水平/垂直"两排六个按钮，占地方而且要靠记忆哪一排是哪个轴。
- 数值字段只能敲，旋转角之类的量改起来很慢。

这一轮把面板改成用户提出的六件事：主题色板、分组可折叠、九宫格对齐、面板可拖宽、数值拖拽改值加单位内嵌、标题栏显示对象预览。

其中两件事碰到了领域层，不能当成纯界面改动处理。

## 决策

1. **显示偏好不进文档**。长度单位、宽高比锁、面板宽度都只是"这个用户此刻怎么看这个面板"，不描述幻灯片本身。它们留在组件状态里，面板宽度另外存进 `localStorage`（`pptd.inspector-width`）。它们**不产生命令、不改 `revision`、不进入撤销栈**，也不参与内容/设计版本判定——和 `0018` 里"选择状态、视口缩放、悬停状态不得改变文档 revision"是同一条规则。

2. **九宫格是同一个命令的两种目标，不是两个命令**。`align-element` 的 `target` 从单轴字符串扩展为 `{ horizontal?, vertical? }` 对象：九宫格的中间行/中间列给单轴，四角和中心给双轴。一次点击 = 一个领域事务 = 一个撤销项，撤销一次回到点击前的位置。如果拆成"水平对齐命令 + 垂直对齐命令"，双轴对齐就需要两条命令、两次撤销，用户按一次 Ctrl+Z 只能退回一半。

3. **拖拽改值期间不提交命令**。数值字段在指针按下时记录起点，在移动过程中只更新字段内部显示的预览值，松开指针才提交一次命令。中间过程不写文档、不进撤销栈，否则一次拖动会塞进几十个撤销项。

4. **标题栏的对象预览复用共享渲染代码**。预览用 `SlideElementFrame` / `SlideElementContent` 按自身盒子的比例画，和画布、缩略图同源（`0018`）。不另写一份"预览专用"的绘制逻辑，否则又会出现"预览与画布两套代码必然漂移"的老问题。

5. **单位放在输入框内部**。`度`、`pt`、`英寸` 之类的单位是输入框里的绝对定位元素，输入框自己留出右边距。单位是字段的固定后缀，不随数值变化，单独占一列会挤掉数值本身。

## 影响与边界

- **对齐九宫格是"相对页面"的对齐**。单元格移动的是对象相对页面的位置，不是相对其它对象的分布；相对其它对象的对齐不在本轮范围内。
- **单元格图示按"实际会动哪个轴"绘制**。中间行/中间列画成一根贴着对应边的条，因为它们只移动一个轴；四角和中心画成对象落在页面上的位置块。两轴都用同一张图会让单轴操作看起来像同时改了两个轴。
- **面板宽度是显示偏好，不随项目走**。换一台机器、换一个项目，面板宽度回到默认值 252px。用户要的是"在这个窗口里看舒服"，不是"把这个宽度写进文稿"。
- **拖拽改值按 4px 一档**，按住 Shift 乘 10，按住 Alt 除以 10。拖拽只改数值，不改其它属性。
- **对象预览是等比缩小的真图**。一个 7.5 英寸宽的标题放进 56px 的框里，文字必然只有几个像素高——这是等比缩小的固有结果，预览的作用是让用户认出"这是哪个对象"，不是让用户读清内容。
