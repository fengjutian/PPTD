# 0042 内容版本快照与差异对比

## 状态

已接受（V0.1）

## 背景

TRS 4.2 要求保存已确认内容版本，并能对比修改前后的内容。V0.1 之前只有撤销栈、单页"恢复 AI 原始"和 AI 草稿历史：

- 撤销栈不是持久版本，关闭项目后就消失。
- "恢复 AI 原始"只覆盖单页，而且会把已确认版本一起丢掉。
- AI 草稿历史记录的是生成输入和草稿，不是用户最终确认的内容。

内容复核闭环（ADR 0040）补上了"确认"动作，但确认后的内容没有留下可比较的基线。

## 决策

### 快照属于项目文档

在 `PresentationDocument` 上增加可选的 `contentVersions`，每个版本保存整份文稿的内容字段：标题、正文、内容块和演讲备注。元素、样式、背景、版式、审核状态和内容哈希都不进入快照。

快照随项目文件保存，复制项目时一起带走。没有采用应用数据库或旁路文件：内容版本是项目内容的一部分，不是本机元数据；换机器或复制项目后仍应可追溯。

### 确认时自动生成

两个命令是确认动作：

- `approve-slide-content`；
- `apply-ai-designed-draft`（应用已经过审核的 AI 内容）。

命令在完成内容写入后调用 `captureContentVersion`。版本使用命令即将写入的内容 revision 和文档 revision，不额外开一次事务，也不产生额外的撤销项；撤销确认动作时，该动作新增的快照随 Immer patch 一起撤销。

同一份内容重复确认不新增版本。去重使用内容签名：标题、正文、备注和内容块，移除 slide id 与 block id。设计换版会重新生成 id，但内容没变，因此不会污染版本历史。

每个项目最多保留 30 个版本，超出时丢弃最旧的快照。内容以文本为主，30 份快照的上限足以覆盖一次审核往返，又不会让项目文件无限增长。

### 差异按内容字段呈现

`diffContentVersion` 把选中版本与当前文稿逐页比较：

- 页面按稳定的 slide id 匹配。
- 页面集合不变时，索引变化报告为页序调整；有增删页时，不把后续页面的索引位移误报成移动。
- 标题、正文、演讲备注逐字段对比。
- 内容块按 block id 匹配；指标值、表格行列等以可读摘要呈现，不把整个对象 JSON 倒给用户。

UI 只提供查看，不提供"恢复此版本"。

## 备选方案

- **存到 SQLite 的应用历史表**：实现快照不需要 Schema 迁移，但历史不随项目文件移动，复制或换机后丢失；AI 草稿历史已经证明这类数据容易被误认为项目内容。
- **保存完整文档快照**：可以直接恢复版式，但设计变化会制造内容版本，文件体积也远大于文本快照。
- **直接对比撤销栈**：不持久，而且一次撤销项只覆盖一个事务，无法表达"上次确认的版本"。
- **提供恢复按钮**：恢复涉及内容、对象和版式，跨越内容与设计两个域；把它包装成一个内容命令会掩盖真实影响，超出本次范围。

## 影响

- Schema 升到 14，新增 `contentVersions` 可选字段和 13→14 迁移；迁移不伪造历史。
- 项目文件增加最多 30 份内容快照；单份快照只含文本和块数据。
- 旧文档第一次确认时生成第一个版本，不回溯填充。
- 内容块 id 被整体替换时，差异会显示为"删除旧块 + 新增新块"，而不是细粒度字段变化；这是按 id 匹配的已知边界。
- 表格差异以行列摘要呈现，不是单元格级 diff；单元格级回溯仍通过撤销完成。
- 版本不带墙钟时间，只带 revision；这样可以保持命令的确定性，UI 不显示"几分钟前"。
