# 0006 文件边界与模板处理加固

## 状态

已采纳（2026-10-21）。

## 背景

项目文件、PPTX 模板和渲染脚本都来自外部。此前的路径校验只要求绝对路径和扩展名，项目 JSON 读取没有大小上限，ZIP 只限制单个 XML/预览条目，PowerPoint 渲染进程没有超时；PPTX 写入还把完整字节数组序列化成 JSON。

## 决策

1. 文件路径在 Rust 端规范化父目录并拒绝符号链接目标；扩展名仍按命令限定。
2. 项目打开/恢复读取上限为 64 MiB。图片、导出和模板继续使用各自的显式上限。
3. PPTX ZIP 在解析 XML 前检查条目数（2048）、总解压大小（1 GiB）、绝对路径、`..`/`.` 段和 NUL 字符；导入时还要求 `[Content_Types].xml` 与 `ppt/presentation.xml`。
4. 模板渲染使用 `spawn` + `try_wait` 轮询，120 秒后通过 `taskkill /T /F` 终止进程树并返回 `TEMPLATE_LAYOUT_RENDER_TIMEOUT`。
5. 新增 `write_pptx_raw` 命令：前端把 PPTX 作为 `Uint8Array` 原始 IPC body 发送，路径放在 base64 编码的 `x-pptd-path` 请求头中，避免大体积 JSON 数组。旧 `write_pptx` 保留给测试和小调用方。
6. 前端保存使用互斥标记，自动保存/清除恢复快照通过串行队列执行；打开和保存后记录项目文件 mtime，保存前检测外部修改并要求确认覆盖。

## 影响

- 绝对路径仍允许用户通过系统对话框选择任意位置；这是桌面应用的用户授权路径，不是“任意路径自动可信”。更严格的 capability 授权需要后续由对话框插件直接签发路径凭据。
- ZIP 检查不解压内容，因此不是恶意 OOXML 的完整沙箱；XML 解析仍依赖 roxmltree 的结构校验和条目大小上限。
- 原始 IPC 路径通过请求头传递，Tauri 侧只接受 base64 编码，避免直接拼接文件名。
