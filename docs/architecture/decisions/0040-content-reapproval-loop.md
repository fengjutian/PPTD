# 0040：内容复核闭环（确认与退回审核）

## 状态

已接受（2026-10-23）。

## 背景

内容状态有五个值：`draft`、`review`、`approved`、`changed`、`needs_review`。实际运行时只有前三个会出现，而且只有一个方向：

- 应用 AI 草稿时页面写成 `approved`。
- 已确认页面被内容命令改动后变成 `changed`（`markContentChanged`）。

没有反方向的命令。于是用户改一个标题之后，这一页永远停在 `changed`：导出预检每次都报 `content-not-approved`，报告里那句"尚未完成审核"再也消不掉。用户唯一能让告警消失的办法是撤销自己的修改，等于删掉工作。

这不是提示太吵的问题，而是复核流程缺了一半：系统要求复核，却没有提供复核的入口。

## 决策

1. 新增两个内容域命令：
   - `approve-slide-content`：把目标页设为 `approved`。
   - `reopen-slide-content`：把目标页设为 `review`（退回审核，不是退回草稿——内容本身没变）。
2. 两个命令都只改 `slide.content.status`，不碰标题、正文、结构化块、备注、对象和页序。确认是复核动作，不是编辑动作。
3. 命令域为 `content`：文档 revision 和内容 revision 各 +1，设计 revision 不变。审核状态属于内容态，导出预检读的也是它。
4. 目标状态已经达成时命令返回 `null`（`commandDomain`），store 直接返回，不产生空撤销项。重复点"确认"不会让撤销栈变长。
5. 编辑器底部状态栏显示当前页的审核状态，并提供唯一动作：
   - 未确认（`draft` / `review` / `changed` / `needs_review`）→ "确认本页内容"。
   - 已确认（`approved`）→ "退回审核"。
6. 状态说明写"为什么现在不能导出"，而不是重复状态名；按钮的 title 说明动作后果。
7. 导出预检不变：非 `approved` 页面继续给出 `content-not-approved` 警告。闭环只负责让用户有办法消除它，不替用户确认。

## 结果

- 页面级复核形成闭环：`approved → changed → approved`，`approved → review → approved`。
- 确认和退回都进撤销栈：误点一次确认可以撤销，revision 也会回退。
- 审核状态不影响内容哈希（哈希排除审核状态），所以确认不会让页面在视觉/内容比对上看起来"变了"。
- 单元测试覆盖：状态迁移、命令域、内容与对象不变、重复确认不产生事务、未知页面抛 `SLIDE_NOT_FOUND`、store 的撤销与 revision 计数、状态栏的两种动作。

## 未覆盖与风险

- 只有逐页确认，没有"确认全部待确认页"的批量动作。批量确认等于替用户审核，暂不提供。
- 导出仍以警告而不是错误对待未确认页面：用户可以带着 `changed` 状态导出。这是既有产品选择（导出不能因为审核状态丢工作），本次不改。
- 指标卡数字仍然没有绑定内容块：在编辑器里改指标卡文字会被算作设计命令，不会把页面变成 `changed`。这属于另一个内容完整性问题，本次不动。
- 状态栏只显示当前页。整套文稿里还有多少页未确认，要在导出报告里看。
