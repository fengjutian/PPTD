# 0109 原生分组导出

## 状态

已接受（V0.2，2026-10-26）

## 背景

`Slide.groups` 自 [0051](0051-editor-selection-groups.md) 起是页面级选择组：成员仍是平铺的 `slide.elements`，只声明“这些对象一起选”。PptxGenJS 没有分组 API，之前的导出把成员写成独立原生对象，preflight 逐页提示 `group-not-exported`。

TRS 4.4.1 把“分组对象”列为支持对象，用户也期待在 PowerPoint 中继续把一组对象当作整体移动、缩放和取消组合。继续展平会丢掉这层编辑结构，但直接把成员 XML 包进 `<p:grpSp>` 又可能改变坐标、Z 序或生成 PowerPoint 需要修复的文件。

## 决策

### 在导出末尾后处理 `<p:grpSp>`

导出仍先用 PptxGenJS 写普通原生对象。所有按对象名或文档顺序定位的补丁（主题色、渐变、切换、动画、图片裁剪/形状）完成后，再由 `patchSlideGroups` 把成员包进 `<p:grpSp>`。

顺序是约束，不是偏好：

- 渐变和图片形状补丁按元素顺序找目标；
- 原生动画按 `p:cNvPr` 的 `name` 找 shape id；
- 先分组会让这些补丁找不到成员或把成员移出预期位置。

### 恒等子坐标系

组的 `a:off`/`a:ext` 与 `a:chOff`/`a:chExt` 取同一个外接框。成员自己的 `a:xfrm` 不改写，因此子空间到页面空间的映射是恒等变换，组合前后画面应逐像素一致。

外接框按成员旋转后的四角计算，避免旋转对象伸出组框。组框只承担选择和整体变换，不参与成员渲染。

### Z 序放在最前成员的位置

一个 `<p:grpSp>` 只能占一个 Z 位置。编辑期选择组的成员 Z 序可以不相邻；导出时把组放在最前成员的旧位置，成员在组内保持原相对顺序。这样最前面的成员仍覆盖它原来覆盖的对象，符合 PowerPoint 对非连续对象执行“组合”时的行为。较低成员会随组上移，这是原生分组的固有限制。

### 不能成组的成员整体回退

表格的 `p:cNvGraphicFramePr` 带 `a:graphicFrameLocks noGrp="1"`，PowerPoint 本身不允许把表格放进组合。含表格、嵌套组、找不到 XML 成员或缺少可导出成员（例如只在母版里的版式背景）的组不写入 `<p:grpSp>`，成员按独立原生对象导出，并计入 `nativeGroupSkipped`、写入导出报告。

图表补上 `objectName: element.id`，使 `graphicFrame` 能被组稳定寻址。图表动画仍不写入：它有名字不等于动画节点已经验证。

### 报告与回读

导出报告新增：

- `nativeGroupCount`：成功写入的原生组合数；
- `nativeGroupSkipped`：回退为独立对象的组数；
- 回退时追加一条用户可读警告。

`verifyExportedPptx` 仍只比对文字、图片、表格和图表数量；组合数量不做回读断言，因为“哪些组按规则必须回退”与导出映射共享同一套判断，容易把同一个盲点复制到校验器。组合结构由单元测试和真实 PowerPoint 打开验证。

## 验证

- `src/features/pptx-export/group-xml.test.ts`：恒等子坐标系、最前成员 Z 序、表格回退、缺失成员、多组、旋转外接框、无组时字节不变。
- `src/features/pptx-export/export-pptx.test.ts`：文本+形状原生组合、表格组合回退、图表+文本组合、图表动画仍跳过。
- 真实 PowerPoint 打开导出的组合页：`Shapes.Count` 从 4 变为 3，组对象 `Type = msoGroup`、`GroupItems.Count = 2`，未触修复；组页与未组页导出的 PNG SHA-256 完全一致。
- 全量 TypeScript 类型检查、测试、Lint 和生产构建通过。

## 后果

- 文本、形状、图片、图标和图表可以导出为 PowerPoint 原生组合；表格组合仍回退。
- 组整体缩放/旋转、嵌套组、组内进入/退出编辑、复制/粘贴携带分组仍不在模型内。
- 组合内对象的动画 XML 会保留，但动画在 PowerPoint 中的播放行为尚未逐项验证，不能在文档中声称已验证。
- 非连续 Z 序的组会按最前成员重新落位，和 PowerPoint 的组合行为一致，但与编辑期画布的绝对 Z 序可能有差异。

## 备选方案

- **继续展平**：实现最省事，但用户无法在 PowerPoint 中继续按组编辑，不符合分组对象的产品目标。
- **嵌套 group 元素**：模型更彻底，但要改渲染、命中测试、全部元素遍历、Schema 和复制粘贴，成本远超本次增量。
- **让 PptxGenJS 生成组**：当前版本没有分组 API；等待上游会阻塞交付。
- **直接包装而不处理表格/缺失成员**：会生成 PowerPoint 可能修复或拒绝的文件，违反“不夸大兼容能力”。
