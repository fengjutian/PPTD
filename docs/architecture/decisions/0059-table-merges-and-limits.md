# 0059 表格合并单元格与行列上限

## 状态

已接受（V0.2）

## 背景

原生表格此前只有表头和数据行两个字符串数组。导入 PPTX 时，合并单元格被拍平，超过 8 列或 30 行的表格被截断；画布和导出器也都没有“一块区域只画一次”的概念。用户看到的表格和源文件不是同一张表。

## 决策

### 合并区域是内容块上的显式数据

`table-data` 内容块新增可选的 `merges`：

```ts
interface TableMerge {
  section: "header" | "body";
  row: number;      // 区块内的行；表头固定为 0
  column: number;
  rowSpan: number;
  columnSpan: number;
}
```

覆盖区域内的普通单元格仍保留占位字符串，但渲染和导出都跳过它们，由左上角单元格承载内容与跨度。这样：

- 文本、编辑和内容哈希仍然只有一份；
- 画布、缩略图和导出读取同一份数据；
- 不需要为“被覆盖的单元格”发明第二套内容语义。

### 不变量

Schema 在当前文档上校验：

- `section` 只能是表头或表体；表头只有一行，跨行合并到表体被拒绝（导入器会把这种跨界的表头合并降级为单行并报告）。
- 合并区域不能越出表头列数或表体行数。
- 合并区域不能重叠。
- 跨度为 1 的记录没有意义，导入器不生成。

### 渲染与导出

- 画布 `TableView` 计算覆盖集合，只在左上角单元格写 `rowSpan`/`colSpan`。
- 导出把同一份覆盖集合交给 PptxGenJS：被覆盖的单元格从行数组里移除，左上角写 `colspan`/`rowspan`。PptxGenJS 按首行单元格的跨度累计列数，保留覆盖单元格会让它多分出一列。
- 导出后仍是原生 PowerPoint 表格，不是图片。

### 行列上限

表格上限从 8 列 × 30 行提高到 **12 列 × 50 行**，前端常量与 Rust 导入器保持一致。超过上限仍在导入报告里逐项说明，不是静默截断。

### 持久化

`merges` 是可选字段，与预设形状一起进入第 19 版；`18 → 19` 迁移只改版本号。没有合并的旧表格保持原样。

## 后果

- 导入的合并单元格不再被拍平；画布和导出的表格保持同一块区域。
- 用户可以在导入后的表格里编辑左上角单元格；被覆盖的单元格仍出现在内容块的原始数组中，但不会显示或导出，避免出现“编辑了却看不到”的第二个值。
- 表格结构（增删行列、手工合并/拆分）仍不是编辑命令；本决策只保证导入的合并结构与导出保真。
- 超大表仍会截断，但上限提高且报告明确。
- 导入器对跨表头/表体边界的合并、重叠合并会降级并报告，不生成 Schema 拒绝的文档。

## 验证

- Schema：越界合并和重叠合并被拒绝。
- 导入：Rust 读取 `gridSpan`/`rowSpan`，交给 TypeScript 写入 `merges`；跨界表头合并降级。
- 画布：合并区域只输出一个带 `colSpan`/`rowSpan` 的单元格。
- 导出：slide XML 出现 `gridSpan="2"`，包结构有效。
- 前端与 Rust 全量测试、类型检查、构建通过。
