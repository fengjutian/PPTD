# 0029：整册真实链路验证，中文标点规范化

## 状态

已接受（2026-10-22）。

## 背景

前面六波都在做同一件事：按推理补齐"AI PPT 一眼假"的各种成因。补到第六波时，**这些成因到底对不对，已经没有真实数据支撑了**。

这里有一处方法上的欠缺：所有验证都是**局部的**——测一个提示词返回什么、测一个适配器解析什么、测一个几何函数算得对不对。没有一次跑完整条链路、看真实产出长什么样。

于是先补这件事：用真实凭据、真实模型、真实图像接口，跑一遍完整的"大纲 → 正文 → 视觉设计 → 配图"，把每一步的产出打印出来看。

## 决策

### 整册真实链路测试

1. 新增 `src-tauri/src/ai/live_deck_tests.rs`：`#[ignore]` 的整册链路测试，默认不跑，需要网络与凭据，按张计费。
2. 测试跑完整链路并打印每一步：大纲标题、逐页正文、视觉设计参数、每张配图的格式与尺寸。
3. **断言只检查链路本身**（页数一致、每页有标题），不检查审美——好不好看要人看渲染图，测试不该假装自己能判断。

### 真实产出暴露的第一个问题：中文里的半角标点

4. 实测一整册六页，**四页的标题写成半角逗号**："Q2 营收达成预算目标,盈利能力出现结构性压力"。半角逗号夹在中文中间，整册看上去就是机器排的。
5. 这类毛病比配色难看更扎眼，因为它出现在每一页，而且读者说不出哪里不对，只觉得"廉价"。
6. 新增 `src/core/content/punctuation.ts`：`normalizeChinesePunctuation()` 把中文语境里的半角标点转成全角。
   - **不是无脑替换**。判断依据是相邻字符：半角标点两侧只要有一侧是中文就转，两侧都是拉丁字母或数字就不动。"12,345"不是标点，"Revenue, net"也不是。
   - 括号成对处理，不会留下"（abc)"这种半边。
7. 新增 `src/services/ai-draft-normalize.ts`：`normalizeDraftPunctuation()` 规范化整份草稿——文稿标题、逐页标题、正文、备注、页面计划、以及所有内容块里的文字。
8. **规范化只作用在模型刚产出、用户还没看到的文本上**（`generatePresentationDraft` 返回前）。用户自己敲的半角逗号是他自己的表达，替他改掉是越界；历史草稿同理，里面可能有用户的编辑。
9. 规则表写进共享资产 `assets/content-lexicon.json` 的 `punctuation` 段，Rust 侧新增 `punctuation_rules_prompt()` 写进三个生成提示（一次性草稿、大纲、分批正文）。**提示要求模型写全角，前端按同一张表规范化**，与词表的同源原则一致。

### 连带修好的问题：半角逗号污染句式指纹

10. 词表的连接词里含 `,`，于是半角逗号被当成了句法连接词，四页标题被判成"共用同一句法骨架"。
11. 规范化之后，指纹里不再出现半角标点。
12. 但**重复信号本身是真的**：规范化后这四页仍然是 `2|，` 结构。这不是误报，是整册标题确实结构雷同——检测端说的是真话。

## 结果

- 整册真实链路跑通：220 秒，六页标题、六页正文、六页视觉设计、六张配图全部产出，配图全部成功（1024×768 / 1024×512 / 2048×512，JPEG）。
- 真实产出的标题质量明显改善：全部是结论式判断（"客流同比回暖未能完全对冲客单价下行"），没有出现"现状分析""市场概述"这类栏目名——第五波的词表纪律确实生效了。
- 半角标点问题修掉，规则与检测同源。

## 未覆盖与风险

- 整册链路测试仍然是 `#[ignore]`，厂商改协议或模型行为变化时不会被自动发现。
- 标点规范化目前只覆盖模型产出。历史草稿和用户手输的文本不处理。
- 半角标点的判断依据是"相邻字符是否为中文"，遇到中英混排的边缘情况（如 "营收12,345万元" 里的逗号两侧都不是中文）会保留半角——这是有意的：千分位比标点更常见。
- 生成图的内容合规性仍无自动检查。
- 配图只服务于 AI 设计流程，手工编辑路径没有配图入口。
