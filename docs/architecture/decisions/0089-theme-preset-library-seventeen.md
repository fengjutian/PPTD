# 0089：主题预设库扩到 17 套

## 状态

已接受（2026-10-25）。延续 [ADR 0033](0033-preset-library-expansion.md)：结构不变，只扩充主题资产与推断规则。

## 背景

主题选择器现有 11 套预设，覆盖人文、通用、商务、叙事、科技、金融、医疗、政务、创意与教育。用户在实际选题里仍会遇到没有对应气质的情况：学术答辩、法律合规、制造业与工程、建筑与地产、时尚消费、极简作品集。这些题材落到现有预设上会被硬塞进“商务”或“创意”，配色与字体描述都说得通，但整册观感区分不出来。

预设库是数据驱动的：每套预设只声明色板、字体配对与字阶，渲染路径完全共用。因此补预设是拉开学派差异成本最低的做法，不需要改版式代码。

## 决策

新增 6 套预设，沿用 `ThemePreset` 的同一结构（7 个色板槽位 + 标题/正文字体 + 字阶 + 标题字距）：

| id                   | 名称     | 气质                       | 强调色    | 主要场景                     |
| -------------------- | -------- | -------------------------- | --------- | ---------------------------- |
| `academic-indigo`    | 学术靛   | 暖白、深靛、砖红、宋体     | `#2E4A7D` | 论文答辩、课题汇报、学术会议 |
| `minimal-gray`       | 极简灰   | 纯白、灰阶、黑体、黄铜点缀 | `#333333` | 作品集、品牌手册、摄影集     |
| `legal-burgundy`     | 法务酒红 | 象牙白、酒红、深灰、宋体   | `#7B2D3B` | 法律意见、合规、审计、风控   |
| `fashion-rose`       | 时尚玫   | 暖白、玫红、炭黑、黑体大字 | `#B03A5B` | 时尚发布、美妆、消费品牌     |
| `industrial-steel`   | 钢蓝     | 冷灰、钢蓝、安全橙、黑体   | `#35566B` | 制造、汽车、工程、供应链     |
| `architecture-stone` | 石筑     | 暖石色、铜棕、墨色、宋体   | `#7A6A57` | 建筑、地产、室内、城市更新   |

同时：

1. 为 6 套预设补齐 `theme-preset-metadata.ts` 的设计方向元数据（适用场景、受众、推荐页型、密度、图片方向、图表色、禁止组合）。
2. 为 6 套预设补齐 `theme-preset-guidance.ts` 的人工指引文案，保持选择器详情、AI 提示词与元数据一致。
3. 扩展 `inferThemePresetId`：新增学术、法律合规、时尚消费、制造工程、建筑地产、极简作品集六类关键词；原有“教学 → 纸墨、汇报 → 藏青、展陈 → 素纸”等映射不变。推断只用于推荐，不自动覆盖用户已选主题。
4. 新增元数据完整性测试：每套预设必须在 `THEME_PRESET_METADATA` 中有显式条目，防止漏配后静默落到 fallback。

所有新预设的 `surface` 保持浅色：渲染器目前以浅底 + 深色正文为对比度前提，深色主题需要单独的表面策略，不在这轮范围内。

## 后果

正面：

- 选择器从 11 套增加到 17 套；卡片、详情抽屉、`THEME_PRESETS.length` 计数和 8 页样张自动纳入新预设，无需改 UI。
- 六个此前只能“近似归类”的题材有了专属配色与字体气质，主题推断的推荐也更准。
- 元数据测试从“有 fallback 就算通过”改为“必须显式配置”，新增预设漏配会直接失败。

代价与限制：

- 选择器变成 17 张卡片，首屏需要滚动；后续若要继续扩张，应增加按场景筛选而不是无限加卡片。
- 新增预设只保证色板、字体与字阶不同，没有视觉回归基线；观感仍需人工抽查样张。
- 推断规则按关键词顺序匹配，`方案`、`品牌`、`活动` 等泛词仍可能先命中更早的规则（例如“工程方案”会命中商务汇报）。推断只是推荐按钮的依据，用户可改选。
- 仍无深色主题：需要渲染器先定义深色表面的正文/标题对比规则。

## 备选方案

- **只加预设、不补元数据与指引**：选择器能显示，但详情抽屉与 AI 提示词会落到通用 fallback，等于新预设对设计模型不可见；不采用。
- **新增深色主题（暗夜、黑金）**：视觉差异最大，但现有渲染与对比度检查假设浅色表面，需先改表面策略；暂不采用。
- **按行业自动选预设**：推断仍只作为推荐，不自动覆盖用户选择，避免与“设计不改变已审核内容与用户决定”的边界冲突。
- **让用户自定义预设并持久化**：需要新的持久化模型、编辑 UI 与迁移；本轮先验证“内置库继续扩充”是否足够。
