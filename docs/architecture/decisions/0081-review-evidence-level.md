# 0081 视觉评审的证据等级

## 状态

已接受（2026-10-24）。

## 背景

报告里写着“视觉评审通过”，但这句话背后可能是三种完全不同的证据：

1. 导出的 PPTX 被 PowerPoint 真实渲染后评审；
2. 本机没有 PowerPoint，评审看的是画布近似重绘；
3. 视觉评审根本没运行，只有确定性校验。

三者被同一个“通过”覆盖，会把近似预览当成最终画面，也会把“没评审”误读成“检查过了”。

## 决策

### 1. 结论携带证据，而不是另加一个开关

`DesignQualityStageResult.visualEvidence`：

```ts
interface ReviewEvidence {
  renderer: "powerpoint" | "canvas" | "none";
  evidence: "final" | "layout" | "indicator";
  reason?: string;
}
```

- `powerpoint` + `final`：PowerPoint 渲染导出的 PPTX，最接近用户最终看到的画面。
- `canvas` + `layout`：画布近似重绘；断行、字体度量、图表与表格由画布估算，不是最终结果。
- `none` + `indicator`：没有视觉评审，只有确定性检查。

### 2. 证据跟随“被采用的结论”，不跟随最后一次尝试

评审循环可能回退到更早一轮的更高分设计。证据等级取自 `aligned.bestIteration` 对应的 `ReviewRound`，而不是最后一轮渲染。否则会出现“采用画布结论，却报告 PowerPoint 最终渲染”的错误。

真实渲染失败时保留失败原因；报告显示“画布近似渲染；真实渲染不可用”，不假装重试成功。

### 3. 只报告，不改变通过判定

证据等级不参与 `visualPassed` 的计算，也不阻断生成。它回答的是“这个结论有多可信”，不是“要不要交付”。画布评审仍然可以达标，但报告必须让用户知道它不是最终画面。

### 4. 界面

设计质量报告顶部显示“评审依据：…”：

- “PowerPoint 真实渲染导出文稿（最终画面）”；
- “画布近似渲染（版式预览，非最终断行与字体度量）；真实渲染不可用”；
- “仅确定性校验（视觉评审未运行）”。

### 5. 当前只支持两种渲染器

后端目前只有 PowerPoint COM 栅格化与前端画布渲染，没有 LibreOffice 路径。类型保留 `renderer` 字段，是为了以后接入第三种渲染器时不改报告合同；当前不得声称支持 LibreOffice 评审。

## 后果

正面：

- “视觉评审通过”不再掩盖证据来源。
- 采用回退轮次时，证据与结论一一对应，报告可审计。
- 用户能区分“画布上看着没问题”和“PowerPoint 里没问题”。

代价与限制：

- 画布评审的分数仍然可用于修复；证据等级只影响解释，不影响自动修复。
- 手工复检也携带证据等级，但仍受同一渲染器限制：没有 PowerPoint 时只能是画布。
- 没有 LibreOffice/跨平台渲染，macOS 与 Linux 上真实渲染不可用，只能报告 `canvas/layout`。

## 验证

- `design-quality-stage.test.ts`：真实渲染 → `powerpoint/final`；渲染失败降级 → `canvas/layout`；关闭视觉评审 → `none/indicator`。
- 全量测试、类型检查、ESLint、生产构建通过。

## 备选方案

- **只加一句“可能来自画布”**：不可审计，也无法在报告中按等级过滤。
- **画布评审不算通过**：会让没有 PowerPoint 的环境完全失去视觉评审，代价大于收益。
- **把证据等级塞进分数**：评分语义被污染；证据是元数据，不是分数。
- **用 LibreOffice 冒充 PowerPoint**：两者断行和字体不同，必须单独标注渲染器，不能合并。
