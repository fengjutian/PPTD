# 0048 页面尺寸修改不自动缩放对象

## 状态

已接受（V0.2）

## 背景

TRS 4.4.4 要求“设计”功能区提供页面尺寸。编辑器的文档模型已经有 `pageSize`，但只有只读展示，没有修改命令。用户在新建 16:9 文稿后无法改成 4:3，也无法调整导入模板的页面。

修改页面尺寸有两种常见策略：只改画布尺寸，或把现有对象按比例缩放到新页面。两者对已审核内容的影响完全不同。

## 决策

### 默认只改页面，显式勾选才缩放对象

`set-page-size` 只替换 `document.pageSize`。元素坐标、尺寸、字号、图片裁剪和内容都不变。

理由：

- 缩放对象会改变版面构图和文字字号，等于一次隐式重排版；用户没有在命令里表达这个意图。
- 内容审核锁定的是文字，不是坐标，但字号和位置被静默改变仍然会让已确认的页面“看起来变了”。
- PowerPoint 的“幻灯片大小”对话框也把“确保适合/最大化”作为单独选择；默认只改尺寸。

页面变小后跑到页外的对象由控件计数和导出预检提示，用户自己移动或撤销。

### 2026-10-23 补充：显式的 `scaleObjects`

“设计”功能区新增“缩放对象”复选框（默认不勾）。勾选后，同一个 `set-page-size` 命令在改尺寸的同时按新旧页面比例缩放对象：

- 坐标和宽高分别用宽、高两个比例，保持对象在新页面中的相对位置。
- 字号、字距、描边宽度、圆角、表格内边距和边框宽度用较小的那个比例，避免非等比换页把字形拉扁或让文字溢出较窄的一边。
- 内容（标题、正文、表格单元格、指标值、备注）不参与缩放；这仍然是一次 Design Model 变更，内容版本和审核状态不变。
- 仍是一个命令、一个撤销项。复选框本身就是“用户表达了缩放意图”的证据，不需要再拆成第二条命令。

不勾选时行为与原先完全一致。

### 尺寸边界与 PowerPoint 一致

宽度和高度必须在 1–56 英寸之间，且换算后是安全整数 EMU。超出边界或出现小数 EMU 时命令返回 `INVALID_PAGE_SIZE`，不写入文档。

这样编辑器接受的页面在 PowerPoint 里一定能打开和继续编辑，也不会因为坐标不是整数而导致导出偏移。

### 设计域命令

页面尺寸属于 Design Model。命令只递增设计 revision 和文档 revision，内容版本、内容哈希、审核状态保持不变。一次修改一个撤销项。

### 预设与自定义共用同一入口

16:9、4:3、16:10 只是 `pageSizeFromInches` 的快捷值；预设按钮和宽高输入最终都调用同一个 `set-page-size`。属性面板保持只读，避免两个写入口显示不同状态。

## 后果

- 改尺寸是可撤销、可预期的设计操作，不会悄悄重排版。
- 需要“确保适合”的用户勾选“缩放对象”即可，不需要逐个手动调整；默认仍是只换纸张。
- 缩放只处理几何和视觉尺寸，文本的局部强调（runs）偏移不变；图片裁剪参数不变，非等比换页会把图片拉成新比例。
- 模板母版和版式背景按原坐标绘制，换尺寸不会重建；导入模板的文稿建议保持原尺寸。

## 备选方案

- **按比例缩放所有元素**：会把字号、线宽和图片裁剪一起改掉，无法区分“我想换纸张”和“我想重排版”。
- **自动调用 relayout**：会重建整页对象，可能覆盖手工对象和配图，与既有 `relayout-slide` 的保留规则冲突。
- **允许任意尺寸**：PowerPoint 会拒绝或修复文件，等于把兼容性问题推到导出之后。
