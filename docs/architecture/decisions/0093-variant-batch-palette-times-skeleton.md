# 0093：批量版本配对「配色 × 骨架」，不再共用一套版面

## 状态

已接受（2026-10-25）。修订 [ADR 0091](0091-batch-design-variants.md) 第 4 条的实现方式：批量仍然只跑到设计为止，但每一版不再共用同一个设计方向。

## 背景

ADR 0091 把批量版本定义为"AI 选模板"，实现时为了"让比较只关于配色"而让整批共用一个 `DeckConcept`（`generateVariantBatch` 里一条注释写明"One skeleton for the whole batch"）。实际反馈是：六张卡看起来是同一份稿子，用户分不清它们在比什么。

当时这个取舍有两个代价，其中一个已经变成事实错误：

1. **六版只有配色和字体不同**，页面通用同一套配方与同一个版心、字阶。用户以为在选六种版面，实际只在选六个色号，正是 [ADR 0087](0087-four-renderable-directions.md) 明确拒绝的"同一骨架换色"。
2. **封面 bug 让配色差异也消失了。** 深色节拍页把"这页的强调墨"（近白）当成面板底色，六套主题的封面因此都是同一条灰阶渐变（见本仓库上一轮修复：`panel` 颜色角色）。最大的视觉面积被统一成灰色，卡片自然一模一样。

## 决策

1. **每张卡一对「主题 × 骨架」。** `variantConceptPresetId(base, index)`：第 0 张保留模型推荐的方向（AI 推荐的卡仍然是模型选的），其余按下标轮转四个可渲染预设（editorial → documentary → paper → instrument）。轮转是确定性的：同一份稿子每次得到同样的卡，相邻两张不会既同色又同构。
2. **一张卡走完整条设计链。** 每个版本的设计调用、`apply-ai-designed-draft`、问题数测量、两页预览、整册预览都用这张卡自己的 `concept`；`prepared` 续跑本来就带 `{ presetId, concept, design }`，选中的那一版不会因为续跑而换骨架。
3. **卡片标题写明两件事。** 名称改为「配色 · 骨架」（例如「科技蓝 · 数据仪表」），画廊副标题改为「N 组『配色 × 版面』」，进度详情按「配色 · 骨架 · 推荐理由」逐版显示。用户能直接读出差异来自哪里。
4. **不增加模型调用。** 方向仍在一次概念调用后由代码展开；四个骨架的 `resolveDeckConcept` 是纯函数，按需缓存。批量成本仍是每版一次设计调用。

## 结果

- 六张卡的差异从"色号"变成"配色 + 版心 + 标题轴 + 字阶 + 图像角色"，与方向门（ADR 0087）表达同一件事。
- 封面修复后，六套主题的封面重新变成各自的品牌色，卡片第一眼即可分辨。
- 新增测试：`variantConceptPresetId` 的起点、轮转、相邻不重复、循环长度；既有方向门与配方测试不变。

## 未覆盖

- 四个骨架仍然共用同一套页面配方。`paper` / `instrument` 的差异是版心（0.17 / 0.22）、标题轴、竖线与字阶，不是新的页面构图；ADR 0087 的"未覆盖"在这里依然成立。要让六张卡在**构图**上也互不相同，需要新增配方，而不是改批量逻辑。（2026-10-25 补：[ADR 0094](0094-direction-owned-compositions.md) 为 `paper` 与 `instrument` 各加了一条自有配方，纯文字与短要点页已有方向自己的构图；表格、图表、指标页仍走共享配方。）
- `documentary` 的差异主要来自图片角色；批量不生成配图，所以它在画廊里只表现为更小的页边距，视觉差距弱于其他三个。
- 轮转不看内容适配（例如长文稿配到 `instrument`）。骨架与内容不匹配时，用户仍可切到别的卡或返回重选，这一版不会被静默保留。
