# 0111：批量版本独立创作与质量提交门

## 状态

已接受（2026-10-26）。

## 背景

批量生成此前只调用一次整册概念，再按序号轮换预设骨架。八张候选虽然都执行了逐页设计，仍共享同一个创意起点；其中一版的配图还会被其他版本复用。这使“八个版本”更接近换主题和换骨架，而不是八次独立创作。

最终生成的质量阶段此前只产生报告。即使确定性排版检查、视觉覆盖或视觉评分失败，候选文档仍会替换当前项目并写入历史。这把质量门降成了事后提示，也破坏了失败不改变项目状态的预期。

## 决策

1. 每个批量候选分别执行一次整册概念生成和一次逐页设计，不共享基础概念，不按序号机械轮换骨架。
2. 批量请求最多三路并发。并发只缩短等待时间，不共享候选状态；任一候选失败不取消其他候选。
3. 批量候选在进入画廊前构建真实文档并运行确定性质量门。存在文本溢出、重叠、低对比、越界或严重空洞的候选直接淘汰。
4. 批量预览使用每个设计自己的图片意图占位。真实图片只在用户选定版本后生成，避免让其他候选继承第一版的图像策略，也避免为最终丢弃的版本支付图片生成成本。
5. 最终质量阶段是项目状态的提交边界。只有确定性质量门通过、要求的视觉评审覆盖完整且视觉目标达标时，候选文档才可替换当前项目、写入 AI 历史、记录设计记忆并进入编辑器。
6. 质量未通过时保留当前项目，打开质量报告并将工作流标记为失败；失败候选不作为项目版本保存。

## 结果

- “八个版本”表示八次独立的整册设计决策，而不是一个概念的八种换皮。
- 候选画廊只展示通过确定性排版检查的版本，因此实际可展示数量可能少于请求数量；界面继续报告失败数量，不用低质量候选补足名额。
- 视觉模型不可用时仍可依靠确定性质量门交付；如果视觉评审已经启用并执行，则覆盖不完整或评分不达标都不能提交。
- 失败生成不会改变当前文档、项目路径、历史或设计记忆。

## 后续

配方数量不是设计能力的唯一尺度。后续扩展应采用“语义原语 + 可组合区域 + 约束求解 + 少量高价值配方”的方式，并为每个新增能力提供容量、内容消费和视觉回归测试；不得直接开放任意坐标让模型绕过领域不变量。
