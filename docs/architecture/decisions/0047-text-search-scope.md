# 0047 查找替换的搜索范围与写回边界

## 状态

已接受（V0.2）

## 背景

TRS 4.4.4 要求“开始”功能区提供查找和替换。编辑器的文本分布在多个位置：普通文本框、绑定了内容块的标题/正文、指标卡片、表格单元格、图表标签、演讲备注，以及文档标题。

如果把这些位置都当成一个字符串池来搜，替换时就会遇到不同的写回规则：表格单元格要走 `set-table-cell`，演讲备注要走 `set-speaker-notes`，标题要走 `edit-text`，图表标签来自内容块而不是元素。一个“全部替换”可能在用户不知情时同时改动内容、设计、备注和图表数据。

## 决策

### 搜索所有承载文案的位置

查找覆盖五类目标，每类保留自己的类型，而不是压成一个字符串池：

- 文本元素：`SlideElement.type === "text"` 的 `text`。
- 表格单元格：表格元素指向的 `table-data` 块的表头和数据行。
- 图表字段：图表元素引用的 `metric` 块的标签和值，也就是图表的分类与数据标签。
- 演讲备注：`slide.content.speakerNotes`。
- 文档标题：`PresentationDocument.title`。

理由：这些位置各自的单目标写回命令已经稳定（`edit-text`、`set-table-cell`、`set-metric`、`set-speaker-notes`、`rename-document`）。批量替换复用同一套校验，才能解释清楚“替换全部”到底改了哪些内容。

### 一个字段只替换一次

同一个 `metric` 字段可能既被指标卡渲染、又被图表引用；同一个 `table-data` 块也可能被两个表格元素引用。搜索按“页面 + 块 + 字段/单元格”去重：指标卡已经覆盖的字段不再作为图表字段出现，共享表格块也只保留第一个表格元素的结果。因此“全部替换”不会把同一个值写两遍，也不会出现两个结果指向同一处修改。

### 替换全部按目标生成一条编辑

`buildReplaceAllEdits` 先按目标计算完整的新文本，再去重。逐条替换会在第一次替换后改变后续匹配的偏移，也可能会把同一个目标写多次。生成的编辑数组交给一个命令执行。

### 每种目标沿用单目标命令的校验

`replace-text-edits` 在写入前解析并验证整批目标：

- 文本元素和表格元素被锁定则整批拒绝，不绕过锁定。
- 表格单元格必须在表头/数据行范围内，长度上限与 `set-table-cell` 一致。
- 图表字段必须属于该图表引用的 metric 块，长度上限与 `set-metric` 一致。
- 备注沿用 `set-speaker-notes`，标题沿用 `rename-document`（去首尾空白、非空、512 字符上限）。

任何一条目标失效都整批拒绝，不留下半替换的文档。

### 批量命令是一个事务

新增 `replace-text-edits`，先校验所有目标再写入。全部替换只产生一个撤销项；如果目标 id 已失效，整批拒绝，不留下半替换的文档。

命令的域名按目标逐条计算：标题/正文/指标卡片算内容，普通文本算设计，两者都有返回 `both`，因此一次替换的 revision 增量与实际影响一致。

### 内容写回复用同一套规则

`edit-text` 与批量替换共用 `applyTextEdit`：

- 标题/正文同步到 `slide.content`，正文重建段落块。
- 指标卡片同步内容块与同字段的其他卡片。
- 旧 runs 被清空，因为它们指向旧文本的偏移。
- 内容绑定页从 `approved` 变为 `changed`。

这条约束保证“查找替换”不是一条绕过内容审核的旁路。

## 后果

- 全量替换可以安全撤销，并如实更新内容版本和审核状态。
- 结果列表按目标类型显示“文本 / 表格 / 图表 / 备注 / 文档标题”，替换状态按位置计数。
- 替换会丢失文本的局部强调（runs），与手动修改文本一致；表格、图表字段、备注和标题本来就没有局部强调。
- 锁定对象的命中仍会出现在结果里，但替换会跳过并在状态栏说明，而不是静默忽略。
- 文本元素与表格/图表字段共享同一个内容块时，以先出现的渲染目标为准，避免重复写回。

## 备选方案

- **搜索整个文档 JSON 的字符串**：会命中 id、样式颜色和内部字段，无法安全写回。
- **逐条调用 `edit-text`**：每条一个撤销项，且偏移在替换后失效。
- **全部替换用 `replaceAll` 直接改内容块**：会绕过 `applyTextEdit` 的同步与审核规则，造成卡片、正文和指标值不一致。
