# 0047 查找替换的搜索范围与写回边界

## 状态

已接受（V0.2）

## 背景

TRS 4.4.4 要求“开始”功能区提供查找和替换。编辑器的文本分布在多个位置：普通文本框、绑定了内容块的标题/正文、指标卡片、表格单元格、图表标签、演讲备注，以及文档标题。

如果把这些位置都当成一个字符串池来搜，替换时就会遇到不同的写回规则：表格单元格要走 `set-table-cell`，演讲备注要走 `set-speaker-notes`，标题要走 `edit-text`，图表标签来自内容块而不是元素。一个“全部替换”可能在用户不知情时同时改动内容、设计、备注和图表数据。

## 决策

### 只搜索文本元素

V0.2 的查找替换只覆盖 `SlideElement.type === "text"` 的 `text` 字段。表格、图表标签、演讲备注和文档标题明确不在范围内。

理由：文本元素的写回路径已经统一到 `edit-text` 的语义（同步内容、清空旧 runs、标记审核状态）。其他位置需要各自的命令和校验，混在一个“替换全部”里无法解释到底改了什么。等每一类都有稳定的批量写回协议后，再扩展搜索范围。

### 替换全部按元素生成一条编辑

`buildReplaceAllEdits` 先按元素计算完整的新文本，再去重。逐条替换会在第一次替换后改变后续匹配的偏移，也可能会把同一个元素写多次。生成的编辑数组交给一个命令执行。

### 批量命令是一个事务

新增 `replace-text-edits`，先校验所有目标再写入。全部替换只产生一个撤销项；如果目标 id 已失效，整批拒绝，不留下半替换的文档。

命令的域名按目标逐条计算：标题/正文/指标卡片算内容，普通文本算设计，两者都有返回 `both`，因此一次替换的 revision 增量与实际影响一致。

### 内容写回复用同一套规则

`edit-text` 与批量替换共用 `applyTextEdit`：

- 标题/正文同步到 `slide.content`，正文重建段落块。
- 指标卡片同步内容块与同字段的其他卡片。
- 旧 runs 被清空，因为它们指向旧文本的偏移。
- 内容绑定页从 `approved` 变为 `changed`。

这条约束保证“查找替换”不是一条绕过内容审核的旁路。

## 后果

- 全量替换可以安全撤销，并如实更新内容版本和审核状态。
- 搜索范围小于“看起来的所有文字”，UI 的结果列表只展示文本元素；用户不会误以为备注或表格也被替换。
- 替换会丢失局部强调（runs），与手动修改文本一致。
- 表格/图表/备注/文档标题的搜索需要各自的任务与写回协议。

## 备选方案

- **搜索整个文档 JSON 的字符串**：会命中 id、样式颜色和内部字段，无法安全写回。
- **逐条调用 `edit-text`**：每条一个撤销项，且偏移在替换后失效。
- **全部替换用 `replaceAll` 直接改内容块**：会绕过 `applyTextEdit` 的同步与审核规则，造成卡片、正文和指标值不一致。
