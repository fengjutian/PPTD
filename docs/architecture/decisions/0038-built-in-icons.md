# 0038：内置图标元素

## 状态

已接受（2026-10-23）。

## 背景

卡片页的编号徽标是通用装饰：同样的圆点出现在每一页，只能说"第几条"，说不出"这一条讲什么"。open-ppt-skill 的规范里有独立的 Icon 元素；我们借这个思路，但只做一套受控的线性图标，并且只在文案明确指向某个概念时才使用。

## 决策

1. 新增 `IconElement`：`{ type: "icon", name, style: { color, strokeWidth? } }`。元素只存**图标名**，路径数据来自内置注册表；schema 用枚举校验名称，损坏的文件无法注入任意 SVG。
2. 内置 12 个图标：book、mountain、water、sun、moon、target、chart、users、bulb、flag、heart、leaf。全部是 24×24 网格上的描边图形。
3. 画布用 React 从注册表重建 `<svg>`，不注入 HTML；导出写**原生自定义几何形状**（DrawingML `a:custGeom`），每个图标是一个可编辑的矢量形状，不产生图片 part。
4. 生成器只在网格/卡片页使用图标：条目文案命中明确名词（目标、数据、团队、文本、方法、里程碑、情感、山、水、阳光、夜晚、自然）时，用图标替换编号徽标；否则保留编号。单字匹配（"人""心"）一律不用，避免把"知人论世"配成团队图标。
5. 图标继承强调色底：圆底用 `accentFill`，图标描边按底色明度取白或深墨。

## 结果

- 卡片页第一次有语义图标：目标/数据等条目看到图形，其余仍是编号。
- 图标在画布上是矢量、在 PPTX 里是可编辑的原生矢量形状；两种渲染结果一致。
- 新增或更新了测试：注册表可绘制、路径解析到有限坐标、按框缩放、闭合子路径、文案映射、画布 SVG、导出为 `custGeom` 且不产生图片 part、生成器替换编号。

## 未覆盖

- 导出的是原生矢量形状，但一个图标仍是一个整体：要单独改某一条线的颜色，需要先拆分形状。
- PptxGenJS 不暴露线端/拐角样式，当前使用 PowerPoint 默认值；与画布 SVG 的 round cap/join 有细微差异。
- 图标集只有 12 个，且为人工挑选；没有按行业扩展。
- 匹配仍是关键词启发式，中英混排、同义词没有覆盖。
- 插入位置仍是固定的默认坐标；属性面板可以换图标、颜色和线宽，但不能拖动以外的方式定位。

## 修订：为什么不再写 SVG 图片（2026-10-23）

PptxGenJS 4.0.0 处理 SVG 图片时会生成两个媒体 part：一个 SVG 和一个 PNG 预览。预览 part 在 Node/Worker 中没有可用的 canvas，写进去的实际上是 SVG 字节；PowerPoint 把这个 `.png` 当作损坏图片，整个文件拒绝打开。原测试只断言 `.svg` part 存在，没有检查 PNG 预览，也没有用 PowerPoint 打开过文件，所以问题一直没暴露。

修复改为把图标路径解析成 DrawingML 自定义几何：`iconOutline()` 把 M/L/H/V/C/S/Q/T/A/Z（含相对指令和圆弧）转成三次贝塞尔点，导出器为每个图标写一个 `a:custGeom` 形状，`a:noFill` + 描边。它不经过 PptxGenJS 的 SVG 预览分支，不产生任何图片 part，因此在主线程、Worker 和 Node 测试里走同一条路径。PowerPoint 已实际打开并渲染 12 个图标验证。
