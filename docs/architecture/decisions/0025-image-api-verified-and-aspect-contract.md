# 0025：图像接口按真实响应校正，图与框的比例是同一份契约

## 状态

已接受（2026-10-22）。

## 背景

ADR 0024 落地了视觉素材层，但整套实现是**照着官方文档写的，没有跑过一次真实请求**。文档会变，厂商会改字段名，图片也可能放在文档没提的地方。

更需要修的是一处设计缺陷：请求图片的尺寸和排版留的图框，各写各的。

- 前端请求的尺寸是随手写的：通栏 16:9，其余正方形。
- 图框由排版引擎按页面几何算出来：通栏约 7.3:1，侧栏约 2.26:1。

两边对不上，填充裁剪（`coverCrop`）就不得不切掉大量画面。实测：

| 角色 | 图框比例 | 请求比例 | 画面保留率 |
|---|---|---|---|
| hero | 1.35 | 1.00 | 74.3% |
| side | 2.26 | 1.00 | 44.2% |
| band | 7.28 | 1.78 | **24.4%** |

四分之三的画面被切掉，正是"AI 配图一眼假"最直接的来源。而且裁剪越狠，越像随手贴的素材。

## 决策

### 按真实响应校正适配器

1. 新增 `src-tauri/src/ai/live_image_tests.rs`：三个 `#[ignore]` 的真实调用测试，默认不跑，需要网络与本机凭据，且按张计费。命令 `cargo test --lib live -- --ignored --nocapture`。
   - `probe_the_live_response_shape` 打印真实响应的字段结构。
   - `generates_a_real_image_through_the_full_pipeline` 走完整链路：请求 → 解析 → 下载 → 嗅探格式与尺寸。
   - `honours_an_explicit_pixel_size` 验证显式 `width`/`height` 真的优先于 `aspect_ratio`。
2. 真实响应与文档一致的部分：顶层 `id` / `data` / `metadata` / `base_resp`，`data.image_urls`，`base_resp.status_code = 0`。
3. **文档没写对的部分**：图片不在厂商自己的 CDN 上，而在阿里云 OSS 的 `hailuo-image-algeng-data` 桶里（区域端点 `oss-cn-wulanchabu.aliyuncs.com`），且是**签名地址**（带 `Expires` 与 `Signature`）。
   - 下载白名单新增 `ALLOWED_OSS_ENDPOINT_SUFFIXES`，只放行这一个区域端点，**不是整个 `aliyuncs.com`**——放行整个云厂商域名等于允许厂商把请求引到任意人的桶上，等于没有白名单。
   - 签名参数属于凭据，测试日志只打印主机与路径，不打印查询串。
4. 真实返回的是 **JPEG**，不是 PNG。适配器的 `detect_image_mime` 按字节嗅探，本来就正确；前端 `App.tsx` 的 mimeType 映射也已覆盖 `image/jpeg`。
5. 显式 `width`/`height` 确实优先于 `aspect_ratio`，且**严格按请求尺寸出图**：实测 1024×1024、1280×720、2048×512 三个尺寸全部原样返回。

### 图与框的比例是同一份契约

6. 新增 `VISUAL_ASSET_REQUEST_SIZE`（请求尺寸）与 `VISUAL_ASSET_ASPECT`（图框比例），两者由同一组角色定义：hero 4:3、side 2:1、band 4:1。前端按前者请求，排版引擎按后者留框。
7. `planVisualAssetLayout` 改在**像素里**算框，不再在归一化坐标里算：归一化坐标的宽高比不等于像素宽高比（页面是 16:9，宽按页宽、高按页高），照归一化算出来的框放进页面就不是想要的比例。函数签名相应增加 `pageWidthEmu` / `pageHeightEmu`。
8. 尺寸受厂商限制：边长在 [512, 2048] 之间且是 8 的倍数，所以最宽比例是 4:1（2048×512）。通栏角色最多 4:1。
9. 校正后实测三个角色的画面保留率均为 **100%**，填充裁剪不再需要切任何像素。

## 结果

- 图像接口从"照文档写的"变成"跑过真实请求的"。CDN 白名单、MIME 嗅探、显式尺寸这三个最容易错的地方，现在都有真实响应兜底。
- 配图不再被裁掉四分之三。修正前后实测：hero 74.3% → 100%，side 44.2% → 100%，band 24.4% → 100%。
- 端到端验证跑通：真实生成的 JPEG（75946 字节，1024×768）落进文档模型 → 导出 PPTX → PowerPoint COM 渲染，图片在右侧、文字让位到左侧、无裁剪无变形，导出报告 `croppedImages: 0`、`package.valid: true`。

## 未覆盖与风险

- **真实调用仍需人工触发**：`#[ignore]` 的测试不会在 CI 里跑，厂商改协议时不会被自动发现。首次接入或厂商更新后要手动跑一次。
- 测试会消耗额度（三张图），因此不做成常规门禁。
- 阿里云 OSS 区域端点与厂商域名一样会变，真变了要改 `ALLOWED_OSS_ENDPOINT_SUFFIXES` 这一行。
- 生成图的内容合规性仍无自动检查——这是第六波剩下的工作。
- 配图只服务于 AI 设计流程，手工编辑路径没有配图入口。
