# 0012 表格数据渲染为原生表格

## 状态

已采纳（2026-10-22）。

## 背景

内容模型里没有表格。`comparison` 块是对照两栏，`timeline` 块是时间轴，`process` 块是步骤，三者都是排好版的结构化内容，但都不是“网格”：用户想看一张对照表（产品线 × 季度、区域 × 指标），AI 只能把它降级成要点列表或者项目符号，导出的 PPTX 里也就没有表格对象。用户在 PowerPoint 里拿到的是一段文字，想做成表格只能自己重画。

要补的正是这件事：**可编辑的表格**。

## 决策

1. 表格通过**新的内容块类型** `table-data` 引入，它带表头 `header` 和若干行 `rows`。不改造 `comparison` 块：那会破坏已经确定的双栏对照设计，而且对照与表格的语义确实不同。
2. 表格的**单元格留在内容里**。新增的 `TableElement` 只保存 `contentBlockId`（它引用哪个 table-data 块）和样式，不复制任何单元格。因此表格不可能显示内容里没有的单元格，改内容就会改表格。
3. 导出写的是**原生表格对象**（`<a:tbl>`），不是表格的图片。用户可以在 PowerPoint 里改单元格、加行删列。
4. 单元格读不出来时**阻止导出**并报 `invalid-table-data`。空表格比没有表格更糟，这条与图表的 `invalid-chart-data` 同理。
5. 画布、缩略图和 AI 视觉评审都读同一份单元格，因此三处看到的表头与行与导出文件一致。
6. 文档模型升级到 `schemaVersion: 7`，新增 `table` 元素分支与 `table-data` 内容块，附 `6 → 7` 迁移与 `v6-document.json` 固定样例。版本 6 的文档早于原生表格，迁移后不产生任何表格。
7. 属性面板可以改表格字体、字号、表头填充、表头文字色、正文文字色、边框色和首列加粗；这些都属于设计态，不改内容。
8. AI 提示词（Rust 与 TypeScript 两侧）都说明了 `table-data` 的形状，并限定“仅当输入确有可对照的表格”——不诱导模型凭空造表。

## 影响

- 含对照数据的页面导出后得到真正可编辑的表格，而不是散落的文本框。
- 表格样式只有一套：表头填充色 + 首列加粗 + 统一边框。合并单元格、跨行跨列、条件着色都不在当前范围内，需要新的内容块字段。
- 画布上的表格是 DOM 近似（`<table>`），不是 PowerPoint 的渲染结果；两者单元格一致，但字体度量与列宽可能略有差别。
- 表格的行高按元素框等分，行数很多时单行会偏挤；导出同样按等分行高写入。这是已知限制。
- 表格内容由 AI 显式产出。若模型把内容写成要点而不是 `table-data`，页面仍然按要点渲染，不会退化成表格。
