# 0002 模板固定视觉层采用原生渲染适配器

- 状态：已接受
- 日期：2026-10-21

## 背景

PPTX 模板中的视觉效果不仅由主题色和占位符坐标决定，还可能来自：

- 背景图片、渐变、透明度和阴影；
- Logo、自由形状、组合对象和装饰图形；
- `Design → SlideMaster → CustomLayout` 的多级继承；
- PowerPoint 专属的字体替换、裁剪和渲染行为。

仅解析颜色、字体和占位符，无法得到与原模板接近的页面。若在 PPTD 内完整重建 OOXML 渲染器，开发和兼容测试成本过高，并且仍可能与 PowerPoint 的实际渲染结果不同。

## 决策

### 双层页面模型

使用模板生成页面时，将页面拆成两个视觉层：

1. **模板固定视觉层**：背景图片、渐变、自由形状、Logo 和复杂母版继承由原生渲染器生成，作为锁定的整页背景图片进入文档。
2. **可编辑内容层**：标题、正文、指标、流程、时间线和 PPTD 新增形状继续使用原生可编辑对象。

整页图片是明确记录的模板视觉降级，不得把标题、正文或业务数据一并栅格化。

### 当前高保真适配器：Microsoft PowerPoint

Windows 环境优先使用 Microsoft PowerPoint COM 自动化：

- 打开模板的临时副本，不覆盖用户源文件；
- 强制设置 `AutomationSecurity = 3`，禁止执行宏；
- 遍历全部 `Design → SlideMaster → CustomLayout`；
- 为每个 `CustomLayout` 创建不含示例正文的临时空白页；
- 由 PowerPoint 导出 PNG 视觉底图；
- 临时页面和临时文件在任务结束后清理；
- 视觉底图作为锁定图片置于可编辑内容下方。

该方式的主要收益：

- 最接近 PowerPoint 对自身模板的显示结果；
- 原生处理母版与版式继承关系；
- 准确保留背景图片、渐变、透明度、阴影、自由形状和 Logo；
- 减少 PPTD 自行解释复杂 OOXML 所产生的兼容偏差；
- 企业 PowerPoint 模板通常能获得更高的视觉保真度。

### 回退链

模板渲染能力必须通过适配器接入，长期回退顺序为：

1. PowerPoint 高保真渲染适配器；
2. LibreOffice 跨平台渲染适配器（计划能力，当前尚未接入生成主链路）；
3. PPTD 内置解析器：主题色、字体、背景色、基础装饰形状和占位区；
4. 安全默认布局。

PowerPoint 不可用、渲染失败或输出为空时，界面必须显示可诊断提示，不得静默声称已完整应用模板。

## 安全与运行约束

- 当前高保真模式依赖 Windows 和已安装的 Microsoft PowerPoint。
- 模板文件视为不可信输入；只打开临时副本并禁用宏。
- 渲染任务必须限制页面数量、单张图片大小和总资源大小。
- 后续应增加取消、超时、残留 Office 进程清理和结构化进度报告。
- 固定视觉层不得覆盖或改写已审核内容。
- 导出报告必须标记复杂模板视觉层使用了整页图片降级。

## 后果

### 正面影响

- 用户可以获得明显接近源模板的背景与品牌视觉。
- PPTD 无需立即实现完整 OOXML 绘制引擎。
- 可编辑内容和模板复杂视觉相互隔离，符合内容与设计权限边界。

### 代价与限制

- 没有安装 PowerPoint 时无法使用当前高保真适配器。
- Office 自动化速度较慢，并可能受授权弹窗或异常后台进程影响。
- 固定视觉层中的渐变、自由形状和 Logo 不能在 PPTD 中逐个编辑。
- 图片背景会增加项目与导出文件体积。
- macOS、Linux 和无 Office 环境需要 LibreOffice 或其他渲染适配器。

## 验收条件

- 多母版模板的每个版式均能生成不含示例正文的视觉底图。
- 生成页面中模板底图位于最底层并处于锁定状态。
- 标题和正文保持原生可编辑，且不与模板占位区重叠。
- PowerPoint 不可用时给出明确提示并执行可预测的回退。
- 宏不会执行，源模板不会被覆盖。
- 导出报告能够识别并记录模板固定视觉层降级。

## 备选方案

- **完全自行解析 OOXML**：可获得更强的逐对象编辑能力，但实现周期和兼容风险过高，暂不作为近期主路径。
- **只使用主题色和占位符**：实现简单，但无法满足模板视觉保真要求，已经证明效果不足。
- **直接截图模板现有页面**：会把示例文字、图表和业务内容一起带入背景，因此不采用；必须从空白 `CustomLayout` 渲染。
- **仅依赖 LibreOffice**：跨平台更好，但与 PowerPoint 模板在字体、换行、渐变和图形效果上存在差异，未来作为兼容适配器而不是 Windows 高保真模式的替代。
