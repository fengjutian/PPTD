# 0013 文字片段级样式（富文本 run）

## 状态

已采纳（2026-10-22）。

## 背景

一个文本框只有一套样式：`TextElement` 存一段文字和一个 `TextElementStyle`（字体、字号、颜色、粗细、对齐）。因此"覆盖机构：12万"里的"覆盖机构"和"12万"只能同权同色地写在一起，重点被淹没在一段等权重的文字里。

导出侧也是同一个问题：`slide.addText(element.text, {...})` 只写一个 run，整段文字在 PowerPoint 里是同一个格式。用户想强调一个词，只能进 PowerPoint 手动改；PPTD 导出的文件里没有这个能力。

## 决策

1. 片段用**偏移量**定位，不复制文字。新增的 `TextRun` 只带 `start`、`end` 和样式（`bold`、`color`、`underline`），指向 `element.text` 里的一个区间：
   ```ts
   interface TextRun {
     start: number;
     end: number;
     bold?: boolean;
     color?: string;
     underline?: boolean;
   }
   ```
   文字只有一份（在内容里），片段只是它上面的一层标注。因此片段不可能显示内容之外的字，改文字也不会让强调与正文脱节。
2. 片段属于**设计态**。它挂在元素上，不进内容哈希，也不参与 `contentHash`。强调是"怎么呈现"，不是"说了什么"，与 `TextElementStyle` 同级。
3. 区间不得越界，也不得从代理对（emoji 等）中间切开：`assertTextRange` 会以 `INVALID_TEXT_EMPHASIS` 拒绝这种请求。切开的片段会导出成乱码字符。
4. `edit-text` 改了正文后，**清空该元素的片段**。偏移量指向的是旧正文，留着会让强调落在别的词上。清空比"看起来还留着强调"更诚实。
5. 导出写的是**原生 run**：有片段的文本用 `addText` 的数组形式，每个片段一个 run，各自带自己的 `<a:rPr>`。用户在 PowerPoint 里可以单独改其中一段的粗细和颜色。没有片段的文本仍然走原来的单字符串路径，输出不变。
6. 画布、缩略图和 AI 视觉评审都读同一份片段，因此三处看到的强调与导出文件一致。
7. 交互入口在属性面板的文本框：选中若干字后点"加粗所选"（或按 `Ctrl+B`），再次点击则取消。已强调的片段会列出来，可以整体清除。
8. 文档模型升级到 `schemaVersion: 8`，新增 `runs` 字段（可选），附 `7 → 8` 迁移与 `v7-document.json` 固定样例。版本 7 的文档早于片段，迁移后仍是整段统一样式。

## 影响

- 导出的 PPTX 里同一段文字可以有不同格式，且每个片段在 PowerPoint 中独立可编辑——这是"优先保证可编辑性"原则的延伸。
- 片段目前只有粗细、颜色、下划线三种属性。斜体、字号、字符间距、上下标、超链接都还没有。
- 片段是**手工**的：AI 生成的文案不会自带强调。用户需要在属性面板里选中并点击。如果后续要让 AI 决定强调哪些词，需要在内容侧引入语义标记，再由设计侧决定怎么呈现——那是另一个决定。
- 画布上的片段是 DOM 近似，与 PowerPoint 的换行算法不完全一致；片段边界落在换行处时，两边的断行位置可能略有差别。
