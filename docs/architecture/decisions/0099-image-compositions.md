# 0099 图片页的三种构图

## 状态

已接受（2026-10-25）。

## 背景

一页有配图时，渲染器只有一条路：`image-led`。图占右侧 48% 且出血到页面三边，文案收在左侧窄栏。这条构图本身是对的，但当一份文稿有四五页配图时，每一页都是同一个版式——视觉评审把它记为 `generic-layout`，人眼看到的是“同一页重复了五次”。

同时，`supports()` 里的 `hasAsset` 判断把大多数带图页面都推回文字配方，图片页和非图片页之间没有第三种选择。

## 决策

### 1. 增加两个构图，一共三种

| 配方               | 图的位置                   | 文案位置                   | 适用内容                   |
| ------------------ | -------------------------- | -------------------------- | -------------------------- |
| `image-led`        | 右侧出血，撑满页高         | 左侧窄栏，标题在标题轴上   | 要点 3–4 条，图是背景      |
| `side-image-text`  | 内容区内的图板，保留页边距 | 对开的一栏，标题在标题轴上 | 要点 2–5 条，图文对读      |
| `full-bleed-image` | 整页                       | 底部实色题板               | 封面/章节/一句话，要点 ≤ 2 |

`full-bleed-image` 的文字板是 `surfaceRaised` 的实色矩形，不是半透明蒙版：渲染模型没有透明度，直接压在照片上的文字只有靠运气才读得清。把文字放在实色板上是同一构图的诚实版本，而且导出的仍然是原生可编辑对象。

### 2. 选哪一条由图和内容共同决定

`chooseRecipeId` 不再对所有带图页面返回 `image-led`，而是按顺序尝试：

- 陈述型页面（封面、章节页、要点 ≤ 2）→ `full-bleed-image`，其次 `image-led`；
- `band` 图（宽横条）→ `image-led`，其次 `full-bleed-image`。宽条裁成竖栏会丢掉大半画面；
- 其余 → `side-image-text`，其次 `image-led`。

每个候选都要真正通过 `supports()` 才会被选中，所以窄内容区、模板自带装饰、结构化内容仍会退回原配方或旧分支。

### 3. 方向拥有自己的构图

`full-bleed-image` 只出现在 `documentary` 方向的配方集合里。`paper` 是窄栏散文、`instrument` 是数据轨道，整页摄影与这两者的骨架冲突。`side-image-text` 在四个方向都可用。

### 4. 标题轴不变

`side-image-text` 的标题仍在 `chrome.title` 上，只是在背后加一条 `accentSubtle` 色带。`full-bleed-image` 属于陈述页，和封面/章节页一样不守内容页的标题轴——这与既有 `cover-statement`、`section-statement` 的定位一致。

### 5. 模板页用自己的图位

模板声明了图片占位时，`side-image-text` 直接使用该区域，不再计算“图板 + 分栏”，也不画第二道分栏线：模板已经有自己的分区线。

## 后果

正面：

- 同一份带图文稿可以轮换三种构图，不再是一页重复。
- 图文对读的页面有了真正的两栏关系，而不是“图占一半、字挤一半”。
- 文字永远落在可计算的底色上，对比度由代码保证而不是靠图片内容。

代价与限制：

- 没有半透明蒙版，所以暂时做不到“大字直接压在图片上”。要做需要先给形状模型加透明度并验证导出；
- `full-bleed-image` 的题板高度随文案增长，极长正文会被拒绝（返回冲突），而不是压缩字号塞进去；
- 一页仍然只有一张配图：`image-grid`（三图/四图墙）需要内容模型支持一页多图，本次未做；
- 图片页的文案排版仍受 `layoutFlow` 的容量约束，要点超限时返回冲突。

## 验证

- `recipes.test.ts`：两者各自的 `imageFrame`、内容消费、题板/色带填充、拒绝条件（要点超限、无图、模板装饰无图位、band 图）。
- `plan.test.ts`：三种图页构图的选择顺序，含方向限制（editorial 不选 full-bleed）。
- `design-preview.test.ts`：图片板不越界、不压文字，标题仍在共享标题轴上。
- `deck-concept.test.ts`：editorial 集合不含 `full-bleed-image`，documentary 集合包含。

## 备选方案

- **只加一个 `image-right` 变体**：只是同一构图的镜像，解决不了“每页一样”。
- **用半透明蒙版压字**：形状模型无透明度，导出会是实色块；先不做。
- **让 AI 直接写图片坐标**：违反“AI 不写坐标”的样式合同；不采用。
- **支持一页多图做图墙**：需要内容模型、生成批量和导出同时改，单独立项。
