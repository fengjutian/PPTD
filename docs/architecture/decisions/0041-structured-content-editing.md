# 0041：在编辑器内编辑结构化内容（指标与表格）

## 状态

已接受（2026-10-23）。

## 背景

正文、指标数值和表格数据是内容，不是设计。领域模型一直这样划分，但编辑器只提供了标题/正文的文本框：

- 指标页上的数字是生成器用普通文本画出来的。文本对象不指向任何指标块，所以在属性面板里改一个数字，只改了画面上的字符串；已审核的指标块没变，导出时如果图表或别处引用了这个指标，两边就会说不同的数。页面也不会变成 `changed`，复核流程根本看不到这次改动。
- 原生图表不存储自己的数据，它读指标块；原生表格也不存储单元格，它读表格块。两者在编辑器里都没有入口，修改数据的唯一办法是重新生成整页，那会丢掉已经做好的设计。

结果是：结构化内容能生成、能导出，但**审核之后不能再改**。这既是一个缺失的编辑能力，也是一条内容完整性漏洞。

## 决策

1. `TextElement` 新增可选的 `contentBlockRef: { blockId, field: "label" | "value" }`，把生成的指标卡文字绑定到它复现的内容块。Schema 升到 13；迁移只改版本号，旧文档的卡片保持普通文本，不猜测、不回填。
2. 生成指标卡时，数值和标签都带上绑定。编辑绑定文本（`edit-text`）会写入指标块，而不是只改字符串；同一块同一字段的所有卡片文字同步更新。
3. 新增内容域命令 `set-metric`：图表属性面板按指标块编辑名称和数值。块更新后，所有绑定到该块的卡片文字一起更新。
4. 新增内容域命令 `set-table-cell`：表格属性面板渲染单元格网格，逐格提交表头或表体。表格对象本身仍然没有单元格，画布和导出都继续从表格块读取。行比表头短时用空字符串补齐，避免写出序列化后变成 `null` 的空洞。
5. 三个入口（卡片文本、指标字段、表格单元格）都算内容域：文档与内容 revision 各 +1，设计 revision 不变；已确认页面变成 `changed`，需要走 0040 的复核闭环重新确认。
6. 目标值与现值相同时命令返回 `null`，不产生空撤销项；点击字段再离开不会让撤销栈变长。超出范围的单元格、未知块和超长文本分别抛 `TABLE_CELL_OUT_OF_RANGE`、`CONTENT_BLOCK_NOT_TABLE` / `CONTENT_BLOCK_NOT_METRIC`、`CONTENT_TEXT_TOO_LONG`，长度上限与持久化 Schema 一致。
7. 设计换版（relayout）会临时生成新的块 id，必须把卡片绑定映射回原页面的块；映射不到时删除绑定，让卡片退化为普通文本，而不是写进一个页面不拥有的块。
8. 粘贴的卡片不保留绑定：副本可能落到另一页，那里没有对应的块。复制出来的卡片是用户自己的文字。

## 结果

- 指标数字和表格单元格现在可以在编辑器里修改，导出对象（原生图表、原生表格）和已审核内容保持一致。
- 编辑内容会把页面标记为 `changed`，状态栏提供"确认本页内容"，形成 `approved → changed → approved` 的完整链路。
- 切换指标卡的文字样式、移动卡片等设计操作不会改变绑定，也不会增加内容 revision。
- 旧文档不需要人工迁移：版本 12 及以前的卡片仍可正常打开和导出，只是属性面板不会声称它绑定了指标。
- 测试覆盖：卡片写入块、多个视图同步、图表字段编辑、表头/表体/短行补齐、命令域、无操作、越界与超长错误、relayout 绑定重映射、revision 与哈希的撤销恢复、Schema 迁移与字段校验、两个属性组件的渲染。

## 未覆盖与风险

- 只能改单元格，不能增删行列；表结构变化仍需要重新生成。
- 指标卡绑定只在生成时建立。旧文档里的卡片不会自动识别；需要重新生成该页才能获得绑定。
- `timeline`、`process`、`comparison` 的文字仍按普通文本编辑，它们还没有"一个内容块对应多个视觉元素"的绑定。
- 图表数据面板只对原生图表出现；两个以上同单位指标会被画成图表，其余指标页仍是卡片，只能通过卡片编辑。
- 指标值允许为空字符串（与既有内容模型一致）；空值不会进入图表数据，图表会少一个类别。没有额外禁止空值，避免把"尚未填写"当成非法文档。
