# 0078 导出回读校验必须独立于导出映射

## 状态

已接受（2026-10-24）。

## 背景

导出报告此前只证明两件事：预检通过、ZIP/OOXML 结构合法。它不证明文档里的文字真的进了包，也不证明图片、表格和图表没有被静默丢掉。

一个自然的做法是复用导出器的中间计划来比对。但导出器和校验器一旦共用同一份映射代码，就会共享同一个盲区：导出器漏掉的文字，计划里也没有，比对必然通过。

## 决策

### 1. 从写出的字节读回

`verifyExportedPptx(bytes, document)` 重新解压刚写出的包，读取 `ppt/slides/slideN.xml`，不读取导出器的计划对象，也不调用导出映射函数。

### 2. 比对内容与数量

逐页比对：

- **文字**：文本元素的文本、表格块的表头与单元格。比较前折叠空白、去掉零宽字符、还原 XML 实体；PPTX 不保证 run 边界与 HTML 一致。
- **图片数量**：`<p:pic>` 与文档内容图片（不含 `layout-background`，它属于母版）。
- **表格数量**：`<a:tbl>` 与原生表格元素。
- **图表数量**：`<c:chart>` 与原生图表元素。
- **页面数**：缺少某个 slide part 记为 `missing-slide`。

### 3. 明确声明不覆盖什么

- 图表标签在 chart part，不在 slide XML；本轮不比对。
- 演讲备注在 notes part；本轮不比对。
- 分组不进入回读计数：原生组合内的对象仍按成员计数，组数量与回退规则由导出测试覆盖。
- 通过只意味着“文档的文字与原生对象数量进入了包”，不意味着视觉保真或与 PowerPoint 渲染一致。

这些项进入 `skipped`，报告不得把它们算作通过。

### 4. 只报告，不修复

回读结果写入 `ExportReport.parity`。不一致时保留文件、不自动重试、不删除用户刚导出的结果。界面显示通过页数或前 12 条不一致；完整问题留在报告对象里。

回读本身抛错（例如包无法解压）时返回 `error` 与 `passed: false`，不让校验异常导致导出失败。

### 5. 与包结构校验分工

`validatePptxPackage` 仍负责“这个包能不能被 Office 打开”；回读负责“文档内容有没有到包里”。两者都要有，不能互相替代。

## 后果

正面：

- 文字丢失、图片/表格/图表数量不符第一次成为可检测的导出缺陷。
- 校验器与导出器不共享盲区；测试可以故意破坏包来证明校验器有效。
- 报告可追溯到具体页与对象类型，用户不必靠肉眼逐页检查。

代价与限制：

- 每次导出多一次解压与 XML 扫描；当前文稿规模下可接受。
- 依赖 XML 结构而不是 OpenXML SDK；命名空间前缀变化会让规则失效，需要固件测试。
- 不覆盖图表标签、备注与视觉布局；“通过”不是兼容性声明。

## 验证

- 正常导出：`parity.passed === true`，页数与文本片段数大于零。
- 删除 slide XML 中的 `<a:t>`：报告 `missing-text`。
- 删除 `<p:pic>`：报告 `picture-count`。
- 8 页样张：表格 1、图表 1，回读通过。
- 全量测试、类型检查、ESLint、生产构建通过。

## 备选方案

- **复用导出映射比对**：共享盲区，正是本决策要避免的。
- **只做视觉像素比对**：慢、依赖 Office，且不能指出“哪段文字丢了”。
- **只校验 ZIP 结构**：无法发现内容丢失，现有 `validatePptxPackage` 已覆盖这一层。
- **用 OpenXML SDK/第三方解析器**：增加运行时与供应链，当前收益不足以抵消；XML 规则先固化，出现前缀差异再加适配。
