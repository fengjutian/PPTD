# 0010 数值指标渲染为原生图表

## 状态

已采纳（2026-10-21）。

## 背景

内容模型里有 `metric` 块：一条指标带一个标签和一个值，例如“年检测样本量 / 38万”。设计阶段一直把它渲染成一块块统计卡片（一个形状加两个文本框），导出的 PPTX 里也是这些散落的形状和文本框。用户拿到文件后看到的是“六个小方块”，不是一张能改的图：想改成柱状图只能自己在 PowerPoint 里重画，想加一列数据也只能改文本框。

同一份文件里其实已经有数字了。数字是已审核内容的一部分（`metric` 块的 `value`），也已经由内容哈希保护。缺的只是把它当作图表来呈现。

## 决策

1. 图表的**数字留在内容里**。新增的 `ChartElement` 只保存 `contentBlockIds`（它引用哪些 metric 块）、图表种类和样式，不复制数值。因此图表不可能显示内容里没有的数字，改内容就会改图表。
2. 只有**单位一致**的指标才能成图。"38万"和"12%"不能放进同一个坐标轴：那样比较的是两个含义不同的数。单位不一致时退回原来的统计卡片。
3. 只有**纯数字**的指标才能成图。"38万人"带单位名词，解析成 38 会改变已审核数字的含义，因此不解析、不成图。
4. 单位跟着数值走。"38万"在图里显示为 `38 万`（数据标签格式 `#,##0.##"万"`），坐标轴同样带单位，不会变成没有量纲的 380000。
5. 导出写的是**原生图表对象**（`ppt/charts/chart1.xml`），不是图表的图片。用户可以在 PowerPoint 里改类型、改数据、改配色。
6. 画布、缩略图和 AI 视觉评审都读同一份内容数值，因此三处看到的类别、数值和单位与导出文件一致。
7. 图表数据读不出来时**阻止导出**并报 `invalid-chart-data`。空图表比没有图表更糟。
8. 文档模型升级到 `schemaVersion: 5`，新增 `chart` 元素分支，附迁移与 `v4-document.json` 固定样例。
9. 属性面板可以改图表类型、系列颜色、字号、数值标签和图例；这些都属于设计态，不改内容。

## 影响

- 数据页的导出质量明显提升：数字页变成可编辑的图表，而不是一排方块。
- 图表的种类目前由设计命令决定（指标多于 4 个时用条形图，其余用柱状图），用户可以在属性面板里改。
- 只覆盖"指标页"。真正的多系列图表（一条曲线两个指标）需要新的内容块类型，属于后续工作；当前所有指标属于同一单位、构成一个系列。
- 画布上的图表是 DOM 近似（柱、条、折线、饼），不是 PowerPoint 的渲染结果；两者类别和数值一致，但字体度量与留白可能略有差别。
