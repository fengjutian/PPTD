# 0052 PPTX Level A 内容导入：Rust 读取器 + 中性映射

## 状态

已接受（V0.3 首版已实现）

## 背景

TRS 4.5 要求打开/导入入口接受 `.pptx` 并把页面内容变成可编辑文档。此前的 `import_pptx_template` / `analyze_pptx_template` 只读取主题、母版和版式，用于设计参考，不读取幻灯片内容。

内容导入有三条可能路线：

1. 前端 TypeScript 直接解 ZIP 和 OOXML。
2. Rust 读取 OOXML，直接构造 `PresentationDocument`。
3. Rust 返回中性结构，TypeScript 映射到领域模型。

前端解 ZIP 需要额外引入浏览器 ZIP 库，且文件访问会绕开 Tauri 的受控命令边界；Rust 直接构造文档会把领域模型复制到 Rust 侧，两套 Schema、两套 ID 和两套单位换算很难保持一致。

## 决策

### 读取与映射分离

- Rust `commands/pptx_import.rs` 负责解 ZIP、解析 OOXML、执行安全边界，返回中性 `ImportedDeck`（页面尺寸、页面、元素、主题、报告）。
- TypeScript `core/commands/pptx-import.ts` 是纯函数，把 `ImportedDeck` 映射成当前 `PresentationDocument`，复用现有 Schema、ID、EMU 和内容模型。
- Rust 不写项目文件、不生成 `PresentationDocument`、不接触 React/Tauri 状态。

### 同一入口，两种意图

打开 `.pptx` 后先选择：

- **导入内容（Level A）**：走新读取器。
- **仅提取模板主题**：保留原有模板流程。

不把“抽取主题”和“导入内容”混成一个命令，因为二者产物、报告和失败语义不同。

### 只承诺 Level A

首版只映射常规文本、图片、基础形状、基础表格、主题色/字体和演讲备注；另外把顶层组合展平为成员并保留编辑期选择组，把单序列柱状/条形/折线/饼图映射为原生图表 + `metric` 内容块。多序列图表只取第一个序列。嵌套组合、面积图/散点图/雷达图、SmartArt、OLE、媒体、动画和切换一律跳过并进入报告；组合旋转/翻转未保留；合并单元格、超过 8 列/30 行的表格降级或截断并报告。

兼容等级由实际解析结果决定；报告中的对象计数、跳过项和警告是产品的一部分，不是日志。

### 导入结果是待审核的新项目

- 页面状态设为 `review`，导出预检继续提示未审核。
- 新文档没有项目路径、`savedRevision = -1`，必须另存为新的 `.pptd`。
- 源文件只读；导入前后都不写回，也不覆盖。
- 载入导入文档会重置撤销栈；导入前的工作区已由“未保存修改”确认保护。

### 版式不做视觉重建

母版/版式只用于补齐占位符几何（slide → layout → master），不把母版装饰、背景图形和继承样式绘成对象。没有几何的占位符使用页面相对默认位置，避免所有文本堆在 0,0。

这不是 OOXML 保真编辑，也不是无损往返；PPTX 仍由 PptxGenJS 重新生成。

### 安全边界在读取器内

文件大小、ZIP 条目数、解压总量、条目路径、XML 大小、外部关系、单媒体/总媒体大小都有上限；不执行宏、脚本或外部关系。路径穿越与畸形 ZIP 在解析 XML 之前拒绝。

## 后果

- Level A 内容可以进入编辑器并继续编辑，导入行为有逐项报告。
- Level B/C 仍未完整实现：多序列/其他图表类型、嵌套组合、SmartArt、复杂表格和原生分组导出都缺少；报告会说明。顶层组合可作为编辑期选择组导入，但成员已展平，导出仍是独立对象。
- 版式/母版的视觉保真有限，导入页可能与原稿有排版差异。
- 进度按页通过 Tauri 事件上报，取消在页间生效；单页内的大量媒体解析不会中途中断。
- `.ppt` 仍依赖现有转换器先转 `.pptx`。

## 备选方案

- **前端解 ZIP**：绕开受控文件命令，安全边界难以集中，且要引入新依赖。
- **Rust 直接生成领域文档**：领域 Schema、内容版本和 ID 规则会分叉，后续迁移成本高。
- **PptxGenJS 反向导入**：它没有读取 API，不能作为导入器。
- **把不支持对象栅格化**：会破坏可编辑性，也违反“整页图片只能用于明确降级”的产品原则。
