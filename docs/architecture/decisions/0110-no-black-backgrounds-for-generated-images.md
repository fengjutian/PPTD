# 0110 生成配图不使用黑色背景

## 状态

已接受（2026-10-26）。

## 背景

用户给了一份真实生成的年报封面：页面背景是主题的蓝色，右侧放着一张
`hero` 配图。配图是黑底上的霓虹光带——整页的视觉重心变成了一块黑色，
标题所在的蓝色半边被压了下去。

这张图的提示词由三部分组成：整册共用的风格前缀（“低饱和、自然光、留白
充足；不要霓虹灯”）、模型写出的画面描述（“……背景为深色科技感的渐变”）、
以及图片模型的默认审美。实测画面描述压过了风格前缀：模型照着描述画了
深色科技背景，还把霓虹一起带回来了。只改风格前缀不会改变结果。

## 决策

### 1. 提示词三处同时收紧

- 内容/设计阶段的配图规则（`content_lexicon.rs`）要求 `prompt` 描述浅色
  明亮背景，禁止深色、黑色、夜景、暗场和黑底。
- 素材层风格前缀写明“浅色留白背景”，并明确不要黑色或深色背景。
- 画面描述里如果点名要深色背景，`lightenBackdropRequest` 在发出请求前把它
  改写成“背景为浅色留白”；提示词结尾再重复一次背景硬约束。

只改背景措辞，不改画面主体：一台“深色工业设备”仍然可以是深色的，要改的
是承载画面的底。

### 2. 结果按边缘像素验收

提示词是请求，不是保证。生成回来的图先下采样到 64×64，只测四周 12% 的
边缘带：如果至少 60% 的不透明边缘像素相对亮度 ≤ 0.08，就判定为黑色背景，
整张图不使用。

- 只看边缘，不看整图：浅色底上的深色主体（设备、人物、图表）仍然通过。
- 透明像素不计入：带 alpha 的素材没有“黑色底”这回事。
- 测不出结果（解码失败、无 canvas）时放行：这道检查拦的是已知的坏结果，
  不是新增一种图片失败。

### 3. 手工路径说实话，整册路径跳过

手工“生成配图”失败会在对话框里说明原因，让用户改描述后重试。整册生成里
一张图只是素材：不合格就跳过，页面回到不放图的排版，不阻塞整份文稿。

## 后果

正面：

- 生成的封面和内容页不会再出现一块黑色配图。
- 深色主体、深色物体仍然可用；被拒绝的只是近黑背景。
- 判断写在核心层（纯函数），画布、导出和测试用的是同一套阈值。

代价与限制：

- 夜景、暗场摄影这类合理画面也会被拒绝。需要这类素材时应由用户自己上传，
  上传路径不受这条规则约束。
- 已经是黑色背景的旧文档不会被自动修改；重新生成或替换那张图才会生效。
- 提示词改写是词面规则，覆盖不到所有表达（例如“像深夜一样”）；最终仍由
  像素验收兜底。

## 验证

- `image-backdrop.test.ts`：黑底霓虹样张被拒绝；浅色底、深色主体、单边深色
  和透明背景都通过；阈值两侧行为正确。
- `visual-asset.test.ts`：“背景为深色科技感的渐变”被改写为浅色；背景约束
  出现在画面描述之后；深色主体不被改写。
- `content_lexicon.rs`：配图规则里包含浅色背景和黑底约束。
- 用真实失败样张（`latest.pptd` 封面的黑底霓虹图）按同一算法复测：边缘近黑
  占比 0.988，判定为黑底；同一文稿里白底立方体配图为 0，正常通过。
