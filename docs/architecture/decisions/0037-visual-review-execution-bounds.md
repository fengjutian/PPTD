# 0037 运行时视觉评审的执行边界

## 状态

已采纳（2026-10-22）。

## 背景

`runDesignQualityStage` 的视觉评审闭环（[0003](0003-visual-alignment-loop.md)、[0022](0022-visual-review-on-real-pptx.md)）已经能看真实导出的 PPTX，但执行边界有几处会让用户静默拿到更差的稿：

1. 前端只允许 20 页参与评审，而栅格化器已经能产出 40 页。21 页以上的文稿整份失去视觉评审，只留下一条语焉不详的降级说明。
2. 内容隔离守卫的指纹由调用方传入。生产调用忽略入参、始终返回同一份生成时草稿，比较的两边永远相等，守卫从未真正运行。
3. 评审结果缺失逐页指导时，归一化会为每页补一个默认 `safeRegion` 和 `title-body` 版式；规则降级再拿这些伪造指导生成修复，导致模型不可用时每一页都被重排。
4. 修复让评分下降时，闭环直接返回变差后的设计。
5. 任一批评审失败会让整轮评审作废，即使其他批次已经给出结论。

## 决策

1. **评审上限与栅格化器一致**。`MAX_REVIEWED_SLIDES` 为 40，超过上限的文稿明确报告“本次未做视觉评审”，不把整份文稿塞进一次非法请求，也不假装评审过。
2. **内容指纹从真实文档快照计算**。`documentContentFingerprint` 使用核心层的 `hashSlideContent` 汇总标题、正文、结构化块、备注和页序，调用方必须传入由当前设计构建出的文档，而不是闭包里的常量。
3. **缺失的指导保持缺失**。归一化不再为没被模型提到的页面编造安全区和版式。规则降级只处理评审确实指出问题的页面；模型给出的修复计划同样按 `affectedSlideIndexes` 过滤。没有可执行动作的问题直接跳过，不用默认值凑动作。
4. **修复必须可回退**。闭环记录评分最高的设计；评分下降或停滞时返回该版本并标记 `reverted`，不再保留最后一轮。修复前后设计指纹相同时以 `no-change` 停止，避免再导出、再渲染、再评审同一份画面。
5. **部分评审优于没有评审**。分批请求相互独立，失败的批次被记录，成功批次的结论继续使用；报告写出实际覆盖的页数，覆盖不完整视为降级。
6. **降级必须说清楚**。评审不可用时同时记录失败原因和“本次未做视觉评审”；部分覆盖时记录 `已评审/总页数`。
7. **整套缩略图只发送一次**。缩略图是每批都相同的图片，此前随每批请求重复上传。现在它只跟第一批发送；后续批次明确告诉模型“本批没有总览”，`consistencyScore` 只表示批内一致性，不再假装跨页判断。
8. **只重画变化页**。栅格化命令接受页索引（请求头 `x-pptd-slide-indexes`，1 起算），PowerPoint 仍打开整册，但只导出被请求的页。前端缓存上一轮真实渲染图，只请求设计发生变化的页，再用合并后的整册画面重拼缩略图墙。请求的页没有全部返回时视为渲染不完整，降级到画布全量渲染，不用旧图冒充新画面。
9. **评审结论随结果返回**。`runDesignQualityStage` 返回最后一轮的 `VisualReview`（五项评分、逐页建议、模型给出的安全区）和实际覆盖的页数；报告界面逐条展示模型建议并标注来源轮次。降级到确定性校验时两者都为空，调用方不能把“没有结论”当成“检查通过”。
10. **整册总览与逐页评审分开**。增加一路只看缩略图的整册评审（请求字段 `deckOnly`）：它只判断跨页一致性、节奏和重复度，不输出逐页几何。逐页批次不再携带缩略图，跨页一致性只取整册评审的分数；总览评审失败时退回逐页批次的批内一致性，并明确记录这次降级。
11. **视觉评审是可关闭的隐私选项**。设置里新增“允许视觉评审”，默认开启以保持既有行为；关闭时生成流程改用不发送任何图片的禁用端口，报告明确写出“视觉评审已在设置中关闭，只做确定性校验”。设置缺省值在 Rust 与前端两侧都回落到开启，老库升级不会静默改变行为。
12. **未变化的页批次复用评审结论**。逐页批次按整批设计签名缓存；修复只改一两页时，其余批次不再重复上传图片。整册总览每轮都重新评审，因为任何一页变化都会改变总览；没有整册评审时，携带缩略图的第一批也每轮重看，避免用旧总览给出新的跨页一致性。
13. **逐页评分结构化返回**。逐页评审协议新增可选的 `slideScores`，每个被检查页一条，包含总分、层级、对齐和可读性；一致性仍是整套指标，不进入逐页评分。规范化只保留本轮实际检查过的页，丢弃越界、重复和非法分数，缺省时退回批次级口径。报告会在问题旁标出该页评分。
14. **逐页复用评审结论**。逐页缓存按渲染来源和页数隔离；修复后只上传缺少当前设计结论的页，未变化页沿用上一轮逐页结论，再按页分数的最小值拼回批次结论。模型没有为每个被检查页返回 `slideScores` 时无法安全拆分，退回整批重看；没有整册评审时第一批仍整批重看，以刷新缩略图的跨页一致性。

## 与需求基线的对应

需求基线 6.2 与 10.4 要求视觉质检可诊断、不能静默改变已审核内容。本决定不新增评审能力，只让既有闭环在边界情况下仍然遵守内容隔离、可回退和如实报告这三条约束。

## 影响与边界

- **评审仍是主观评分**。回退只比较 `overallScore`；同一份稿两次评审可能有小幅差异，因此没有引入更细的逐页回退。
- **分批评分合并仍是保守的 `min`**。跨页一致性已经由专门的整册评审给出，但层级、对齐、可读性和总分仍取各批逐页评审的最小值；逐页评分已经结构化返回并用于页级复用，但拼回批次时仍取页分数的最小值，没有改成加权平均。
- **PPTX 仍整册构建，PowerPoint 仍每轮启动**。增量的是逐页栅格化：只有设计变化的页重新导出，未变化页复用上一轮图片。导出整份文件、拉起 PowerPoint 实例的固定成本仍然存在，复用 COM 实例不在本决定范围内。
- **超过 40 页仍不评审**。限制来自栅格化器一次返回的页数；多窗口评审需要新的渲染接口，不能靠放宽校验解决。
- **评审 trace 尚未持久化**。评分与逐页建议随本次生成结果返回并展示在报告里，但重新打开项目后不可回看；写入项目文件需要 `schemaVersion` 迁移，属于后续工作。
- **没有模型能力预检**。关闭开关只保证不上传图片；开启后如果所选模型不支持视觉输入，仍会在第一次评审请求时失败并降级。预检需要厂商能力声明或一次探测请求，尚未实现。
