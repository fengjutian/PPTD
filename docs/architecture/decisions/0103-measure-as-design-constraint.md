# 0103 行长作为设计约束：两套字符带

## 状态

已接受（2026-10-26）。

## 背景

页面上没有"太长"这回事的检查。文字只要不溢出框就算通过，于是一行可以横贯 11.5 英寸的 16:9 页面：14pt 下约 59 个汉字。它不触发任何告警，但读者读到行尾会找不到下一行的开头——这是排版里最常见、也最容易被自动生成踩中的问题。

字号的检查（`BODY_TEXT_TOO_SMALL`）只回答"看不看得清"，不回答"读不读得下去"。

## 决策

### 1. 两套字符带，按文字本身判断

| 文字        | 下限 | 上限 | 依据                                                              |
| ----------- | ---- | ---- | ----------------------------------------------------------------- |
| 全角（CJK） | 18   | 36   | 45–75 个拉丁字符折算成全角字形（一个全角约 1.6–1.8 个拉丁字符宽） |
| 拉丁        | 40   | 85   | 传统排版的可读区间 45–75，两端各留一点余量                        |

同一段文字里汉字和字母各占多少，由 `measureLine` 逐字统计后按多数决定，而不是按字体名猜。一个段落混排时，读者感受到的是"哪种字占主导"。

### 2. 只作用于成段的正文

短于 `minBodyLength`（默认 20 字）的文本一律不检查：列表要点、图注、页脚都不是段落，按字符带要求它们是错的。

### 3. 软提示，不阻断

新增两个 code：`MEASURE_TOO_WIDE` / `MEASURE_TOO_NARROW`，级别 `soft`。它们和品味检查的其余项一样只进报告（ADR 0015），不影响生成与导出。

### 4. 不自动改栏宽

配方已经按内容与构图决定栏宽；这一轮不让检查去改动几何。原因是一旦"规则可以改布局"，同一条文案在不同分支会得到不同栏宽，视觉回归与配方测试都会失去基准。若将来要让配方消费这个带，应由配方显式读取令牌，而不是由 lint 反写。

## 后果

正面：

- "满行长行"从审美意见变成可定位的报告项，带页号、元素 id、实际字符数与建议。
- 汉字与字母分别判断，不会出现"中文页面永远超宽"或"英文页面永远过窄"的假阳性。
- 阈值集中在 `MEASURE_BAND` 一处，校准只需要改一张表。

代价与限制：

- 字符数是估算：真实字宽取决于字体与度量器，`measureLine` 用的是与溢出检查同一套宽度估算。
- 只判断"一行能放多少字"，不判断实际断行位置；一段只有两行的文字可能按单行宽度被判宽。
- 不覆盖标题：大字号标题天然字数少，用字符带判断没有意义。

## 验证

- `taste-lint.test.ts`：11.5in / 14pt 的正文报 `MEASURE_TOO_WIDE`（脚本记为 cjk，字符数 >36，级别 soft）；1.6in 的正文报 `MEASURE_TOO_NARROW`；5.2in / 14pt 的拉丁正文落在带内不报。
- `design-preview.test.ts`：产品自身的十页夹具与三页深色夹具仍然零发现，说明新规则没有对现有版面误报。
- 同时修正了 `taste-lint.test.ts` 里那条"干净页面"夹具：它的正文原本是 11.5in 满宽，按新规则本来就不该算干净。

## 备选方案

- **只提示"超过 N 个字符"，不分脚本**：中文页面会被误报一片，英文页面几乎永远不会触发；不采用。
- **按实际断行数判断**：需要渲染后的行盒，画布与导出各一套，且无法在纯函数里复现；不采用。
- **让 lint 自动收窄栏宽**：见决策 4。
