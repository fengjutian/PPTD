# 0106 深色页全幅图自动双色

## 状态

已接受（2026-10-26）。实现 [TRS FR-V4](../../requirements/PPTD-Visual-Quality-TRS-v0.1.md) 里悬置的 `ImageElement.tone`。

## 背景

照片是纯色页上最亮的东西。一张照片铺满深色页时，观众先看到照片、后看到内容，页面的构图被照片压过去；换一张照片，整封信的语气也跟着变。FR-V4 早就把 `tone`（双色映射）列进需求，但一直没有消费者，所以一直没有实现——按本仓库的规矩，没有消费者的字段不加。

这一轮用户拍板了策略：**深色页上的全幅图自动染色**（B 方案）。

## 决策

### 1. 只有"全幅图 + 深色页"自动染色

- `full-bleed-image` 配方在深色页上给图片设 `tone`。
- 图文对开（`side-image-text`）里的照片**不染色**：它是被"看"的图，不是被当作底纹的图。
- 浅色页永不染色：那里照片本来就属于页面，染色只是装饰。

判断"深色"用的是颜色角色同一套阈值（背景亮度 < 0.45，ADR 0101），所以一处改、处处一致。

### 2. 两端取自品牌色，不取自墨色

`dark = accentStrong`（品牌实心色），`light = mixHex(accentStrong, #FFFFFF, 0.55)`。

第一版用了 `accent` 作亮端——深色页上 `accent` 是近白**墨色**（ADR 0098），于是整张图被提成惨白的色块，比不染色还抢眼。这条和 ADR 0104 是同一个坑：**墨不是面**。

### 3. 没有 strength

OOXML 的 `a:duotone` 只有两个色标，没有强度。需求里写的"强度"在这里无法实现——与其加一个什么都不做的字段，不如不要：`ImageTone = { dark, light }`。

### 4. 导出是原生效果，不是像素处理

写入 `<a:blip>` 内的 `<a:duotone>`，照片在 PowerPoint 里仍可替换、仍可改色。画布用等价的 SVG 滤镜（去饱和 + 双色表）绘制同一映射，不是叠色块——叠色块对饱和色是错的，而这张效果的全部意义就是颜色映射。

## 后果

正面：

- 深色页的全幅照片归入品牌色系，不再压过标题。
- 图片仍是原生图片对象，可替换、可编辑。
- 画布与导出的映射一致（同一个两色表）。

代价与限制：

- 两类"全幅图"里的模板版式背景图（`placement: layout-background`）不受影响：它们属于模板，不该被主题改色。
- 配方决定染色，用户不能逐页关掉；需要时可在检查器里清 `tone`（字段已持久化），但目前没有控件。
- 只有两色，做不出"轻染色"这类中间档。

## 验证

- `image-tone.test.ts`：深色页返回品牌两端、亮端比暗端亮；浅色页返回 `undefined`；阈值边界 0.45 两侧行为正确。
- `export-pptx.test.ts`：带 `tone` 的图片写出 `<a:duotone>` 与两个 `a:srgbClr`，并且与 `roundRect` 裁剪**同时生效**（形状路径会重建 blip，效果必须一起重建）。
- `CroppedImage.test.tsx`：画布渲染出滤镜定义与 `filter:url(#…)`，无 `tone` 的图片不产生滤镜。
- 真实渲染（PowerPoint，深色词汇基线第 3 页）：照片成为品牌青色的双色图。

## 备选方案

- **手动设置（A 方案）**：用户已否。
- **不做（C 方案）**：需求里的 `tone` 将永远是死字段。
- **整页叠一层半透明色**：模型没有 alpha 通道（ADR 0101 的约束），且会同时压住文字。
- **导出时重编码像素**：图片变成不可替换的位图，违反"原生可编辑优先"。
