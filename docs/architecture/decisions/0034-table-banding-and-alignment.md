# 0034：表格样式：斑马纹、内边距、边框与数字右对齐

## 状态

已接受（2026-10-23）。

## 背景

原生表格原来只有表头填充、表头/正文文字色、边框色和首列加粗。画布和导出虽然一致，但表格看起来是"裸网格"：没有斑马纹、内边距由导出器固定、边框宽度固定、数字列和文字列一样左对齐。

## 决策

1. `TableElementStyle` 增加四个可选字段：
   - `bandingFill`：正文奇数行填充；
   - `headerBold`：表头是否加粗（缺省 true）；
   - `cellPaddingPt`：单元格内边距（pt，0–30）；
   - `borderWidthPt`：边框宽度（pt，0–10）。
2. 数字列右对齐由**内容**决定，不新增样式标志：`tableColumnAlignsRight` 统计该列中形如 `1,200`、`3.5%` 的单元格，达到 60% 即右对齐。画布与导出共用这个判定，避免两边各写一套。
3. 生成器写表时给出默认样式：`bandingFill = cardFill`、`cellPaddingPt = 6`、`borderWidthPt = 0.75`、`headerBold = true`。
4. 画布与导出同步消费这些字段：PptxGenJS 写 `fill`、`margin`、`border.pt`、`algn`，画布写 CSS。

## 结果

- 表格第一次有斑马纹和内边距；数字列自动右对齐，标签列保持左对齐。
- 画布与导出的表格外观一致，卡片式页面的表格不再像裸网格。
- 新增 4 条测试：表格数据列对齐判定、TableView 斑马纹/右对齐/内边距、导出 XML 的 `algn="r"` 与斑马纹色。

## 未覆盖

- 没有按列设置宽度、合并单元格、条件底色；这些要等真正的表格编辑需求。
- 斑马纹只作用于奇数行，不能按行/列自定义。
- 数字判定是启发式：`38万` 这类带单位的文本仍按左对齐处理。
