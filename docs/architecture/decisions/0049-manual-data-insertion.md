# 0049 手动插入表格与图表的内容边界

## 状态

已接受（V0.2）

## 背景

TRS 4.4.4 要求“插入”功能区提供原生可编辑表格和基础图表。编辑器里的表格和图表不是自包含对象：

- `table` 元素只有 `contentBlockId`，单元格来自页面的 `table-data` 内容块。
- `chart` 元素只有 `contentBlockIds`，类别和数值来自页面的 `metric` 内容块。

AI 设计阶段会同时生成内容块和元素；手工插入如果只加一个空元素，画布可以是空的，导出校验会拒绝，或者得到一个没有数据的原生对象。

## 决策

### 插入同时创建内容块和元素

`add-table` 创建带表头和空白行的 `table-data` 块，再追加表格元素；`add-chart` 创建 3 个示例 `metric` 块，再追加图表元素。

命令域是 `both`：内容 revision 和设计 revision 都递增，已确认页变为 `changed`。这样“插入表格”不会绕过内容审核——表格里的文字就是内容。

### 用可编辑的占位数据，而不是空对象

表格默认表头为“列 1…列 n”、单元格为空；图表默认“项目 A/B/C，10/20/30”。

理由：

- 空表头/空行和没有可解析指标的图表无法通过导出校验。
- 占位值让用户一插入就能看到完整对象，并明确知道要在属性面板替换示例数据。
- 占位数据进入内容版本，比导出一个空表格诚实。

### 行列数和图表类型在插入时确定

表格列数/行数在对话框中选定，图表类型在对话框中选择。插入后属性面板只编辑单元格和指标，不能增删行列或序列。

增删行列会改变内容块结构，需要迁移已有数据和审核状态；这属于下一层的内容编辑能力，不在本任务里用“看似支持”的按钮伪装。

### 复用既有原生导出

表格和图表仍走现有的 PptxGenJS 原生对象导出，不引入图片降级。插入路径只是创建了合法的内容块和元素，导出器无需特判。

## 后果

- 手工插入的对象与 AI 生成对象走同一条渲染、编辑和导出路径。
- 插入即内容编辑，已审核页会回到待确认；用户可以在内容审核界面看到差异。
- 插入后不能改表格尺寸或图表序列数量，需要删除重插；后续可以补一个“表格结构编辑”任务。
- 新对象居中放置，不自动避让已有内容，可能重叠；用户需要自己移动。

## 备选方案

- **只加设计元素、不建内容块**：画布能显示，但导出没有数据，违反可编辑性要求。
- **空表格/空图表**：导出校验失败，或生成 PowerPoint 打不开的对象。
- **把表格数据存在元素里**：会形成第二份内容真相，与审核、内容版本和图表/表格同步冲突。
