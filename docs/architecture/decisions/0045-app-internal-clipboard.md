# 0045 应用内剪贴板与跨页粘贴边界

## 状态

已接受（V0.2）

## 背景

TRS 4.4.4 要求“开始”功能区提供剪切、复制和粘贴，并允许在无法访问系统剪贴板时降级为应用内剪贴板。桌面端当前没有安装 Tauri clipboard 插件，也没有声明对应 capability。

原来的复制/粘贴只存在于快捷键里：剪贴板记录源对象的 id，粘贴时对当前页的同 id 对象执行 `duplicate-elements`。这使复制依赖来源对象仍然存在，也无法跨页带走对象。

## 决策

### 剪贴板保存元素快照，不保存 id

剪贴板保存 `SlideElement[]` 的不可变引用。文档命令每次都产生新对象，旧引用不会被原地改写，因此不需要深拷贝大图片。粘贴时由 `paste-elements` 命令通过 `copyElementForPaste` 生成新 id 和偏移。

这样复制后删除来源仍可粘贴，副本也不受之后对来源的编辑影响。

### 粘贴是独立的设计域命令

`paste-elements` 接受快照元素和显式偏移，追加到页尾，强制 `origin: "user"`、`locked: false`。一次粘贴一个事务、一个撤销项；store 在命令结束后选中新副本。

连续粘贴的偏移由 UI 的 `pastes` 计数递推（0.2、0.4、0.6 英寸），命令本身保持无状态，便于测试和复用。

### 内容块依赖不能跨页

表格和图表是页面内容块的视图。把它们粘贴到没有对应块的页面会生成导出器无法解析的悬空引用，因此命令在写入前检查目标页并返回 `PASTE_REQUIRES_CONTENT_BLOCK`。

文本不受影响：粘贴路径把文本改为 `decorative` 并移除 `contentBlockRef`，它与已审核内容脱钩。图片、形状、线条和图标也没有页内引用。

### 动画不进入剪贴板

动画挂在页面的 `animations` 时间线上，引用元素 id。V0.2 的剪贴板只保存元素，不保存动画；粘贴对象不会带过来动画。这个限制写进任务书，等需要时再把动画快照纳入剪贴板协议。

## 后果

- 复制/粘贴不再依赖来源对象存活，可以跨页使用。
- 剪贴板是进程内状态，关闭窗口清空，也不能与其他应用互通；后续接系统剪贴板时替换 App 的存储层即可，命令和快捷语义不变。
- 表格/图表跨页粘贴被明确拒绝，而不是产生一个导出时才失败的坏对象。
- 动画复制仍是缺口，需要单独的任务。

## 备选方案

- **继续保存元素 id**：实现最省事，但删除来源后粘贴失败，跨页也无法使用，等于把快捷键包装成按钮。
- **粘贴时复制内容块**：会静默修改内容模型和审核状态，违反“设计命令不得修改已审核内容”的约束。
- **深拷贝整个文档**：图片 data URL 会成倍占用内存，而且与文档不可变模型重复。
