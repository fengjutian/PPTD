# 0052 界面语言与文案字典

## 状态

已接受（V0.2）

## 背景

设置页需要提供“中文 / English”的界面语言选择。项目此前把中文文案直接写在 React 组件里，没有统一的界面语言状态；如果每个组件各自读取本地存储，语言会与主题、字体一样出现多个事实来源，也无法保证保存和升级时的回退行为一致。

界面语言还容易与演示文稿语言混淆。演示文稿正文、模板名称和 PPTX 导出结果属于用户内容，不能因为用户切换界面语言而被翻译或改写。

## 决策

### 语言是应用偏好，不是文档状态

`AppSettings` 新增 `uiLanguage: "zh" | "en"`，与主题、界面字体一起保存在本地设置库的 `ui_language` 键中。它不进入 `PresentationDocument`、不改变内容或设计 revision，也不产生撤销项。

旧数据库没有 `ui_language` 键时回落到 `zh`，避免升级后界面突然变成英文。语言值在写入前经过白名单校验；非法值读取时回落到默认值。

### 文案集中在一个类型化字典里

`src/services/i18n.ts` 保存中英文文案键和语言卡片元数据。英文表使用 `Record<UiMessageKey, string>`，漏掉一个键就无法通过类型检查；测试同时检查运行时键集合一致。

语言设置只决定当前界面使用哪一份文案，不通过网络翻译，也不在运行时改写 DOM。

### 逐步迁移界面

本次先覆盖设置页和主导航，因为它们是语言选择的入口，也是用户验证切换是否生效的最短路径。其余工作区继续显示中文，语言设置的帮助文字如实说明当前覆盖范围；不把“已支持界面语言”扩大成“整份应用已完成本地化”。

后续迁移一个工作区时，只允许把用户可见文案移入字典；领域错误码、稳定标识符、AI 提示词和导出内容不得为了翻译而改值。

### 切换时机

语言与其他偏好一样，点击“保存设置”后才生效。选择语言时会立即更新设置页的选中状态，但不提前改变已保存的应用语言；保存成功后主框架与设置页一起切换，保存提示使用切换后的语言。

## 后果

- 设置页和主导航支持中文、英文，选择会跨重启保留。
- 演示文稿内容和 PPTX 导出不受界面语言影响。
- 其他工作区仍是中文；这是明确的范围限制，不是翻译遗漏。
- 新增界面文案必须同时补齐中英文，否则类型检查失败。
- 如果以后需要更多语言，扩展 `UiLanguage` 与 `UI_MESSAGES`；语言卡片数据已经独立于持久化字段。

## 备选方案

- **在组件里按 `language` 写三元表达式**：短期最快，但文案散落到各组件，无法保证键集合完整，也容易让中文文案和英文文案行为漂移。
- **用浏览器插件式运行时 DOM 翻译**：不侵入组件，但会翻译用户内容、破坏 React 状态与无障碍文本，也无法保证导出内容不被改动。
- **把语言放进项目文档**：同一台机器切换项目时界面语言会跟着项目变，且会让纯显示偏好污染文档 revision 与撤销栈。
