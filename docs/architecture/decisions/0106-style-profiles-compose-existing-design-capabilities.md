# 0106 风格档案组合现有设计能力

## 状态

已接受（2026-10-26）。

## 背景

主题选择器已经能选择颜色、字体和字阶，设计方向能够选择整册骨架，页面配方负责具体构图。把“商务专业、未来科技、学术科研”等用户语言继续塞进主题，会使换风格退化成换色；把它们直接做成固定模板，又会限制同一种风格对不同内容形态的适配。

## 决策

新增 `StyleProfile` 作为设计能力的编排层。风格档案只引用已实现的主题、设计方向和页面配方，并补充密度、图片语言、视觉特征和禁用组合。它不保存正文、坐标或任意渲染属性。

前端新增独立“风格”工作区。选择风格会匹配默认主题，并把风格约束合并到模型可见的 `ThemeDirection`。开启方向门时，编辑式、纪实全幅、纸本专栏和数据仪表各绑定一份独立的 `StyleProfile`、主题与约束，作为四种可选择的完整风格，而不是同一风格下的四个骨架。每个方向使用最能暴露该构图差异的内容页作为样张，不再共用封面。关闭方向门或方向生成失败时，使用当前风格档案声明的首选骨架。

风格选择暂存为本机界面偏好，不改变项目 Schema。生成结果仍通过既有设计命令写入文档，只增加设计 revision，不改变已审核内容、内容版本或页面语义顺序。

风格进入 AI 设计时先收敛为 `StyleConstraint`，只携带允许的整册骨架、首选页面配方、密度、间距/圆角/阴影/线条/图片裁切 token、图片语言、禁用组合与能力降级说明。该约束同时传给样张预览、整稿设计和确定性排版编译器；模型负责在内容语义允许的范围内做选择，代码负责选择合法的首选配方，并把间距、圆角、阴影、线条和图片裁切落实到原生可编辑对象。内容块语义、配方容量、模板安全区和已审核内容始终具有更高优先级。

补充（2026-10-26）：`StyleConstraint` 同时携带风格摘要、可观察视觉特征和主要构图语言。带 `PageDesignPlan` 的页面也必须由设计编译器应用风格首选配方，并在 `DesignCompileReport` 中记录 `STYLE_RECIPE_SELECTED`；不得因为模型已经返回设计计划，就把风格降级成只换颜色、圆角和阴影。风格只能接管普通陈述或通用列表，图表、流程、时间线、比较等结构化内容仍以内容语义和配方容量为最高优先级。

## 后果

- 用户可以先用“商务专业”等语言选择视觉方向，再调整具体主题。
- 风格、主题、骨架与页面配方保持独立，避免新增一种风格就复制一套渲染器。
- 玻璃拟态与 3D 视觉可以进入目录，但必须标为“部分支持”：玻璃背景模糊降级为原生透明面板、渐变、描边与阴影；3D 主体降级为生成或导入的渲染图片。两者均不得宣称导出原生背景模糊或可编辑 3D 对象，降级规则必须在详情抽屉中可见。
- 若后续要求跨设备保存或对已有项目一键换风格，需要先扩展项目 Schema、迁移和设计命令；本次不提前修改持久化格式。
