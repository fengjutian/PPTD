### 1.2 问题陈述

- **P-1 结构对了，看起来还是平。** 语义色、图片构图、体检通道已经补齐（ADR 0098–0100），但页面仍只有"底 + 墨 + 线"三种元件。缺少浮起、阴影、圆角体系、图片色调这些让它读起来像"设计过的页面"的元件。
- **P-2 色彩只有一层。** 每个主题只有一个强调色和一个浅底，没有"深色页面用的一套值"，同一套主题在深色页上只能靠手工推导。强化色、下沉面、描边层次都缺失。
- **P-3 排版没有依据。** 字阶比例、行距、版心宽度是经验常量，无法回答"为什么是 1.08"或"这一行是不是太长了"。中文字数/行、拉丁字符数/行没有约束。
- **P-4 模板是配色而不是设计系统。** 一个模板只有一套配色，无法表达"同一套设计下，封面 / 图文 / 指标 / 时间线各自长什么样"。presenton 那类"模板 = 布局变体集合 + 配色变量"的结构可以把可选版式一次讲清。
- **P-5 生成仍是从零写。** 没有"参考稿 → 页级模式 → 选择并编辑"的两阶段路径，导致同一题材的输出结构高度同质，也让用户已有的优秀稿件无法成为风格来源。
- **P-6 好看与否不可度量。** 视觉评审给一个总分，但没有 rubric、没有整册节奏打分、没有"这一项为什么扣分"的证据页，因此每轮优化只能靠主观争论。

## 2. 目标

1. 让"设计过的页面"可被表达：浮起、阴影、圆角、图片色调这些元件进入模型并原生导出。
2. 让色彩在深色页上同样成立，而不是照浅色页推导一遍。
3. 让排版比例有来源、可测试，并被体检约束（行长、字阶比）。
4. 让模板从"一套配色"升级为"一套设计 + 一组版式变体"。
5. 让生成可以复用参考稿的结构，并让"好看"变成可复现、带证据的评分。

## 3. 非目标

- 不引入 HTML/CSS 作为设计真源；所有新增视觉手段必须落到 OOXML 原生属性。
- 不把文字、图片栅格化成整页图；任何效果不支持时必须报 conflict 或降级，不得静默贴图。
- 不复制任何 AGPL 项目的代码与资产（见第 13 节）。
- 不改变内容模型、内容审核、内容版本与内容哈希规则。
- 不做自由画布或任意坐标；几何仍由编译器与配方生成。
- 本轮不做：一页多图（图墙需要内容模型变更，见 §14）、字体嵌入、3D、PPTX 保真编辑。

| 角色                  | 场景                       | 期望                                           |

## 5. 术语

| 术语                        | 定义                                                                   |
| --------------------------- | ---------------------------------------------------------------------- |
| 设计令牌（Token）           | 颜色角色、字阶、间距、圆角、阴影、图表参数的命名集合；不含量与坐标。   |
| 语义角色（Role）            | 颜色在版面中的职责，如 `surfaceRaised`（浮起面）、`border`（分隔线）。 |
| 元素效果（Effect）          | 形状或图片上的原生 OOXML 属性：阴影、圆角、渐变、色调、亮度/饱和度。   |
| 主题包（Theme Package）     | 令牌 + 一组命名版式变体 + 元数据（密度、禁用组合、样张）。             |
| 版式变体（Variant）         | 模板内的一种页面形态：配方 + 槽位覆盖 + 版式参数。                     |
| 参考稿（Reference Deck）    | 用户提供的既有 PPTX，仅用于提取结构与密度，不复制其文字与资产。        |
| 页级模式（Page Pattern）    | 从参考稿抽象出的"页级功能 + 内容块形状 + 密度"，不含坐标与原文。       |
| 美学评分（Aesthetic Score） | 按 rubric 给出的多维评分，每项附证据页与判定来源。                     |
| 确定性项（Deterministic）   | 可由几何与像素直接判定、同输入同输出的检查项。                         |

## 7. 功能需求

### FR-V1 颜色语义角色与深浅配对

**目的**：让同一套主题在浅色页与深色页上都成立，并让"浮起 / 分隔 / 次要文字 / 强调底色"成为可选的角色而不是手调色值。

**范围**：在 ADR 0098 已交付的 4 个角色之上，补齐到 8 个角色，并给出每个角色的深色页取值。

| 角色            | 职责                                 | 状态   |
| --------------- | ------------------------------------ | ------ |
| `surfaceRaised` | 浮起面（卡片、题板、色带）           | 已交付 |
| `border`        | 细线、描边、分栏线                   | 已交付 |
| `textMuted`     | 图注、来源、副标题                   | 已交付 |
| `accentSubtle`  | 强调色低强度填充                     | 已交付 |
| `surfaceSunken` | 下沉面（分区底、表格斑马底）         | 本需求 |
| `borderStrong`  | 需要明确边界的描边（选中、强调）     | 本需求 |
| `accentStrong`  | 可承载白字的强调实心（徽标、数字块） | 本需求 |
| `onAccent`      | 强调实心上的墨色                     | 本需求 |

**规则**：

1. 每个角色必须同时有浅色与深色取值；深色取值不得由浅色值按固定比例反推（ADR 0098 已记录该失败模式）。
2. 角色值写入 `DocumentTheme`；模板页没有可读取的角色时按页面真实底色与墨色派生，派生函数保持唯一。
3. 每个角色必须声明"允许承载哪些墨"，并由对比度校验器验证 ≥ 4.5:1（大字号按 3:1）。
4. AI 仍然只能选择调色板角色或十六进制强调色，不得直接选择 `accentStrong` 等派生角色。
5. 导出时未知角色名不影响主题部件；已识别的角色按既有语义槽写入。

**验收**：AC-V1、AC-V2。

### FR-V2 主题包与命名版式

**目的**：让"一套设计"能表达封面、正文、图文、指标、时间线等不同页形，而不是一套配色撑所有页。

**范围**：

- `ThemePackage`：令牌集（FR-V1、FR-V5）+ 命名版式集合 + 元数据（适用场景、密度、禁用组合、样张索引）。
- 命名版式：`id`、展示名、绑定的配方 id、槽位覆盖（该版式下角色取哪个值）、版式参数（分栏比例、留白档位）。
- 版式 id 必须来自已实现配方集合，不得声明无法渲染的版式。

**规则**：

1. 一个主题包至少声明 4 个版式，覆盖封面、正文、图文、数据四类；缺项的包不得标为"完整"。
2. 版式只覆盖令牌与版式参数，不得包含坐标、字号点数或正文。
3. 版式名面向用户（中英文各一），映射关系写入导出报告与样张清单。
4. 旧主题（单配色）视为"只有一个版式"的包，加载后行为不变（恒等迁移）。

**验收**：AC-V3。

### FR-V3 模板 = 版式变体集合

**目的**：让模板选择器能说明"这个模板能排出哪几种页"，并让 AI 在模板内选择变体而不是自由发挥。

**范围**：

- 模板（导入或内置）声明可选变体清单；每个变体 = 配方 id + 允许的构件（图片位、指标位、时间线位）+ 密度。
- 生成时模型在变体清单内选择；越界选择被拒绝并记 conflict。
- 选择器展示每个模板的变体数量与代表样张。

**规则**：

1. 变体不得改变模板的母版、Logo、页脚与安全区。
2. 变体必须与 FR-V2 的版式 id 对齐；同一个 id 在模板与主题包里指同一种页形。
3. 模板未声明变体时，按现有单一配方集合处理，不新增空步骤。
4. 变体数量、名称与样张进入项目文件与导出报告。

**验收**：AC-V4。

### FR-V4 元素效果与图片处理链（原生）

**目的**：补上让页面"像设计过"的元件，且全部保持原生可编辑。

**范围**：

| 能力          | OOXML 落点                            | 备注                             |
| ------------- | ------------------------------------- | -------------------------------- |
| 形状阴影      | `a:effectLst/a:outerShdw`             | 预设三档：纸片、浮起、强调       |
| 圆角体系      | `a:prstGeom prst="roundRect"` + `adj` | 卡片 / 徽标 / 图片三档半径令牌   |
| 图片形状裁剪  | `a:blipFill/a:srcRect` + `a:prstGeom` | 圆形、圆角矩形、拱形             |
| 图片色调      | `a:duotone`                           | 双色映射，用于统一不同来源的配图 |
| 亮度 / 饱和度 | `a:lum` / `a:satMod`                  | 仅限可读区间，越界即拒绝         |
| 渐变（形状）  | `a:gradFill`                          | 已有，扩展到主题包默认值         |

**规则**：

1. 所有效果必须由导出层写成原生属性；**禁止**把效果烘焙进图片像素。
2. 每个效果必须有真实 PowerPoint 渲染验证与视觉回归夹具；LibreOffice 差异单独记录。
3. 效果参数使用令牌（半径档位、阴影档位），配方不得写任意数值。
4. 体检新增两条：同一页混用超过 2 档阴影、同一页圆角档位不一致。
5. 不支持的组合（例如图片形状裁剪 + 旋转 + 裁剪区域同时出现）必须报 conflict，不得静默丢弃。

**验收**：AC-V5、AC-V6。

### FR-V5 排版比例与行长约束

**目的**：让字阶、行距、版心与行长有可计算依据，并让"这一行太长"成为可诊断问题。

**范围**：

- 字阶比例：display / title / body 之间使用固定比例档（1.25 与 1.333），替换现有经验常量。
- 行距：标题 1.08–1.20、正文 1.30–1.50，按字号区间取值而非全局常数。
- 版心与行长：正文行宽约束 45–75 个拉丁字符或 20–32 个全角字符。
- `theme.displayFont` 落地：预设可声明 display 字体；缺失时回退 title 字体，字体不可用时按既有回退链。

**规则**：

1. 比例与行距写入令牌；配方只消费令牌，不写点数。
2. 行长越界由体检报 `MEASURE_TOO_WIDE` / `MEASURE_TOO_NARROW`（软提示），并给出建议列宽。
3. 字阶比例变化必须通过现有溢出与容量守卫，不允许为了"比例正确"缩小到不可读。
4. 中文与拉丁字符分别计数，不得用同一个阈值套两种文字。

**验收**：AC-V7。

### FR-V6 原生图表主题

**目的**：让数据页的图表与整册设计同源，而不是 Office 默认蓝。

**范围**：

- 图表令牌：系列色（按强调色与辅助色生成有序序列）、轴与网格样式、数据标签样式、图例位置。
- 默认审美：去掉纵向网格线、坐标轴收敛、关键数据点直接标注、只保留一个强调系列。
- 主题包可覆盖令牌；配方只能选择"强调哪个系列"。

**规则**：

1. 图表必须是原生图表对象，不得降级为图片。
2. 系列色必须来自主题令牌，且相邻系列在灰度下仍可区分（对比度 ≥ 1.6:1）。
3. 数据标签不得遮挡图元；遮挡时回退为轴标注。
4. 图表主题写入导出报告，便于回读核对。

**验收**：AC-V8。

### FR-V7 参考稿驱动的两阶段生成

**目的**：让用户既有优秀稿件成为结构来源，降低"每份稿子都从零写"的同质化。

**范围**：

1. 分析阶段：本地解析参考稿（Level A 导入已有能力），产出页级模式清单——页级功能（封面 / 陈述 / 对比 / 指标 / 流程 / 图文 / 收束）、内容块形状、密度、图文关系。
2. 生成阶段：为每一页选择模式，再由编译器按模式生成；模型只做选择与文案适配，不写坐标。
3. 评分阶段：按 FR-V8 的 rubric 给三维分（内容适配 / 设计完成度 / 整册连贯）。

**规则**：

1. 参考稿只在本地解析；发送给模型的内容只能是"无文本"的模式描述，发送前必须通过无文本校验（不含标题、正文、备注、图片）。
2. 模式不得携带坐标、字号或颜色值；它们来自主题与令牌。
3. 参考稿缺失或解析失败时回退现有单阶段路径，不阻断生成。
4. 用户可随时关闭该能力；关闭后不读取参考稿。
5. 生成结果不得复制参考稿的文案与资产；命中重复长句时告警。

**验收**：AC-V9。

### FR-V8 美学评分 rubric 与整册复核

**目的**：把"好看"变成带证据、可复现、可回归的评分，而不是一个总分。

**范围**：

- 维度：层次（主次是否清楚）、留白（是否成构图）、对比（墨与底是否成立）、图像（图片是否承担信息）、节奏（整册是否重复）、连贯（页面是否同一套语言）。
- 确定性项：留白占比、字号比、色彩数、骨架重复、行长——由体检直接给分。
- 模型项：层次、图像承担度、连贯——由视觉评审给分，必须附证据页。
- 输出：逐页分 + 整册分 + 每项判定来源（确定性 / 模型 / 未评分）。

**规则**：

1. 未评分的维度显示"未评分"，不得按 0 或满分计入总分。
2. 总分与单项分分开呈现；任一维度低于阈值只封顶总分，不覆盖确定性结论（沿用 ADR 0079）。
3. 同一文档两次评分（温度 0、相同提示词版本）允许 ±3 分波动；超出则标记为"评分不稳定"，不得用于回归基线。
4. 整册复核必须同时给出逐页图与 contact sheet，报告中标注页码。
5. 评分不阻断生成与导出（ADR 0015）。

**验收**：AC-V10。

### FR-V9 一页多图（图墙）— 登记项

**目的**：记录 ADR 0099 已知缺口，避免实现时临时改契约。

**范围**：内容模型允许一页声明多个图片槽位（`slotIndex`），生成批量按槽位请求，导出写入多个图位。

**规则**：本需求在 P3，未立项前不得以"一张图切多块"或"色块占位"冒充多图版面。

**验收**：AC-V11（立项后生效）。

## 8. 约束

- **C-1 内容/设计隔离**：所有新令牌、效果、变体都属于设计态，不得改动标题、正文、数值、引用、备注、页面顺序；内容哈希不变。
- **C-2 原生优先**：新增视觉手段必须落在 OOXML 原生属性；不得以整页图或烘焙图片实现效果。
- **C-3 单位**：几何仍用整数 EMU；字体以 pt 值对象表达；比例与行长用无量纲比例或字符数。
- **C-4 单一真源**：颜色派生、字阶、行长、图表令牌各只有一处实现，配方与 UI 不得各自换算。
- **C-5 可追溯**：主题包版本、版式 id、效果档位、图表主题、评分来源都进入导出报告。
- **C-6 不阻断**：视觉效果与评分的缺失或失败不阻断生成与导出（ADR 0015）。
- **C-7 降级诚实**：不支持的效果、未执行的评分、未覆盖的检查一律显示"未执行/未支持"，不得显示"通过"。
- **C-8 许可边界**：见第 13 节；未完成核验的项目不得引入代码或资产。

## 9. 非功能需求

| 类别     | 要求                                                                                   |
| -------- | -------------------------------------------------------------------------------------- |
| 性能     | 新增令牌与效果不得让 20 页导出增加超过 15% 耗时；效果处理为纯 XML 改写，不重新编码图片 |
| 兼容     | 新增效果在 PowerPoint 与 LibreOffice 各自验证；差异写入兼容矩阵，不合并成一个"支持"    |
| 可诊断   | 效果不被支持、行长越界、评分不稳定均有稳定错误码或检查 code                            |
| 可访问性 | 阴影/色调不得降低对比度到阈值以下；图片色调后仍保留替代文本                            |
| 隐私     | 参考稿仅本地解析；发给模型的模式描述必须通过无文本校验                                 |
| 可回归   | 每种版式、每种效果、每种图表主题至少一个固定样张进入视觉回归基线                       |

## 10. 错误与降级

| 错误码 / code              | 场景                           | 行为                                      |
| -------------------------- | ------------------------------ | ----------------------------------------- |
| `EFFECT_UNSUPPORTED`       | 效果组合无法写成原生属性       | 丢弃该效果并记 conflict，页面其余部分照常 |
| `EFFECT_RENDER_UNVERIFIED` | 效果已写入但目标渲染器无法验证 | 报告标"未验证"，不标"支持"                |
| `MEASURE_TOO_WIDE`         | 正文行宽超过上限               | 体检软提示，给出建议列宽                  |
| `MEASURE_TOO_NARROW`       | 正文行宽低于下限               | 体检软提示                                |
| `THEME_PACKAGE_INCOMPLETE` | 主题包缺版式或角色             | 选择器标"不完整"，不得作为默认            |
| `VARIANT_OUT_OF_SCOPE`     | 模型选择了模板未声明的变体     | 拒绝并记 conflict，回退该模板默认变体     |
| `REFERENCE_TEXT_LEAK`      | 待发送的模式描述包含文本       | 中止该次参考稿生成，回退单阶段路径        |
| `SCORE_UNSTABLE`           | 两次评分差异超过容差           | 标记不稳定，不写入基线                    |

## 11. 验收场景

- **AC-V1（角色齐全）**：8 个角色在 17 套预设上均有值；浅色与深色页面各取一个角色，对比度校验通过。
- **AC-V2（深色成立）**：同一主题的深色页与浅色页分别导出，浮起面、描边、次要文字在白/深底上都可读；断言失败时报告给出具体角色与页面。
- **AC-V3（主题包）**：一个主题包声明 ≥4 个版式；选择器显示版式数量与样张；缺版式的包被标为不完整。
- **AC-V4（模板变体）**：给定一个声明 6 个变体的模板，生成 10 页时模型只能在 6 个变体内选择；越界请求返回 `VARIANT_OUT_OF_SCOPE` 并回退默认变体。
- **AC-V5（原生效果）**：带阴影、圆角、形状裁剪、色调的页面导出后，在 PowerPoint 中选中对象可修改对应属性，且对象类型仍是形状/图片而非图片替代。
- **AC-V6（效果体检）**：构造同页三种阴影样式与两种圆角档位，体检分别报出对应 code。
- **AC-V7（排版依据）**：字阶比例为 1.25 / 1.333 两档可切换；构造超宽行与过窄行的正文，体检报 `MEASURE_TOO_WIDE` / `MEASURE_TOO_NARROW`。
- **AC-V8（图表主题）**：同一组指标在浅色与深色主题下导出，图表无纵向网格线、关键点直接标注、系列色来自令牌；灰度下相邻系列可区分。
- **AC-V9（参考稿）**：给定一份 12 页参考稿，生成结果的页级功能序列与参考稿的模式清单一致；把参考稿正文注入模式描述时返回 `REFERENCE_TEXT_LEAK`。
- **AC-V10（评分可复现）**：同一文档连续评分两次，差异 ≤3 分；删除视觉模型配置后评分为"未评分"，总分不显示为通过。
- **AC-V11（多图，立项后）**：一页 4 个图片槽位生成 4 张图、导出 4 个图位且互不重叠。

## 12. 兼容与迁移

- Schema 22 → 23：只新增可选字段（元素效果、主题包与版式、深色角色、图表令牌）；迁移为恒等迁移并附固定样例。
- 旧文档没有效果字段时渲染结果与当前逐字节一致（视觉回归基线不变）。
- 旧主题没有深色角色时按 FR-V1 的派生函数补齐，不写回文档除非保存。
- 旧模板没有变体时视为单变体，不显示变体选择。
- 导出报告中未知字段按"未执行"呈现，不补造数据。

## 14. 未决问题

1. 深色角色是写在 `DocumentTheme` 的同一数组（以 `dark:` 前缀区分），还是新增 `darkColors` 字段？前者省迁移，后者语义清楚。
2. 主题包的版式是否允许覆盖字号点数（而非只覆盖比例档）？允许会削弱"代码独占字号"，不允许则表达力有限。
3. 图表系列色是否需要按"数据语义"（增长 / 警示 / 中性）分组，而不只是按顺序取色。
4. 参考稿分析是否允许读取图片（用于判断图文比例）而不上传？读取本身不违规，但会在报告中出现"已读取图片"。
5. 美学评分是否进入导出报告默认字段，还是仅在设计复核界面出现（报告体积与误读风险）。
6. FR-V9 的图片槽位是否影响现有 `imageFrame` 契约，需要先做一页多图的 Schema 探针。
