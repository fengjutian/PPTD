# PPTD 浏览器端与云协作补充需求

**文档版本：** V0.1  
**文档状态：** 后续阶段需求基线草案  
**适用阶段：** 桌面端 V1.0 稳定后启动，具体版本号由后续路线图确定  
**对标产品：** Figma 的浏览器可达性、实时协作、评论、版本历史和多人编辑体验  
**关联基线：** [`PPTD-TRS-v1.0.md`](PPTD-TRS-v1.0.md)

---

## 1. 目标与定位

PPTD 后期应提供无需安装桌面客户端即可使用的浏览器端，使用户能够通过链接创建、打开、审核、设计和协作编辑演示文稿，并在权限允许时导出 PPTX。

浏览器端不是独立的简化产品，也不是把桌面窗口机械搬到网页。桌面端与浏览器端必须共享同一套 `PresentationDocument`、领域命令、内容与设计隔离规则、Schema 和兼容性语义；平台差异由端口和适配器承担。

“对标 Figma”在本需求中表示对齐以下产品能力和体验标准：

- 打开链接即可进入工作区，首屏和只读预览无需安装客户端。
- 多人光标、选择状态、在线成员和编辑结果近实时可见。
- 评论、提及、回复、解决和审核形成闭环。
- 文档自动保存、版本历史、恢复和冲突处理对用户透明且可解释。
- 画布缩放、平移、选择和编辑保持专业工具应有的流畅度。
- 分享链接、角色权限和组织边界清晰，不因便利性牺牲数据安全。

该目标不表示复制 Figma 的品牌、界面或全部功能，也不表示浏览器首版即具备桌面端所有本地文件与高保真 PowerPoint 能力。

## 2. 核心原则

1. **同一文档核心：** Web 与桌面端不得维护相互漂移的领域模型或命令语义。
2. **服务端为协作真源：** 云项目以服务端确认的文档版本和操作日志为真源；本地缓存只用于加速与离线恢复。
3. **内容与设计继续隔离：** 协作、评论和同步不得绕过内容审核状态、revision 或 Design Agent 权限。
4. **用户意图原子化：** 一次用户意图仍对应一个领域事务；网络同步不能把拖拽过程拆成大量持久化撤销项。
5. **渐进增强：** 不支持的浏览器能力必须显式降级；只读、评论和基础编辑应覆盖更多环境。
6. **链接不等于授权：** 所有文档、资源、评论、导出和历史访问都必须经过服务端鉴权。
7. **兼容性如实报告：** 浏览器端无法完成的 PPTX、字体或本地系统能力必须说明原因和替代路径。

## 3. 用户与典型场景

### 3.1 用户角色

| 角色 | 主要目标 |
| --- | --- |
| 所有者 | 管理文档、成员、分享、版本、删除和导出权限 |
| 编辑者 | 编辑内容与设计、发起审核、处理评论 |
| 评论者 | 查看文档、添加评论和参与审核，不修改文档对象 |
| 查看者 | 只读浏览、播放和按授权下载 |
| 组织管理员 | 管理成员、团队空间、安全策略和审计能力 |

### 3.2 核心场景

- 用户从工作区创建演示文稿，刷新或更换设备后继续编辑。
- 用户通过链接邀请同事，多人同时编辑不同页面并看到彼此状态。
- 内容负责人冻结已审核内容，设计人员只能调整 Design Model。
- 审核者在页面或对象上评论、提及成员，并跟踪问题是否解决。
- 用户查看命名版本、比较关键信息并恢复为新版本，不破坏历史。
- 桌面端打开云项目进行本地字体、文件或 PowerPoint 相关操作，保存后 Web 端继续协作。
- 网络中断后继续进行有限编辑；恢复连接时同步或明确展示冲突。

## 4. 范围边界

### 4.1 浏览器首个可用版本必须包含

- 账号登录、工作区和最近项目。
- 通过 URL 打开项目，支持只读、评论和编辑权限。
- 与桌面端共用的多页面 2D 画布、基础对象编辑和快捷键。
- 自动保存、在线状态、断线提示和恢复同步。
- 多人在线成员、实时光标、对象选择提示和编辑结果同步。
- 页面级、对象级评论，支持回复、提及、解决和重新打开。
- 分享链接与所有者、编辑者、评论者、查看者四级文档角色。
- 基础版本历史、命名版本和恢复为新版本。
- 浏览器可完成的预览、演示和 PPTX 导出任务。
- 字体、导入、导出或浏览器能力受限时的明确诊断。

### 4.2 首版明确不包含

- 与 Figma 全部能力一比一对齐。
- 插件市场、公共社区、组件市场或第三方脚本运行时。
- 完整分支/合并、任意历史操作的逐命令挑选合并。
- 浏览器内无损编辑任意复杂 PPTX。
- 浏览器直接调用本地 PowerPoint、LibreOffice、系统字体库或任意文件路径。
- 在没有网络时创建可长期独立演进的完整云项目副本。
- 企业私有化部署、数据驻留和客户自管密钥；这些能力另立企业版需求。

## 5. 功能需求

### 5.1 账号、工作区与项目

| ID | 要求 |
| --- | --- |
| WEB-ACC-001 | 用户必须通过受支持的身份认证方式登录；会话过期时保留未同步编辑并提示重新认证。 |
| WEB-ACC-002 | 用户可查看自己拥有、参与和最近访问的项目，不得枚举无权限项目。 |
| WEB-ACC-003 | 项目必须属于个人空间或团队空间，并记录所有者、创建者、创建时间和更新时间。 |
| WEB-ACC-004 | 删除项目采用可恢复的软删除；永久删除仅允许所有者或管理员执行，并有明确确认。 |
| WEB-ACC-005 | 桌面端和 Web 端打开同一云项目时使用相同文档 ID、Schema 版本和资源标识。 |

### 5.2 分享与权限

| ID | 要求 |
| --- | --- |
| WEB-ACL-001 | 文档支持所有者、编辑者、评论者和查看者角色，服务端对每次读写进行授权。 |
| WEB-ACL-002 | 分享范围至少支持“仅受邀成员”和“持有链接者”；后者必须可配置角色、有效期和撤销。 |
| WEB-ACL-003 | 复制、下载、导出和再次分享可由所有者分别控制。 |
| WEB-ACL-004 | 权限变更应在合理时间内影响已打开会话；失去编辑权限的客户端不得继续提交变更。 |
| WEB-ACL-005 | UI 隐藏命令不能代替鉴权，服务端必须拒绝越权命令并返回稳定错误码。 |

### 5.3 实时协作

| ID | 要求 |
| --- | --- |
| WEB-COL-001 | 同一文档中的在线成员、用户颜色、当前页面、光标和选择状态应近实时可见；这些临时状态不得改变文档 revision。 |
| WEB-COL-002 | 已提交的领域事务必须按确定顺序同步，并包含操作 ID、作者、基础版本、影响域和服务端确认版本。 |
| WEB-COL-003 | 并发修改不得静默丢失。可自动合并时应保持确定性；不能安全合并时必须生成可见冲突。 |
| WEB-COL-004 | 同一文本区域的并发编辑必须采用经过验证的协同文本策略；禁止仅用“最后写入覆盖”处理。 |
| WEB-COL-005 | 高频指针、拖拽预览和视口状态通过临时协作通道传输；`pointerup` 后只提交一个领域事务。 |
| WEB-COL-006 | 设计命令与内容命令继续遵循 revision 规则；远端设计操作不得覆盖更新后的已审核内容。 |
| WEB-COL-007 | 客户端重复发送同一操作时，服务端必须幂等处理，不能重复创建对象或重复递增 revision。 |
| WEB-COL-008 | 重连后客户端必须先校验服务端版本，再重放可重放操作；无法重放的操作进入冲突处理，不得假装同步成功。 |

### 5.4 评论、提及与审核

| ID | 要求 |
| --- | --- |
| WEB-REV-001 | 评论可锚定到文档、页面或稳定元素 ID，不得依赖数组索引或临时 DOM 节点。 |
| WEB-REV-002 | 评论支持正文、回复、提及、解决、重新打开、创建者和时间信息。 |
| WEB-REV-003 | 删除被评论对象后，评论保留为“锚点已删除”状态并可定位到原页面。 |
| WEB-REV-004 | 评论不改变文档的 content/design revision；内容批准、退回和修改仍通过领域命令完成。 |
| WEB-REV-005 | 提及通知不得泄露文档内容给无权限用户；权限撤销后通知链接不可继续访问文档。 |

### 5.5 自动保存、版本历史与恢复

| ID | 要求 |
| --- | --- |
| WEB-VER-001 | 所有已获服务端确认的事务自动保存，不依赖用户手动点击保存。 |
| WEB-VER-002 | UI 必须区分“正在保存”“已保存”“离线”“同步失败”和“存在冲突”。 |
| WEB-VER-003 | 版本历史至少记录作者、时间、摘要、文档版本、内容 revision 和设计 revision。 |
| WEB-VER-004 | 用户可创建命名版本；恢复历史版本时生成新的当前版本，不重写或删除既有历史。 |
| WEB-VER-005 | 自动版本保留策略、配额和清理规则必须对用户可见，命名版本不得被普通自动清理删除。 |
| WEB-VER-006 | 服务端必须能够从快照与操作日志恢复到一致状态，并定期验证恢复链。 |

### 5.6 Web 编辑、预览与演示

| ID | 要求 |
| --- | --- |
| WEB-EDT-001 | Web 编辑器复用领域命令，不得由 React 组件直接修改聚合。 |
| WEB-EDT-002 | 画布、缩略图、演示模式和导出计划读取同一 `PresentationDocument` 快照。 |
| WEB-EDT-003 | 浏览器端至少支持桌面 V0.1 的文本、图片、基础形状、页面和常用排列能力；未支持命令必须隐藏或明确禁用。 |
| WEB-EDT-004 | Web 与桌面端对同一命令夹具应产生等价文档结果和 revision。 |
| WEB-EDT-005 | 浏览器字体替代、文本换行和图片解码差异必须可诊断；不得将浏览器预览宣称为 PowerPoint 像素级结果。 |
| WEB-EDT-006 | 演示模式支持按页面顺序播放、全屏和基础键盘导航，并遵守查看权限。 |

### 5.7 资源、导入与导出

| ID | 要求 |
| --- | --- |
| WEB-IO-001 | 上传文件均视为不可信输入，必须限制类型、大小、数量、压缩比和解包资源，并进行恶意内容检查。 |
| WEB-IO-002 | 大文件上传支持进度、取消和可恢复分片；取消后不得留下对用户可见的半成品资源。 |
| WEB-IO-003 | 资源按稳定 ID 和内容哈希引用；协作事务不得内嵌无限制二进制数据。 |
| WEB-IO-004 | PPTX 导出必须基于不可变文档快照，由受控任务执行并产生结构化报告。 |
| WEB-IO-005 | 导出任务支持进度、取消、失败重试和有时效的授权下载地址；失败不得改变项目状态。 |
| WEB-IO-006 | 需要桌面 PowerPoint、本地字体或其他系统能力时，Web 端必须说明限制，并可引导用户在桌面端继续。 |

### 5.8 桌面与 Web 连续性

| ID | 要求 |
| --- | --- |
| WEB-XPL-001 | 用户可从 Web 端请求在桌面端打开同一云项目，不通过导出副本模拟同步。 |
| WEB-XPL-002 | 桌面端离线编辑云项目时保留基础服务端版本和待同步操作，重连后执行同一冲突协议。 |
| WEB-XPL-003 | 本地 `.pptd` 项目上传为云项目时创建新云项目或显式关联，不得静默改变本地文件身份。 |
| WEB-XPL-004 | 云项目导出为本地 `.pptd` 时形成可识别副本；后续是否继续同步必须由用户明确选择。 |

## 6. 一致性与协作模型要求

具体采用 OT、CRDT 或服务端序列化命令，应在技术验证后通过 ADR 决定。本需求只固定以下不可变结果：

- `PresentationDocument` 仍是文档领域聚合，不直接混入光标、在线状态、评论通知或网络会话。
- 持久化协作操作必须由强类型领域命令或等价的受约束操作表达，外部载荷以 `unknown` 接收并校验。
- 每个操作拥有全局唯一操作 ID；每个服务端确认版本可确定排序和追溯。
- 内容与设计 revision 的含义在单机和多人环境中一致。
- 撤销默认撤销当前用户可归属的最近意图，不得直接抹除他人的后续操作。
- 评论、光标、选择和视口状态分别存储，不进入 PPTX 导出，也不污染文档 revision。
- 协作协议升级必须有版本协商、兼容窗口、迁移或明确拒绝策略。

## 7. 非功能需求

### 7.1 性能与容量目标

以下为首版验收目标，测试设备、网络模型和样例集必须在实施计划中固定：

| 指标 | 目标 |
| --- | --- |
| 已缓存应用壳可交互时间 | P75 不高于 2.5 秒 |
| 20 页、每页 50 个基础对象的项目打开到可操作 | P75 不高于 5 秒 |
| 普通选择、平移和缩放反馈 | 目标 60 FPS；P95 帧耗时不高于 32 ms |
| 同区域成员看到已确认编辑 | 在 RTT 不高于 100 ms 时，P95 不高于 500 ms |
| 光标与选择状态传播 | 在 RTT 不高于 100 ms 时，P95 不高于 200 ms |
| 自动保存状态变为“已保存” | 服务正常且网络稳定时，P95 不高于 2 秒 |
| 首版单文档并发在线人数 | 至少 20 人，其中至少 10 人可持续编辑 |
| 首版代表性文档规模 | 100 页或 5,000 个基础对象，达到任一上限时仍可打开和只读浏览 |

性能不达标时必须显示降级或限制，不能通过静默丢弃对象、评论或协作操作达标。

### 7.2 浏览器兼容性与可访问性

- 支持当前及前一主版本的 Chrome、Edge 和 Safari；Firefox 支持级别由兼容测试确定并公布。
- 核心创建、编辑、评论和分享流程应满足 WCAG 2.2 AA 的适用条款。
- 常用命令提供键盘入口、可访问名称、焦点状态和操作反馈。
- 网络断开、权限变更、版本冲突和导出失败不得只用颜色表达。
- 触控设备首版至少保证查看、评论和演示；完整触控编辑另行验收。

### 7.3 可用性与容灾

- 云服务月度可用性目标为 99.9%，计划维护窗口是否排除必须在服务条款中说明。
- 协作网关中断时，已打开客户端进入明确的离线或重连状态，不得显示虚假的“已保存”。
- 文档快照、操作日志和资源必须具有备份、完整性校验和恢复演练。
- 正式上线前确定并验证 RPO、RTO；在此之前不得宣称企业级容灾能力。

## 8. 安全、隐私与合规

- 全链路使用 TLS；服务端存储的文档、资源、评论、操作日志和备份必须加密。
- 会话 Cookie 使用 `Secure`、`HttpOnly` 和适当的 `SameSite` 策略；写操作具备 CSRF 防护。
- 防范 XSS、恶意 SVG、路径穿越、ZIP 炸弹、异常 XML、外部关系、SSRF 和不受控资源代理。
- 浏览器端不得保存 AI Provider API Key；用户密钥如被支持，应进入独立密钥管理设施。
- 日志和遥测不得记录完整正文、评论内容、导入文件内容、令牌或下载签名。
- 审计日志至少覆盖登录、分享、权限变更、导出、删除、恢复和管理员操作，并防止普通用户篡改。
- 数据导出、账号删除、项目删除、备份清理和保留期限应有明确策略。
- 第三方字体、模板、图片和依赖必须验证 Web 分发、嵌入和商业使用许可。
- AI 功能上传内容前必须告知用户数据范围、服务提供方和保留策略，并遵守工作区策略。

## 9. 可观测性与运维

- 每次文档打开、协作连接、命令提交、快照、资源上传和导出任务具有关联 ID。
- 指标至少覆盖打开耗时、命令确认延迟、连接数、重连率、冲突率、保存失败率和导出失败率。
- 客户端错误报告默认脱敏；用户选择附加诊断信息时应展示将要上传的类别。
- 协作协议、Schema 和服务端部署必须支持向后兼容的滚动发布或明确维护窗口。
- 后台任务必须支持幂等、超时、取消、重试上限和死信诊断。

## 10. 分阶段交付建议

### W0：技术验证

- 将领域核心构建为不依赖 Tauri 和 Node 专有 API 的可复用包。
- 验证两种并发策略，覆盖文本、对象变换、页面排序、删除与恢复。
- 验证 20 人协作、断线重连、重复消息和乱序消息。
- 验证 Web 字体、图片解码、剪贴板、下载和大文件上传边界。

**退出条件：** 用固定夹具证明桌面与 Web 命令结果等价，并通过协作冲突故障注入；随后以 ADR 冻结协议选择。

### W1：云项目与只读分享

- 登录、工作区、云项目、上传和打开。
- 只读画布、演示模式、分享链接和查看权限。
- 服务端快照、资源存储和基础审计。

**退出条件：** 未授权用户无法读取项目或资源；100 页代表性文档可按性能目标打开和浏览。

### W2：单人 Web 编辑

- 基础对象与页面编辑、自动保存、离线短时缓存。
- 版本历史、命名版本和恢复。
- 浏览器端导出任务与结构化报告。

**退出条件：** Web 与桌面端对共享命令夹具结果一致；刷新、崩溃和短时断网不丢失已确认事务。

### W3：多人协作与评论

- 实时成员、光标、选择、多人编辑和冲突处理。
- 评论、提及、审核通知和权限即时变更。
- 协作性能、限流、恢复和观测能力。

**退出条件：** 20 人压力场景、网络分区与重连场景通过；无静默丢失、重复提交或越权写入。

### W4：桌面/Web 连续性与团队治理

- 云项目桌面打开、离线编辑和重连同步。
- 团队空间、管理员能力、审计和保留策略。
- 根据真实需求评估企业认证、数据驻留和私有化部署。

**退出条件：** 用户可在两个平台连续工作，冲突和兼容性差异均可见且可恢复。

## 11. 端到端验收场景

| ID | 场景 | 预期结果 |
| --- | --- | --- |
| W-A01 | 查看者通过有效链接打开 50 页项目 | 无需安装客户端，可浏览和演示，无法提交编辑命令 |
| W-A02 | 所有者将编辑者降为查看者 | 已打开会话及时更新权限，后续写入被服务端拒绝且本地改动可导出诊断 |
| W-A03 | 两名用户同时移动不同对象 | 两个操作均保留，各端最终文档与 revision 一致 |
| W-A04 | 两名用户同时编辑同一文本段落 | 按选定协同策略确定合并，不能安全合并时显示冲突，不发生静默覆盖 |
| W-A05 | 用户拖拽对象 5 秒 | 其他成员看到临时移动，结束后只产生一个持久事务和一个撤销意图 |
| W-A06 | 编辑过程中断网 60 秒后重连 | 状态明确显示离线；可重放操作完成同步，不可重放操作进入冲突处理 |
| W-A07 | 恢复三天前的命名版本 | 历史不被改写，系统创建新的当前版本并记录操作者 |
| W-A08 | 评论者在对象上提及成员后对象被删除 | 评论保留并显示锚点已删除，未授权用户无法通过通知访问文档 |
| W-A09 | Web 端导出包含缺失字体的 PPTX | 导出完成或明确失败；报告记录字体替代，项目状态不变 |
| W-A10 | 同一项目在桌面和 Web 分别执行相同命令夹具 | 序列化文档、对象 ID、顺序和 revision 结果等价 |
| W-A11 | 重复发送已确认操作 | 服务端幂等返回既有结果，不重复修改文档 |
| W-A12 | 上传恶意或超限 PPTX | 服务端拒绝并返回稳定错误，其他项目和后台任务不受影响 |

## 12. 上线门槛

浏览器端进入公开可用状态前必须满足：

1. 完成威胁建模、权限矩阵测试和外部安全测试。
2. 固定浏览器兼容矩阵、性能样例和容量上限。
3. 通过并发、断网、乱序、重复消息、服务重启和数据恢复测试。
4. 证明桌面与 Web 共用的领域命令和 Schema 不发生语义漂移。
5. 提供数据备份、恢复、删除、保留和事故响应流程。
6. 所有不支持、降级和需要桌面端完成的能力在 UI 与文档中可见。
7. 完成依赖、字体、模板及第三方服务的许可证和隐私审计。

## 13. 待验证决策

以下事项在 W0 结束前必须形成 ADR，不在本需求草案中提前锁定实现：

- OT、CRDT 或服务端序列化命令的选型，以及文本与结构化对象是否采用不同策略。
- 快照频率、操作日志压缩、历史保留和大文档分片方式。
- Web 客户端缓存技术及离线编辑范围。
- PPTX 导出在浏览器 Worker、服务端任务或混合模式中的边界。
- 资源存储、CDN、数据区域和租户隔离方案。
- 桌面端身份登录、深链接和云项目本地缓存方式。

这些决策不得改变本文件确定的结果性约束：不静默丢失、权限由服务端执行、内容与设计隔离、历史可追溯，以及桌面/Web 文档语义一致。
